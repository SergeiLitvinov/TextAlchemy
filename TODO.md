# TextAlchemy — оставшиеся работы

Актуализировано 2026-10-03. Это единственный активный план приложения: только незавершённые результаты. Доступные возможности и ограничения описаны в [руководстве](docs/guide/index.md), выполненные этапы и проверки — в [истории](docs/history/changes.md). Исторические ID сохранены для ссылок; порядок номеров не задаёт порядок выполнения.

OpenDoc — самостоятельная зависимость с собственными руководством и планом. Здесь учитываются только её подключение, совместимость и использование в TextAlchemy. Исходники библиотеки в этой сессии не изменяются. [Правила обновления пакета](docs/development/document-library.md).

## M7. Архитектура приложения

- [ ] **M7.2 (A2):** перенести проверку записанного PDF в стадию verify до публикации; выделить оставшиеся обязанности formats/pptx и legacy viewer при работе над подтверждённым дефектом. Приёмка: каждая стадия выполняет работу и выдаёт проверяемый результат; ошибка проверки PDF сохраняет прежний файл. HTML-normalize для закладок/ссылок, подготовка изображений HTML/PDF, CSS-геометрия HTML и проверка его навигации уже описаны в руководстве и истории; это не полная проверка ресурсов, layout и качества форматов.

**Граница:** оставшаяся M7.2 отвечает за внутреннее выполнение конвертации. Прикладные сценарии описаны в руководстве и истории. Новая библиотека создаётся при появлении второго потребителя с конкретной приёмкой; отдельного проекта для каждого модуля план не требует.

## M6. Свидетельства качества

- [ ] **M6.1 (Q1):** калибровать прогноз на выбранном корпусе, связывать визуальные измерения и реальные проверки редактирования с отчётом. Указывать происхождение и область проверки; отсутствие измерений оставлять `null`. Приёмка: пользователь отличает прогноз от измеренного результата и проверки в целевой программе.
- [ ] **M6.2 (Q2):** добавить числовые бюджеты ещё не покрытых свойств оформления и объектов на выбранном маршруте. Каждый бюджет требует воспроизводимого случая потери. Приёмка: строгий лимит отклоняет публикацию результата и сохраняет прежний файл.
- [ ] **M6.3 (Q3):** для выбранного PDF/PPTX fallback сохранять исходный ресурс, причину преобразования и связь с визуальной заменой через JSON и экспорт. Приёмка: отчёт и повторное чтение сохраняют эту связь; растр не объявляется редактируемым объектом.
- [ ] **M6.4 (Q4):** обработать оставшиеся конкретные случаи цвета заливок/обводок, ICC/output intent/CMYK/blend. Приёмка: свойства целевого файла и визуальный пример подтверждают результат.

**Граница:** M6.1 измеряет и объясняет, M6.2 ограничивает допустимые потери, M6.3 фиксирует замену объекта, M6.4 исправляет передачу цвета. Новые метрики добавляются для конкретного решения пользователя.

<a id="m5"></a>
## M5. Сложные форматы

- [ ] **M5.1 DOCX (D1):** выбранные comments/SmartArt/OLE и защищённые объекты; правки диаграмм, сносок и внутренних ссылок через два цикла. Приёмка в Word: объект открывается, правка сохраняется. Непрозрачное сохранение XML не считается редактированием.
- [ ] **M5.2 PDF (D2/D3):** выбранные tagged structure/порядок чтения, annotations/forms/layers/clipping/masks; формулы → MathML/OMML, пути → SVG/DrawingML. Для каждого семейства нужен отдельный пример с проверкой поведения; при недостаточной уверенности — объяснимый визуальный fallback.
- [ ] **M5.3 PPTX (P1/P2):** выбранные mixed XY/category/horizontal/3D charts, shear, темы/заливки/стили таблиц и placeholders; структура theme/master/layout, animations/transitions, SmartArt/media/comments/embedded objects. Приёмка на конкретном объекте: внешний вид, поведение и сохранённая правка в Office.
- [ ] **M5.4 HTML (H1):** дополнительные CSS/paged media-сценарии и доступный семантический экспорт. Перед реализацией зафиксировать пример и ожидаемое отображение/чтение вспомогательными технологиями.
- [ ] **M5.5 DjVu (F1):** страницы, текстовый слой и координаты в модели через адаптер приложения. Приёмка: воспроизводимый fixture с ожидаемыми блоками и экспортом.
- [ ] **M5.6 XLSX/ODS (F2):** исследовать конкретные примеры и принять документированное решение о табличном представлении, отсрочке либо отказе. Это исследование, а не обещание поддержки Excel.

**Выход каждого среза:** объявлены объект, маршрут и корпус; сохраняются нужные данные и поведение, потери видны пользователю. «Поддержать полный формат» не является критерием завершения. Новые общие структуры согласуются с владельцем OpenDoc, а не реализуются второй моделью в приложении.

## M8. Приёмка на документах пользователя

- [ ] **M8.1:** согласовать корпус: происхождение, форматы, особенности, ожидаемый результат и правила обезличивания. Выбрать маршруты и критерии приёмки.
- [ ] **M8.2:** выполнить маршруты, сохранить отчёты и доступные измерения времени/памяти; проверить реальные изменения и повторное открытие в нужных Word/PowerPoint/LibreOffice/браузере/PDF viewer. Неизмеренное оставить неизвестным.
- [ ] **M8.3:** превратить разрешённые дефекты в воспроизводимые fixtures, исправить и повторить приёмку; опубликовать матрицу проверенных сценариев и принятые ограничения в руководстве.

**Начало:** получены документы и правила использования. Ожидание корпуса не останавливает проверку текущих сценариев и остальные вехи.

## Как поддерживать план

- Активен один ближайший срез; новая работа имеет конкретный сценарий и конечную приёмку.
- После приёмки обновить руководство и историю, затем удалить выполненный пункт отсюда. Если выполнена часть пункта, оставить только остаток.
- Проверка документации запрещает закрытые отметки, повторяющиеся ID и задачи вне своей вехи.
- Свойства форматов находятся в справочниках; исторические задачи — в [карте миграции](docs/history/todo-milestone-map.md) и [указателе ID](docs/history/legacy-ids.md). Они не являются вторым активным планом.
