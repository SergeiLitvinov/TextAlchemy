# TextAlchemy — план по вехам

Актуализировано 2026-09-13. Единственный действующий план объединяет прежние P0/P1, короткий TODO и отложенные результаты. Реализованные сценарии — в [руководстве](docs/guide/index.md); основание перестройки — [аудит документации](docs/history/documentation-audit.md).

## Статусы и порядок

«Базовый объём выполнен» относится к перечисленным результатам, а не к полной совместимости формата. Сроков и процентов готовности нет: число старых отметок не измеряет готовность продукта.

| Веха | Результат | Статус |
|---|---|---|
| [M0](#m0) | Установить, запустить и автоматизировать обработку | База выполнена; три дефекта CLI/конвейера |
| [M1](#m1) | Обрабатывать документы, распознавать текст и вести библиотеку | Базовый объём выполнен |
| [M2](#m2) | Пройти ограниченный PPTX/HTML обратный путь с диагностикой | Ограниченная приёмка выполнена |
| [M3](#m3) | Создавать документы по шаблонам и данным | Базовый объём выполнен |
| [M4](#m4) | Управлять выбранными файлами и исправлять проблемы | В работе; следующий результат M4.1 |
| [M5](#m5) | Расширить форматы на конкретных сложных документах | Запланировано по сценариям |
| [M6](#m6) | Получать калиброванные свидетельства сохранности | Запланировано; базовые проверки есть |
| [M7](#m7) | Поддерживать расширение без ухудшения надёжности | По мере работы над затронутым кодом |
| [M8](#m8) | Принять результат на документах пользователя | Ожидает корпус; не блокирует M4 |

После M4 конкретные срезы M5/M6 выбираются по дефекту или пользовательскому сценарию. M7 выполняется вместе с нужным изменением, а не как предварительная тотальная переделка. Полная M5 не является условием начала M6/M8.

Ближайшая работа после аудита: M0.1 → M0.3 → M0.2, затем пользовательский результат M4.1. Аудит меняет документацию и план, сами эти исправления ещё не выполнены.

**Дефекты существующих сценариев, обнаруженные аудитом:**

- [ ] **M0.1 — JSON-отчёт успешного сопоставления.** `match --json` после одного совпадения завершается ошибкой сериализации `WindowsPath`. Готовность: команда возвращает успешный код, отчёт содержит фактическое новое имя скопированного файла; проверены непустые совпадения и сериализация. Текущий тест проверяет только пустой каталог.
- [ ] **M0.2 — контракт глобального `--config`.** Парсер принимает путь, но обработчики его не используют. Готовность: определить поддерживаемые команды/приоритет явных аргументов и подключить конфигурацию либо явно отклонять неподдержанный флаг; проверить изменённый параметр и отсутствующий файл. Молчаливое игнорирование исключить, руководство обновить.
- [ ] **M0.3 — входы библиографических операций.** У `render.bibtex/gost/markdown/json` зарегистрирован `input`, а функции принимают `items`; связь `input: bib` завершается TypeError. Готовность: связанный конвейер проходит для всех четырёх операций, прежний `params.items` работает, каталог показывает правильный вход. До исправления обход описан в [справочнике](docs/reference/operations.md).

## M4. Управляемый Web-сценарий — в работе

База уже работает: загрузка → формат/приоритет → отчёт/просмотр → скачивание, пакеты/история, индивидуальные формат/приоритет, фильтры, ZIP, отмена оставшихся и повтор всех неудачных. Инспектор HTML принят в M2 и повторно не реализуется.

- [ ] **M4.1 — следующий пользовательский результат после дефектов M0: повтор выбранных неудачных файлов** (U3, короткий TODO).
  Сценарий: один готовый и два неудачных файла; выбран один неудачный. Готовность: браузер подтверждает повтор только выбранного, сохранность готового артефакта и второго неудачного, понятную обработку смены статуса. Прочие групповые действия и индивидуальные бюджеты исключены из среза.
- [ ] **M4.2 — исправление проблемы и повторный экспорт** (U1/U2).
  Отдельные срезы: правка OCR-текста; порядок чтения/классификация; границы таблицы; навигация от предупреждений других форматов к объекту/странице. Для каждого выбрать fixture. Готовность: «найти → исправить → повторить → скачать», правка сохраняется в модели и целевом файле. Существующие загрузку/preview не повторять.
- [ ] **M4.3 — черновик генератора и наборы данных** (U4).
  Срезы: восстановить незавершённый ввод после перезагрузки; сохранить, выбрать и обновить набор данных. Готовность: данные и шаблон восстанавливаются, ошибки схемы видны, чужой набор незаметно не перезаписывается.
- [ ] **M4.4 — визуальная правка шаблона** (U5).
  По одному сценарию переменной, условия/цикла, строки таблицы, изображения/формулы, библиографии/ссылки. Приёмка каждого: изменение сохраняется в шаблоне и видно в документе; весь редактор по одному полю не объявлять готовым.
- [ ] **M4.5 — остальные действия с выбранными файлами** (остаток U3).
  Кандидаты: отмена выбранных и выдача выбранных готовых результатов. Отдельная приёмка допустимых состояний и состава результата; бюджеты остаются общими. Индивидуальные бюджеты — только по отдельной потребности.
- [ ] **M4.6 — понятность и доступность интерфейса** (U6/U7).
  Сначала перечень непроверенных экранов/состояний. Затем примеры/контекстная помощь, единые русские термины, пустое/ошибочное состояние и восстановление. Приёмка выбранных сценариев клавиатурой, с семантикой для экранного диктора и на мобильном экране; axe не равен полной WCAG 2.2 AA.

**Выход:** перечисленные срезы приняты на объявленных fixtures, руководство описывает фактические действия. Внутри M4 первой выполняется M4.1; следующие уточняются до ограниченного результата перед реализацией.

- [ ] **M5.3 PPTX (P1/P2):** mixed XY/category и horizontal/other plots, сложные/3D charts, shear, темы/заливки/условные стили таблиц, оставшиеся placeholders, MathML/LaTeX и SVG paths; отдельно theme/master/layout как структура, animations/transitions, SmartArt/media/comments/embedded objects. Брать подтверждённый сценарий, проверять вид/поведение/изменение в Office; не смешивать с принятой M2.
- [ ] **M5.4 HTML (H1):** перечисленные дополнительные CSS/paged media-сценарии и доступный семантический экспорт. Сравнивать с ожидаемым отображением и чтением вспомогательными технологиями; базовый импорт не создавать повторно.

- [ ] **M5.6 XLSX/ODS (F2):** исследовать конкретные примеры и принять документированное решение об отдельной табличной модели либо отказе/отсрочке. Это исследование, а не обещанная поддержка Excel.

**Выход каждого среза:** объявлены объект/маршрут/корпус, сохраняются данные и нужное поведение, потери видны пользователю. «Поддержать полный формат» не является критерием завершения.

## M6. Доказательства качества — запланировано

Уже есть прогноз маршрута, структурный/object diff, доступные визуальные сравнения, бюджеты сообщений/объектов/текста, font resolver и часть встраивания. [Как их читать](docs/guide/index.md#отчёт-и-проверка-качества).

- [ ] **M6.1 (Q1):** калибровать прогноз по корпусу; связать визуальные измерения и проверки редактирования с отчётом, указать происхождение/покрытие, неизвестное оставлять `null`. Новый показатель — только для конкретного решения пользователя.
- [ ] **M6.2 (Q2):** числовые бюджеты частичной потери содержимого, формул и оформления на выбранных маршрутах. Приёмка: воспроизводимая потеря отклоняет публикацию при строгом лимите, прежний файл цел. Уже имеющийся допуск изменений слов не реализовать повторно.
- [ ] **M6.3 (Q3):** visual surrogate и история преобразований в конкретных PDF/PPTX fallback. Сохранить исходный ресурс, причину и связи через JSON/экспорт; растр не считать редактируемым объектом. DOCX SVG + raster preview и PDF-адаптация SVG уже существуют.
- [ ] **M6.4 (Q4):** канонический цвет для оставшихся заливок/обводок, выбранные ICC/output intent/CMYK/blend-сценарии. Принимать свойства целевого файла и визуальный пример; единицы/округление и модель цвета не переделывать без дефекта.

**Выход:** отчёт отличает прогноз, измерение, отсутствие данных и реальную правку в целевой программе. Не увеличивать число метрик вместо проверки результата.

## Как поддерживать план

- Активен один ближайший срез, при необходимости не более трёх; сейчас M0.1 → M0.3 → M0.2. Затем M4.1. Новая работа имеет сценарий/дефект и конечную приёмку.
- Выполненное обновляет руководство и [историю](docs/history/changes.md); здесь остаётся короткий результат со ссылкой на доказательства.
- Детали свойств формата живут в справочнике, а не в новых родительских/вложенных TODO.
- Структурный тест, собственный visual golden, независимое изображение и ручная правка — разные свидетельства. Не складывать их в процент готовности.
- Все 273 отметки прежнего плана сопоставлены в [карте миграции](docs/history/todo-milestone-map.md); исходный [снимок](docs/history/todo-2026-09-13.md) неизменён. Сохранён [короткий TODO до перестройки](docs/history/todo-before-milestones-2026-09-13.md); старые ID разрешаются через [указатель](docs/history/legacy-ids.md).
