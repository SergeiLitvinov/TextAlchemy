# Система документации

Документация хранится в Markdown и собирается в локальный сайт MkDocs с поиском, оглавлением и навигацией. Автоматизация находится в `tools/documentation/`, конфигурация сайта — в `mkdocs.yml`. Временные данные собираются только внутри `.textalchemy/`, в Git не попадают.

Небольшие дополнения оформления и поиска находятся в `docs/assets/`: таблицы прокручиваются внутри страницы, а запрос, введённый до готовности индекса, обрабатывается после загрузки. При изменении самого сборщика или hook перезапустите `serve`; изменения руководства, ресурсов и кода приложения подхватываются при работающем сервере.

## Разделы и источники истины

| Где | Что поддерживать |
|---|---|
| `docs/guide/index.md` | Действия пользователя, ограничения, рабочие примеры |
| `docs/guide/formats.md` | Объединённые главы HTML/TXT/EPUB/PPTX/MathML; детали поддержанного подмножества |
| `docs/guide/web-details.md` | Подробности Web/API и пакетных действий |
| `TODO.md` | Единственный план по вехам и критерии незавершённого |
| `docs/reference/` | Автоматически сформированные команды и операции; вручную не редактировать |
| `docs/history/` | Датированные проверки, аудиты, старые ID и неизменяемые снимки |
| `AGENTS.md`, `CODING_STANDARDS.md` | Устройство проекта и правила разработки |
| `docs/examples/` | Входы исполняемых примеров руководства |

Пять прежних справочников форматов объединены в руководство; отдельного актуального backlog больше нет. Неподдержанные CSS/Office/PDF-возможности остаются в M5/M6; документы о приёмке не превращаются в новые задачи. [План](../../TODO.md), [каталог глав](../README.md).

## Команды

Добавьте набор документации к тем extras, которыми пользуетесь. Для всех проверок документации достаточно:

```powershell
uv sync --extra docs --extra dev --extra html --extra docx --extra pdf
uv run python -m tools.docs generate
uv run python -m tools.docs check
uv run python -m tools.docs serve
```

Сайт открывается по [локальному адресу документации](http://127.0.0.1:8001/). Порт отличается от приложения. `serve` следит за исходными Markdown, TODO и кодом; обновляет страницы и справочники предпросмотра автоматически. Прекращение — Ctrl+C. Другой адрес: `uv run python -m tools.docs serve --address 127.0.0.1:8010`.

| Команда | Результат |
|---|---|
| `generate` | Обновляет отслеживаемые Markdown CLI/операций из кода; изменения видны в diff |
| `build` | Проверяет актуальность справочников и строго собирает сайт |
| `check` | Дополнительно проверяет команды руководства, карту старого TODO и реальную генерацию примеров |
| `serve` | Локальный сайт с автоматическим обновлением; не переписывает отслеживаемые справочники |

Собранные файлы: `.textalchemy/docs-site/`. Можно разместить этот каталог на статическом хостинге; автоматическая публичная публикация сейчас не настроена. CI собирает и сохраняет сайт как артефакт, без доступа к серверу публикации и без изменения ветки.

## Что блокирует проверку

Проверка завершается с ненулевым кодом, если:

- CLI/реестр изменились, а `generate` не выполнен;
- ссылка указывает на отсутствующий документ/файл или якорь;
- новая страница забыта в навигации `mkdocs.yml`;
- команда из руководства больше не принимается парсером;
- в карте старого TODO есть пропуск или дубликат;
- пример конвейера/шаблона не выполняется или в DOCX/HTML/PDF отсутствует ожидаемый текст.

Зависимости документации выделены в extra `docs`, версии фиксируются `uv.lock`. CLI и операции читаются из парсера/реестра; известные несовпадения имени входа операции и сигнатуры видны в справочнике. Это не автоматическое доказательство корректности каждой функции — ограничения и вехи требуют содержательного обновления автором.

Строгая валидация выполняется средствами [MkDocs](https://www.mkdocs.org/user-guide/configuration/#validation). Внешние URL не запрашиваются при сборке. Два старых снимка TODO отображаются как исторический текст со скачиванием оригинала: их прежние ссылки не проверяются как действующие инструкции, исходные файлы не изменяются. Остальные главы и архивные отчёты проверяются наравне.

## Как обновлять

1. Измените один основной раздел руководства и соответствующую веху; не копируйте одно требование в несколько документов.
2. После изменения команд/операций выполните `generate` и проверьте diff.
3. Добавляйте страницы в подходящую папку и в `nav`; подробности полей формата дополняют существующую главу.
4. Выполните `check`. Для нового пользовательского примера добавьте содержательную проверку результата, а не только наличия файла.
5. Сохраняйте датированное свидетельство в истории, если оно меняет заявленную границу приёмки.

Исходные относительные ссылки работают в репозитории. Во время сборки необходимые связанные файлы кода копируются в отдельную область сайта для чтения; ссылки за пределы репозитория и отсутствующие локальные файлы отклоняются. Это позволяет смотреть документацию без публикации незакоммиченного кода на внешнем сервере.
