# Независимая библиотека документов

TextAlchemy подключает `opendoc==0.1.0`; импорт — `opendoc`. Самостоятельный проект находится в `C:/project/opendoc`. Приложение устанавливает готовый wheel из `vendor/opendoc`: установка и CI не требуют исходников библиотеки. При распространении приложения нужно предоставить также wheel OpenDoc, пока пакет не опубликован в реестр.

## Граница ответственности

OpenDoc владеет моделью, свойствами, единицами, цветами, ресурсами, формулами, JSON, валидацией, инвентаризацией и структурным сравнением. У библиотеки собственные руководство, API, навигатор, стандарты и CI. Обязательных внешних зависимостей нет; дополнение `math` предоставляет `lxml` для отпечатков MathML. Отсутствие измерения не считается соблюдением строгого допуска.

TextAlchemy отвечает за Office/PDF/HTML, файловую инспекцию, конвертацию, OCR, шаблоны, библиографию, конвейеры, CLI и Web. Обновление приложения не собирает и не изменяет исходный проект OpenDoc. Новый редактор может подключить библиотеку напрямую и реализовать собственные команды и сеансы.

## API и совместимость

Новые потребители используют `from opendoc import DocumentModel`. Руководство библиотеки: `C:/project/opendoc/docs/guide/index.md`; API и навигатор формируются в том же проекте. [Навигатор приложения](../reference/code.md) показывает прикладные адаптеры.

Прежние импорты модели из `textalchemy.core.*` возвращают те же классы OpenDoc. Модули с изменяемыми лимитами используют общий объект модуля. Исключение — JSON-кодек: приложение владеет адаптером прежних файлов `textalchemy.document` и читает также `opendoc.document`. Библиотека записывает `opendoc.document` версии 2 и читает версии 1/2; она не обязана распознавать идентификаторы приложения. Версия пакета и версия данных независимы. Неизвестные версии и типы блоков отклоняются.

Шаблонизатор [textalchemy.templating](templating.md) принимает модель и данные; работа с файлами, изображениями и специальным оформлением библиографии остаётся в адаптерах TextAlchemy.

## Получить новую версию

### Изменения границы конвертации

Рабочий каталог OpenDoc и установленный пакет TextAlchemy независимы. Изменение исходников библиотеки не меняет приложение: оно продолжает использовать сохранённый wheel и lockfile. Удаление из OpenDoc понятий конвертации согласуется при подключении нового пакета, без автоматического чтения соседнего checkout.

Перед обновлением сверяйте перечень удалённых или переименованных экспортов. Модель, ресурсы и JSON остаются контрактом библиотеки; маршруты, преобразования форматов, политики потерь и отчёты выполнения принадлежат TextAlchemy. Если новый пакет убирает используемый символ конвертации, сначала адаптируйте его потребителей в приложении. Совместимые импорты приложения и чтение старых JSON должны сохраняться; второй модели документа создавать не нужно.

Новый пакет принимается после проверки независимой установки, интеграционных тестов, генерации шаблонов, конвертации и Web-сценариев, использующих затронутые символы. При изменении публичного API требуется новая версия пакета и согласованное обновление точной зависимости, wheel, provenance и lockfile. Один номер версии не должен обозначать два разных контракта.

Получите wheel, собранный и проверенный в проекте OpenDoc. При смене версии сначала измените точную зависимость и путь `[tool.uv.sources]` в `pyproject.toml` приложения, затем выполните:

```console
uv run python -m tools.update_document_core --wheel путь/к/opendoc-0.1.0-py3-none-any.whl
uv sync --all-extras --reinstall-package opendoc
uv run ruff check
uv run pytest tests/test_document_library_integration.py
```

Инструмент проверяет имя/версию дистрибутива, отсутствие обязательных зависимостей и обратных импортов приложения, соответствие закреплённому пути. Затем сохраняет wheel и хеши в `provenance.json` и обновляет lockfile. Исходный пакет не меняется. [Описание комплекта](../../vendor/opendoc/README.md).

## Проверить независимую установку

Создайте пустое окружение через `uv venv`, установите только сохранённый wheel через `uv pip install --python путь/к/python --no-deps --no-index vendor/opendoc/opendoc-0.1.0-py3-none-any.whl`, затем выполните `uv run python -m tools.check_document_core --python путь/к/python`.

Проверка запускает изолированный Python вне checkout приложения: ресурсы, JSON, сохранение/загрузка и сравнение работают без TextAlchemy и обработчиков форматов. CI повторяет её на Python 3.11/3.12/3.13. Интеграционные тесты дополнительно проверяют совместимые импорты и соответствие установленного пакета хешам wheel. Полная проверка приложения: `uv run pytest tests/ --cov=textalchemy --cov=opendoc`; порог 80%.

После изменения адаптеров и руководства запускайте `uv run python -m tools.docs generate` и `uv run python -m tools.docs check`. Будущие работы приложения находятся в [TODO](../../TODO.md#m7); план и реализация библиотеки ведутся независимо.
