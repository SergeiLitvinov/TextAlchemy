# Веб-конвертация: соответствие возможностям движка

На странице «Преобразовать» карта направлений доступна до загрузки документа.
Она строится по `/api/convert/capabilities` с учётом установленных зависимостей,
показывает форматы назначения и доступные приоритеты для каждого источника.
Для недоступных режимов каталог возвращает `unavailable_modes`: отсутствие
поддержки движком (`unsupported_mode`), недостающие компоненты выбранного
теоретического маршрута (`missing_dependencies` с `requirements`), отсутствие
подключённого обработчика (`backend_unavailable`) или необходимость промежуточных
файлов, не поддержанных веб-слоем (`web_route_unsupported`). Это диагностика
маршрута планировщика, а не минимальный набор установки среди всех альтернатив.
Сначала проверяется доступный маршрут, поэтому рабочий fallback не скрывается.

Недоступные результаты находятся в `unavailable_targets`, полностью недоступные
источники — в `unavailable_sources`. Интерфейс показывает их причины в карте,
но не добавляет их в выбор файлов и результатов. Подсказка приоритета также
показывает причины отключённых режимов, для пакета — по исходным форматам.

Каталог передаёт рекомендуемый формат результата: например, TXT → DOCX,
EPUB → HTML, PPTX → HTML. Интерфейс выбирает его, если направление доступно.
Сохранение в тот же формат не предлагается: такой маршрут тождественный.

При выборе результата показываются пояснения возможностей и ограничений
экспорта PPTX/TXT и импорта EPUB. Для PPTX → модель объяснён обратный путь:
изменённую модель можно загрузить для экспорта в PPTX. Встроенного редактора
текста, таблиц и диаграмм презентации пока нет. Сохранение настроек диаграмм
движком не означает возможности редактировать эти настройки в браузере.

Прогноз перед одиночной конвертацией явно обозначен как оценка маршрута,
а не измерение конкретного результата. Для пакета не показывается прогноз
первого файла как общий: каждый файл получает свой маршрут и итоговый отчёт.
Рекомендации всех исходных форматов объединяются без повторов.

Проверки включают каталог при недоступных зависимостях, рекомендуемые форматы,
реальный браузер, переключение пояснений и пакетный прогноз на мобильной
ширине, клавиатуру и сообщение при ошибке загрузки каталога.

После завершения всех заданий пакета готовые результаты можно скачать одним
ZIP из панели прогресса или истории. `GET /api/convert/jobs/{job_id}/archive`
возвращает результаты в отдельных нумерованных папках и `manifest.json`
со статусами всех файлов. Одинаковые имена не перезаписываются. Ошибочные,
прерванные и истёкшие результаты не включаются; готовый результат, чей файл
уже недоступен, отмечается как `unavailable`. HTML-просмотрщик остаётся своим
вложенным ZIP без повторной распаковки.

Пока пакет выполняется или отменяется, выдача возвращает 409. При отсутствии
готовых файлов также возвращается 409, при истечении срока пакета — 404.
Суммарный размер включённых результатов ограничен 512 МБ (превышение — 413).
Архив собирается во временном файле с переносом на диск после 8 МБ и удаляется
после выдачи или ошибки; отдельной долговременной копии ZIP не создаётся.
Если файл исчезает во время сборки, предлагается обновить пакет и повторить
скачивание. Список результатов отражает состояние на момент запроса.

Панель пакета фильтрует файлы по состоянию и имени (без учёта регистра).
«В очереди и в работе» включает отменяющиеся задания; «Требуют внимания» —
ошибки, прерывания, отменённые и истёкшие результаты, а также неизвестные статусы.
Счётчик показывает размер выборки и всего пакета. При обновлении статусов фильтр
сохраняется, при открытии другого пакета сбрасывается. Кнопка «Открыть пакет»
в истории позволяет фильтровать завершённые задания без повторного запуска.
Фильтры меняют только список: ZIP содержит все готовые результаты пакета.
Ответы и таймеры ранее открытого пакета не заменяют текущий список.

Для каждого файла пакета можно выбрать собственный формат и приоритет в блоке
«Формат и приоритет каждого файла». Общие настройки меняют нетронутые строки;
кнопка применения ко всем сбрасывает индивидуальные правки. При недоступном
общем направлении выбирается доступный вариант строки. Если общего формата
нет совсем, индивидуальные настройки автоматически раскрываются для проверки.
Бюджеты сохранности остаются общими для всех файлов.

API принимает поле формы `file_options`: JSON-массив объектов `target_format`
и `mode` в порядке загрузки файлов. Длина должна совпадать с числом файлов,
неизвестные поля отклоняются. Пропущенные свойства наследуются из общих
настроек; отсутствие массива сохраняет прежний контракт API. Весь пакет
проверяется до постановки в очередь. Имена файлов могут совпадать: соответствие
настроек определяется позицией. Выбранные формат и приоритет сохраняются в
каждой задаче и восстанавливаются при перезапуске, отображаются в деталях истории.
