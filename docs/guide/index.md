Для версии 0.1.0 и рабочего дерева на 2026-10-02. Руководство описывает реализованные сценарии. Будущие возможности находятся в [плане по вехам](../../TODO.md); подробные ограничения форматов — в [каталоге документации](../README.md).

[Выберите задачу в автоматическом содержании](../reference/user-guide.md). Оно объединяет главы этого руководства, подробности форматов и контракты Web.

## Руководство внутри программы

В верхней панели любой страницы нажмите кнопку с книгой **«Открыть руководство»** либо выберите **«Руководство»** в меню. Документация открывается на том же адресе приложения по пути `/help/`. В неё входят главы руководства, справочники, навигатор по коду и актуальный план.

Отдельный сервер документации и интернет не нужны. Поиск работает локально; доступны светлая и тёмная темы. Кнопка **«В программу»** возвращает на главную приложения. Для просмотра не требуются MkDocs и дополнение `docs`: готовая документация включена в установленный пакет. Сайт является снимком версии приложения; порядок обновления описан в [системе документации](../development/documentation.md).

## Установка и запуск

Нужны Python 3.11 или новее, установленный `uv` и локальная копия проекта. Все команды ниже выполняются из корня проекта. Пути с пробелами заключайте в кавычки.

Для Web, основных документов и статического HTML:

```powershell
uv sync --extra web --extra docx --extra pdf --extra pptx --extra html --extra epub
uv run textalchemy web
```

Откройте [локальное приложение](http://127.0.0.1:8000/). Остановить сервер можно сочетанием Ctrl+C в запустившем его терминале. Для другого порта: `uv run textalchemy web --port 8080`.

| Набор | Назначение |
|---|---|
| `uv sync` | Базовая библиотека, CLI и лёгкие зависимости; не все маршруты доступны |
| `--extra docx` | Чтение/создание Word-документов и DOCX-шаблоны |
| `--extra pdf` | Геометрический PDF-анализ и PDF-конвертеры |
| `--extra pptx` | Презентации, XML и изображения |
| `--extra html` | Статический HTML-импорт и базовый CSS |
| `--extra epub` | EPUB-импорт |
| `--extra web` | Локальный Web-интерфейс |
| `--extra ocr` | Python-компоненты распознавания; большие загрузки моделей и библиотек |
| `--extra dev` | Инструменты разработки и тестов |
| `uv sync --all-extras` | Все дополнительные наборы с учётом ограничений платформы/Python |

При следующем `uv sync` перечисляйте нужные наборы вместе: команда синхронизирует окружение с выбранной конфигурацией. `--all-extras` не устанавливает внешние программы. Tesseract и его языки, LibreOffice, Pandoc, DjVuLibre (`djvutxt`) нужны только соответствующим сценариям. PaddlePaddle исключён из набора на Python 3.14; наличие GPU-флага не гарантирует доступность ускорения. Доступные маршруты проверяйте в самом приложении.

## Конвертация в браузере

1. Откройте «Преобразовать» (`/convert`). В разделе «Доступные форматы и возможности» можно проверить направления до загрузки.
2. Перетащите файл или выберите его. Приложение определит формат и проверит структуру исходника.
3. В простом режиме выберите формат результата. Приложение автоматически подберёт маршрут с приоритетом «Разумный баланс» либо доступным приоритетом, если баланс не поддерживается.
4. Для выбора приоритета и строгих допусков включите «Экспертный» и раскройте проверку сохранности. Доступные варианты зависят от установленных компонентов.
5. Нажмите «Начать конвертацию». После выполнения проверьте отчёт, изменения структуры и доступные страницы предпросмотра.
6. Скачайте результат. Сохраняйте его у себя до истечения срока хранения задачи.

Простой режим включается при каждом открытии страницы. Он сохраняет анализ исходника, предупреждения об ограничениях, отчёт о потерях и предпросмотр. Автоматический выбор маршрута не гарантирует полного сохранения документа. Прогноз маршрута и его техническое описание доступны в экспертном режиме. Возврат в простой режим сбрасывает приоритет, строгие допуски и индивидуальные настройки файлов пакета; выбранные файлы и общий формат остаются.

До выбора файла показаны загрузка и раскрываемый каталог направлений. После выбора загрузка уступает место настройкам; кнопка «Выбрать другой» позволяет заменить исходник. Структура исходника, рекомендации для выбранного формата и подготовка PDF раскрываются отдельно. При замечаниях структурная проверка раскрывается автоматически. Во время одиночной конвертации файл и настройки заблокированы; после ошибки они сохраняются и снова доступны.

Кнопка «Скачать результат» находится сразу под заголовком готового документа. Замечания и результат проверки допусков видны без раскрытия; подробное сравнение структуры открывается отдельно. Если отчёт отсутствует, интерфейс сообщает «Отчёт о качестве недоступен», а не подтверждает отсутствие потерь. При просмотре сохранённой задачи скачивание и подпись приоритета относятся к выбранному результату.

«История пакетов» раскрывается внизу страницы; одиночные задачи доступны в общей панели «Задачи». В активном пакете список файлов виден сразу, а поиск и фильтры раскрываются по необходимости.

| Приоритет | Значение |
|---|---|
| Разумный баланс (`balanced`) | Компромисс между оформлением и редактируемостью; используется по умолчанию |
| Удобное редактирование (`editable`) | Предпочтение тексту и объектам, которые можно менять в целевой программе |
| Максимальное сходство (`faithful`) | Приоритет внешнего вида, если подходящий маршрут доступен |

Недоступный режим не следует обходить переименованием файла: это ограничение маршрута или зависимостей. Прогноз процентов перед запуском относится к маршруту, а не к измеренному качеству вашего документа.

В предпросмотре доступны исходник, результат, сравнение «До / после» и карта различий, когда оба файла удаётся отрисовать. Стрелки ←/→ переключают страницы, когда фокус находится в области документа. Отсутствие предпросмотра не означает, что скачиваемый файл повреждён: проверьте его в целевой программе.

При быстром переходе между готовыми файлами запоздавший ответ не подменяет выбранный просмотр. Если задачу удалили, повторно запустили или срок её хранения закончился во время отрисовки, прежние страницы не выдаются; откройте актуальную задачу из истории. После повторного запуска просмотр запрашивает текущий результат заново. Рендер и структурная проверка выполняются в рабочих потоках, поэтому остальные запросы Web могут обрабатываться во время ожидания. Офисный предпросмотр требует LibreOffice; временный отказ движка не закрепляет отсутствие страниц — можно повторить открытие результата.

Если запуск сообщает о недоступности очереди, выбранный файл остаётся в форме. Уже сохранённая задача может остаться в списке «Задачи» в ожидании; при перезапуске приложения она восстанавливается с прежним исходником и ограничениями. Проверьте список перед новой отправкой, чтобы не создавать повторное задание. Отказ самого сохранения удаляет только частичную новую задачу и не затрагивает прежние результаты.

### Найти проблему в HTML

У предупреждения CSS или изображения нажмите «Показать фрагмент». Инспектор покажет соответствующий импортированный абзац/таблицу, текст и сведения об изображении. Для общих правил, например `@page`, откроется «Весь документ». Можно пользоваться клавиатурой; после перехода фокус окажется в инспекторе.

Привязка сохраняется в JSON модели и сохранённой задаче. Инспектор показывает фрагмент после импорта, до последующих правок модели; это не изображение страницы и не редактор CSS. Подробнее: [HTML-импорт](formats.md#переход-от-предупреждения-к-фрагменту).

## Пакетная обработка

Выберите несколько файлов на странице конвертации. В простом режиме укажите общий формат. В экспертном режиме можно выбрать приоритет и раскрыть «Выбор формата каждого файла». Если общего формата нет, экспертный режим открывается автоматически и возврат в простой недоступен до смены набора файлов. Индивидуальные настройки сохраняются при повторном запуске; бюджеты сохранности общие для пакета.

| Действие | Что происходит |
|---|---|
| Поиск по имени и фильтр состояния | Меняется видимый список, не состав будущего ZIP |
| Просмотр готового файла | Открывается его отчёт и доступный предпросмотр |
| «Отменить оставшиеся файлы» | Отмена ожидающих и запрос отмены выполняющихся; готовые файлы сохраняются |
| «Повторить неудачные» | Повторяются ошибочные, прерванные и отменённые задания, если сохранился исходник и доступен маршрут |
| «Повторить выбранные (N)» | В раскрытом пакете истории отметьте нужные неудачные файлы; повтор затронет только их |
| «Отменить выбранные (N)» | В истории отметьте ожидающие или выполняющиеся файлы; готовые и невыбранные результаты сохраняются |
| «Скачать выбранные (N)» | ZIP содержит только отмеченные готовые файлы; остальные задачи могут продолжать выполняться |
| «Перезапустить» | Полный повтор пакета; отличается от повтора только неудачных |
| «Скачать готовые результаты ZIP» | После завершения пакета выдаются все доступные успешные результаты и manifest со статусами |
| «Удалить» в истории | Удаляется сохранённый пакет; для дальнейшей обработки потребуется исходник |

ZIP сохраняет одинаковые имена в разных нумерованных папках; HTML-просмотрщик может оказаться вложенным архивом. Общий размер выдаваемых результатов ограничен 512 МБ. ZIP всего пакета доступен после завершения задач. Для выбранных готовых файлов ожидание остальных не требуется. При исчезновении файла обновите историю.

Для выборочного повтора раскройте пакет в истории, отметьте «Выбрать» у нужных ошибочных, прерванных или отменённых файлов и нажмите «Повторить выбранные (N)». Без выбора кнопка недоступна. Готовые и невыбранные файлы сохраняются. Если статус успел измениться, исходник истёк или маршрут недоступен, файл пропускается с пояснением. Счётчик сообщает число поставленных в очередь файлов; при недоступной очереди они ожидают её перезапуска. Обновление истории сбрасывает выбор. Для выборочной отмены отметьте активные файлы, для выборочного ZIP — готовые. Счётчики кнопок показывают размер каждой выборки. Файл, завершившийся до отмены, сохраняет результат; при устаревшем выборе для ZIP обновите историю. История пакетов доступна на странице; общая панель «Задачи» — также на других страницах. [Технический контракт Web](web-details.md).

Если сохранение нового пакета не удалось, файлы и индивидуальные настройки остаются в форме: после устранения ошибки повторите запуск. Незавершённый пакет не передаётся очереди. При временном отказе очереди уже сохранённые задания остаются в ожидании с исходниками и настройками; они могут восстановиться при перезапуске приложения в пределах срока хранения.

При отказе записи повторного запуска прежний результат файла сохраняется, а история сообщает причину пропуска. Остальные пригодные выбранные файлы могут запуститься. Проверьте сообщение и повторите действие позже; невыбранные готовые файлы сохраняются.

## Форматы и сохранность

Таблица описывает пути через промежуточную модель документа. Наличие расширения в справке не означает, что доступны любые пары форматов. Проверяйте каталог Web или `plan` в своём окружении.

| Формат | Реализовано | Практическая граница |
|---|---|---|
| DOCX | Импорт/экспорт текста, стилей, таблиц, секций, колонтитулов, изображений, ссылок, полей, сносок и OMML; сохранение ряда исходных частей OOXML | Сохранение непрозрачного XML сложного объекта не означает возможность редактировать его моделью. Не все изменения comments/SmartArt/OLE проверены в Word |
| PDF | Извлечение текста, геометрии, таблиц, растровых и векторных объектов; определение порядка чтения, слияние с OCR; экспорт модели в PDF | Семантика восстанавливается эвристически. Формы, слои, tagged PDF и редактируемые формулы покрыты не полностью; SVG может стать растром с сообщением о потере |
| PPTX | Импорт слайдов, текста, групп/геометрии, фигур, таблиц, изображений, диаграмм, формул, фона и заметок; экспорт модели в редактируемый PPTX | Секция становится слайдом; автоматической разбивки длинного текста нет. Упрощаются отдельные темы, заливки и диаграммы; exporter не предлагается в `faithful` |
| HTML/HTM | Статический импорт абзацев, списков, таблиц, ссылок, SVG/MathML и встроенных изображений; базовый CSS; автономный HTML-экспорт | Скрипты и внешние ресурсы не загружаются. Flex/grid, позиционирование, paged media и полный CSS не поддержаны |
| EPUB | Главы по порядку spine, оглавление, абзацы, ссылки между главами, изображения и базовый CSS → модель | Обратной сборки EPUB нет; экспортируйте модель в HTML/DOCX/PDF и другие доступные цели |
| TXT | Импорт в модель и экспорт UTF-8; пробелы, пустые строки и конечный перенос в текстовом обратном пути | Оформление, геометрия и интерактивные ссылки не сохраняются. Табличный текст разделяется табуляцией, а не становится обратимой таблицей |
| DjVu | Извлечение плоского текста через `djvutxt` | Богатый импорт страниц и координат пока в плане |
| LaTeX | Экспорт текста/документа доступными конвертерами; DOCX-извлечение с вариантом Pandoc | Это не универсальный импорт произвольного TeX-проекта в богатую модель |
| JSON-модель | Версионированное сохранение структуры, ресурсов, свойств и диагностики; повторный экспорт | Обычный JSON с данными шаблона не является JSON-моделью документа |

Шрифты выбираются с учётом доступных гарнитур и начертаний. Отчёт может сообщать о подменах, отсутствующих символах и ограничении встраивания. Поддержано встраивание разрешённых шрифтов в HTML, DOCX и PDF; результат зависит от исходных шрифтов и маршрута. Наличие такого механизма не обещает одинаковую вёрстку во всех программах. Общая поддержка ICC/CMYK и сложного смешивания цветов ещё не завершена.

### Конвертация из командной строки

```powershell
uv run textalchemy plan docx pdf --mode balanced --json
uv run textalchemy convert-file report.docx report.pdf --mode balanced --json
uv run textalchemy convert-file input.html model.json --json
uv run textalchemy convert-file model.json result.docx --json
uv run textalchemy inspect result.docx --json
```

По расширению определяются вход и выход. При неоднозначном имени используйте `--source-format` и `--target-format`. Повторяемый `--feature` задаёт приоритет, например `--feature tables --feature formulas`; это не гарантия полного сохранения.

Для проверки обратного пути используйте промежуточную модель:

```powershell
uv run textalchemy convert-file slides.pptx model.json --mode editable --json
uv run textalchemy convert-file model.json edited.pptx --mode editable --json
```

Между командами модель можно изменить через Python API. Прямое PPTX → PPTX (как и TXT → TXT, HTML → HTML) является тождественным маршрутом и не проверяет импорт/экспорт. Открывайте итоговый PPTX в PowerPoint и проверяйте редактирование нужных объектов. [Границы PPTX](formats.md#pptx), [проведённая приёмка на двух презентациях](../history/pptx-acceptance.md), [MathML](formats.md#mathml), [TXT](formats.md#txt), [EPUB](formats.md#epub).

## Отчёт и проверка качества

Перед HTML-экспортом стадия normalize подготавливает внутренние ссылки и закладки Word: ссылка становится переходом `#цель`, а начало закладки — строчным якорем в том же месте абзаца. Внешние адреса сохраняются. Исходная модель, нативные свойства Word и файл не меняются; подготовленные данные относятся к HTML. Строчные якоря, включая пустые, сохраняются при повторном HTML-импорте и экспорте в DOCX. Метрика `html_normalization` показывает число подготовленных закладок, нативных внутренних ссылок и строчных якорей; в отчёте маршрута она находится в `step_metrics.model.html`. Безымянная закладка даёт потерю `bookmark`; отсутствие цели ссылки выявляет последующая проверка HTML, и строгий бюджет может отклонить публикацию. HTML сохраняет точку перехода к началу закладки, но не редактирование выделенного диапазона Word. Проверка файловых циклов не заменяет проверку сохранения правок в Word.

При HTML-экспорте стадия layout рассчитывает CSS-геометрию блоков с заданной рамкой. Координаты `(0, 0)` сохраняют размещение у начала области содержимого и не превращают объект в обычный поток; изображения внутри абзацев остаются в потоке. Перенос affine-матрицы PPTX переводится из пунктов в CSS-пиксели, исходные координаты модели не меняются. Пустые колонтитулы не создают дополнительного отступа: на слайде без полей начало области содержимого совпадает с началом слайда. Метрика `html_layout` содержит число размещённых блоков, блоков у начала координат, affine-объектов и встроенных изображений; в отчёте маршрута она находится в `step_metrics.model.html`. Это подготовка геометрии поддержанных объектов, а не полноценный расчёт переноса текста, браузерной пагинации или точности всех свойств PPTX.

Перед HTML-экспортом стадия подготовки ресурсов проверяет наличие используемых изображений и читает внешние файлы в снимок модели. Один ресурс подготавливается один раз, даже если используется несколько раз. При отсутствующем файле или неверном типе ресурса экспорт завершается ошибкой до записи; прежний HTML сохраняется. Отчёт `resource_preparation` содержит число ссылок, запрошенных/подготовленных ресурсов и объём данных. Это проверка доступности ресурсов и их заявленного типа, а не декодирование изображения или подтверждение визуального качества.

После сериализации HTML проверяются внутренние ссылки вида `#цель`: цель должна существовать в готовом файле и быть однозначной. Ссылки на таблицы сохраняют их идентификаторы при импорте и экспорте. Отсутствующая или неоднозначная цель добавляет потерю `hyperlink` с номером строки; обычный экспорт допускает такой результат, строгий бюджет потерь может отклонить его с сохранением прежнего файла. Метрика `html_navigation` показывает число проверенных ссылок, отсутствующих/неоднозначных целей и повторяющихся идентификаторов. В общем отчёте маршрута она находится в `step_metrics.model.html`. Проверка выполняется на временном файле до атомарной публикации; ошибка чтения не заменяет результат. Внешние адреса не открываются. Это проверка навигации, а не визуального качества, всей семантики HTML или доступности внешних сайтов.

PDF-экспорт модели использует PyMuPDF (`--extra pdf`). Перед рендерингом стадия ресурсов читает используемые внешние изображения в снимок и преобразует SVG в PNG для движка Story. Повторно используемый SVG преобразуется один раз; исходная модель и файл не изменяются. Растровая замена отмечается потерей `image-vector`; строгий бюджет может отклонить публикацию PDF. Отсутствующее изображение или неразбираемый SVG дают ошибку до записи и сохраняют прежний результат. `resource_preparation` дополнительно содержит `svg_rasterized` и `png_bytes`; в отчёте маршрута эти данные находятся в `step_metrics.model.pdf`. Неиспользуемые вложения не декодируются. Это подготовка ресурсов PDF, а не обещание редактируемой векторной графики или полная визуальная проверка документа.

`ConversionReport` содержит итоговый путь, `success`, `lossless`, сообщения `issues` и данные `metrics`. Сообщение имеет серьёзность, тип проблемы, описание и иногда место в документе.

| Поле/показатель | Как понимать |
|---|---|
| `success: true` | Исполнение завершилось без зарегистрированной ошибки |
| `lossless: true` | Не зарегистрированы сообщения LOSS; не доказательство полной идентичности |
| `warning` | Замечание, которое следует проверить |
| `loss` | Известная потеря/упрощение; при строгом бюджете может блокировать результат |
| `error` | Ошибка выполнения или обязательной проверки |
| Сохранность структуры | Сравнение измеренных объектов; одинаковые количества не доказывают одинаковое содержимое |
| Визуальное сходство | Измерение доступных отрисованных страниц; не проверка редактируемости |
| `null` / «не измерено» | Нет сопоставимого измерения; не ноль и не 100% сохранности |

Строгие проверки CLI:

```powershell
uv run textalchemy convert-file input.html result.docx --max-loss-issues 0 --json
uv run textalchemy convert-file model.json result.docx --text-preservation flow --max-text-edits 0 --json
uv run textalchemy inspect source.docx --compare result.docx --output comparison.json --json
```

Во второй команде используется ранее сохранённая модель; сравнение третьей командой относится к исходному DOCX и результату.

| Параметр `convert-file` | Ограничение |
|---|---|
| `--max-loss-issues N` | Не более N сообщений LOSS; число сообщений не равно числу потерянных объектов |
| `--max-changed-formulas N` | Допуск несовпавших или удалённых исходных формул; непроверяемая структура блокирует результат |
| `--max-changed-emphasis N` | Допустимое число символов с изменённым жирным/курсивным выделением текста модели; пробелы исключены. |
| `--max-lost-objects N` | Бюджет объектов без совпадения, включая вложенные; неполное или неоднозначное измерение блокирует результат |
| `--require-unchanged-text` или `--text-preservation paragraphs` | Дословное сохранение непустых абзацев с учётом повторений; перестановки допустимы, разбиение/объединение — нет |
| `--text-preservation flow` | Проверка последовательности слов с нормализацией пробелов при переразбиении абзацев; порядок, регистр и пунктуация учитываются |
| `--max-text-edits N` | Допуск вставок/удалений/замен слов в проверке последовательности |

Для документов с формулами в Web раскройте **«Расширенная проверка сохранности»** после выбора файла и задайте «Допустимое число изменённых или удалённых формул». Пустое поле отключает проверку; `0` требует совпадения всех исходных формул. В CLI это `--max-changed-formulas 0`. В отчёте `formula_quality_gate` показывает число исходных формул, число несовпадений, лимит и результат проверки. Настройка общая для пакета и сохраняется при повторном запуске.

Проверка читает исходник и уже записанный результат. Считаются экземпляры формул, включая повторы и вложенные формулы; перестановка не считается изменением, добавленные формулы не расходуют допуск. Поддержанный MathML приводится к дереву Office Math (OMML); префиксы пространств имён и отступы XML не учитываются. LaTeX сравнивается по исходной записи. Неподдержанный MathML, повреждённая формула или недоступная инспекция дают «не проверено» с числом изменений `null` и блокируют результат даже при большом лимите. Формулы, не распознанные импортёром как объекты модели, этой проверкой не охвачены. Это проверка структурного совпадения, а не математической эквивалентности, визуального сходства или возможности правки в Office.

Не совмещайте `--require-unchanged-text` с `--text-preservation`. При отказе обязательной проверки новый результат не публикуется; прежний файл сохраняется. Для каталога результата нужен новый путь. В Web доступны соответствующие расширенные настройки и сводка принятого/отклонённого бюджета.

Допуск выделения доступен в Web после выбора файла, в «Расширенной проверке сохранности», и в CLI как `--max-changed-emphasis N`. Пустое поле отключает проверку; `0` запрещает изменение жирного и курсивного выделения, отражённого в тексте модели. Например, при переводе слова **Test** в TXT теряют выделение четыре символа: допуск `3` блокирует результат, `4` разрешает. Каждый символ считается один раз, даже при изменении обоих свойств. Подсчёт включает добавленное выделение. Шрифты, размеры, подчёркивание, цвет и компоновка не проверяются.

Проверка читает исходник и сериализованный результат. Пробельные символы, границы абзацев и разбиение на текстовые фрагменты игнорируются; оставшаяся последовательность символов должна совпадать. Изменённый текст, недоступная инспекция или более 10 000 последовательных групп выделения дают неизвестный результат (`changed_characters: null`) и блокируют публикацию при любом допуске. Учитывается только выделение, распознанное импортёром в `TextRun.style`; это не свидетельство полного сохранения оформления исходного файла. В отчёте результат находится в `metrics.emphasis_quality_gate`. Лимит сохраняется при повторе одиночных и пакетных задач.

## Распознавание и извлечение

На странице «Распознать скан» выберите PDF или изображение, затем язык и способ обработки. Выбор файла ещё не запускает распознавание: нажмите «Получить текст», когда настройки готовы. Для изображения автоматически используется OCR; выбор способа обработки PDF скрывается. Рукописный режим и GPU раскрываются отдельно. Для PDF:

| Сценарий | Поведение |
|---|---|
| `fast` | Используется существующий текстовый слой, OCR не требуется |
| `structure` | Анализ текста и слияние с OCR; нужны компоненты распознавания |
| `scan` | Распознавание страниц как изображений |

```powershell
uv run textalchemy recognize source.pdf --scenario fast --output extracted.txt
uv run textalchemy recognize scan.pdf --scenario scan --backend tesseract --lang rus+eng --output recognized.docx
uv run textalchemy recognize notes.png --backend paddle --mode handwriting --gpu --output notes.txt
```

Для изображений OCR требуется всегда. Поддержаны Tesseract, EasyOCR и PaddleOCR; `auto` выбирает доступный backend. `--mode handwriting` — запрос режима рукописного текста, а не обещание точного распознавания. Перепроверьте имена, числа и формулы.

Результат команды `recognize` в DOCX — распознанный текст, не полная реконструкция расположения объектов. Для богатой PDF-модели используйте `extract.pdf_model` в конвейере.

На странице подготовки PDF к конвертации кнопка «Сохранить и проверить DOCX» сохраняет правки и выполняет пробный экспорт. Замечания также появляются перед скачиванием DOCX. Если сообщение содержит адрес блока, кнопка «Показать блок на странице…» открывает исходную страницу, выбирает блок и показывает его рамку. Например, предупреждение о замене PDF-вектора текстовой подписью ведёт к содержащему рисунок блоку. Для вложенного объекта показывается рамка блока-контейнера, а не точная область вложения. Общие сообщения без однозначного адреса остаются без перехода.

Адрес страницы после перехода содержит выбранный блок: при перезагрузке он восстанавливается вместе с нужной страницей, пока доступен черновик. Отчёт проверяет конкретную сохранённую версию; при локальных изменениях он скрывается до новой проверки. Переход помогает найти проблему, но не устраняет потерю автоматически. Отсутствие замечаний экспортёра не означает полную сохранность документа. Проверенный сценарий — векторный рисунок на второй странице PDF → предупреждение DOCX → исходный блок, в том числе после перестановки.

На странице подготовки PDF к конвертации для прямоугольной таблицы без объединённых ячеек доступна правка границ по строкам и столбцам. Выберите таблицу в списке, задайте первую/последнюю строку и столбец (нумерация с 1 по исходной таблице). Рамка и предварительный просмотр покажут выбранный диапазон. После «Сохранить правки» или «Сохранить и скачать» только эти ячейки входят в таблицу модели и DOCX; ячейки за границами исключаются из результата. Содержимое и свойства оставшихся ячеек сохраняются, другие блоки не меняются. Кнопка «Вся исходная таблица» возвращает полный диапазон, в том числе после сохранения и перезагрузки, пока не истёк срок хранения черновика. Возврат также нужно сохранить.

Это обрезка лишних крайних строк/столбцов по уже определённым границам ячеек. Произвольное рисование рамки, разделение и объединение ячеек, добавление нераспознанных областей, OCR таблиц и нерегулярные/объединённые ячейки не входят в этот сценарий. Если координаты ячеек отсутствуют или сетка неподдержана, панель границ не показывается. Проверенный пример — таблица 3×3 с линиями сетки, обрезка до 2×2 и полное восстановление. Векторные линии исходного PDF остаются самостоятельными объектами; исходное изображение и его линии при обрезке не перерисовываются.

Для PDF с текстовым слоем выберите файл на странице «Преобразовать» и нажмите «Подготовить PDF к конвертации». Выбранный файл откроется без повторной загрузки. Также есть ссылка со страницы распознавания. Это подготовка структуры будущего документа, а не редактирование PDF: исходный файл не изменяется. Настройки показываются для выбранной области: заголовки — для текста, границы — для таблицы. По умолчанию скачивается DOCX; JSON-модель доступна для автоматизации. Загрузите PDF, выберите страницу и нажмите нужный фрагмент непосредственно на изображении либо выберите его в списке. Области также доступны клавишей Tab; рамка показывает текущий выбор. Кнопки «Выше» и «Ниже» меняют последовательность блоков внутри выбранной страницы. Другие страницы и колонтитулы не меняются. «Сохранить правки» записывает изменения; адрес страницы позволяет восстановить их после перезагрузки. Срок хранения — один час после записи. При конфликте вкладок локальный список остаётся на экране; перед загрузкой сохранённого порядка зафиксируйте нужные перестановки.

«Сохранить и скачать» выдаёт JSON-модель или DOCX. При перестановке в JSON сохраняются исходные свойства, координаты и ресурсы импортированных блоков, меняется только их последовательность. DOCX следует новому порядку, но перестраивает вёрстку и может упрощать сложные объекты. Изображение исходного PDF служит ориентиром и не меняется после правок. Этот экран не выполняет OCR и не переносит блоки между страницами. Приёмка проведена на двухстраничном PDF без поворота страниц с текстом и встроенным изображением; сложные PDF требуют отдельной проверки.

Для текстового блока доступен выбор «Тип выбранного текста»: обычный абзац или заголовок уровней 1–3. Выберите тип, при необходимости переставьте блок, затем нажмите «Сохранить правки» или «Сохранить и скачать». Классификация сохраняется вместе с порядком и восстанавливается после перезагрузки. В DOCX заголовок получает соответствующий стиль и уровень структуры; обычный абзац — стиль Normal. Исходное оформление отдельных фрагментов текста сохраняется, поэтому внешний вид может отличаться от стандартного заголовка Word. Изображения, таблицы и формулы этим переключателем не переклассифицируются. «Исходная классификация PDF» обозначает отсутствие ручного выбора, а не гарантированную правильность автоматического определения.

Для изменения порядка текстовых абзацев в Web поставьте курсор в нужный абзац или выделите несколько, затем нажмите «Переместить выше» или «Переместить ниже». Каждая новая строка, включая пустую, считается отдельным абзацем; перенос по ширине поля границу не создаёт. Кнопки доступны с клавиатуры. Новый порядок сначала появляется в поле как несохранённая правка. Нажмите «Сохранить правки» или «Сохранить и скачать», чтобы записать его в модель и экспортировать. Это перестановка текста, без изменения геометрии исходной страницы.

В Web откройте «Распознавание», загрузите файл и исправьте текст в поле результата. «Сохранить правки» записывает текст в модель документа; «Сохранить и скачать» сначала сохраняет изменения, затем выдаёт TXT, DOCX, PDF или JSON-модель в выбранном формате. Пустые строки сохраняются как абзацы. Это редактор текста: исходное расположение объектов, таблицы и изображения в этот результат не входят.

После распознавания адрес страницы содержит ссылку на сохранённый текст. По ней можно вернуться к работе после перезагрузки страницы или сервера. По умолчанию текст хранится один час с последнего сохранения; несохранённый ввод остаётся только в открытой вкладке. При конфликте с другой вкладкой правки не перезаписываются: скопируйте свой текст, загрузите сохранённую версию и внесите изменения заново. Если OCR для изображения или скана недоступен, страница сообщает об ошибке и не создаёт фиктивный результат.

На странице «Извлечь содержимое» выберите PDF, DOCX, TXT или DjVu, затем результат — чистый текст или LaTeX из Word — и нажмите «Извлечь содержимое». Формат исходника определяется автоматически; ручной выбор раскрывается при необходимости. Готовый результат можно копировать или скачать как TXT/TeX. Смена настроек относится к следующему запуску и не меняет уже полученный результат. При отсутствии текста страница предлагает распознавание скана.

Оба экрана показывают редактор/просмотр только после получения результата. Имя исходника находится рядом с готовым текстом. Если обработка не удалась, выбранный файл, настройки и прежний текст остаются — исправьте причину и повторите запуск. Во время обработки нельзя отправить второй файл или изменить её параметры. В OCR порядок абзацев и загрузка сохранённой версии находятся в раскрываемом блоке «Порядок абзацев и сохранённая версия». При замене текста с несохранёнными правками нужно подтвердить их потерю; выбор нового файла сам по себе их не удаляет.

Команда `extract` предназначена для DOCX:

```powershell
uv run textalchemy extract source.docx extracted.txt --format text
uv run textalchemy extract source.docx extracted.tex --format latex
```

Для универсального извлечения PDF/PPTX/HTML/EPUB/TXT/DjVu используйте `extract.text` в конвейере. Для email есть `extract.emails` и сохранение через `render.emails.docx`/`render.emails.txt`: PDF обрабатывается по текстовому слою с OCR при необходимости.

## Библиотека и библиография

В Web можно импортировать текстовый список источников или добавить запись вручную, затем редактировать и удалять отдельные записи. Изменение одной карточки сохраняет соседние источники. Импорт добавляет весь разобранный набор: при ошибке сохранения частичные записи не остаются в библиотеке. На узком экране таблица прокручивается внутри своей области. [Контракт API](web-details.md#библиография).

На странице «Источники» поиск фильтрует показанный список по автору, названию или году; рядом с общим числом записей появляется число найденных. Чтобы получить изменения из другого окна, нажмите «Обновить список». Типы документов показаны по-русски.

«Добавить источник» открывает новую карточку, кнопка редактирования строки — выбранную запись. Основные поля видны сразу; выходные данные, DOI/ISBN и путь к файлу находятся в раскрываемом блоке. При редактировании он открывается, если эти сведения уже заполнены. Карточка сохраняется только по кнопке «Добавить источник» или «Сохранить изменения». Переход к другой карточке, создание новой и отмена спрашивают о несохранённых правках; отказ оставляет введённые значения. Во время сохранения изменение карточки и другие действия с библиотекой заблокированы. При ошибке ввод сохраняется для повтора.

Для импорта раскройте «Импортировать список источников», выберите TXT, BibTeX или JSON и проверьте имя файла. «Добавить записи из файла» становится доступной после выбора; «Снять выбор» отменяет его. Импорт дополняет библиотеку и может добавить дубликаты при повторе. Если записи уже добавлены, а обновление списка не удалось, интерфейс сообщает об этом: используйте «Обновить список», повторно импортировать файл не нужно. При отказе самого импорта выбранный файл остаётся в форме.

В Web разделы «Источники», «Связать файлы», «Состояние коллекции» и «Экспортировать» позволяют вести записи, импортировать библиографию, сопоставлять локальные файлы, просматривать статистику и выгружать список. Сопоставление использует сигналы автора, заглавия, года, DOI/ISBN; сомнительные совпадения проверяйте и уточняйте вручную.

«Состояние коллекции» показывает число записей библиотеки, файлов в настроенной папке исходников, файлов в папке копий и соответствий последнего сопоставления. Наличие файла в папке копий не подтверждает его связь с записью; процент готовности из этих чисел не вычисляется. Обновление только читает данные и не запускает сопоставление или копирование. При отказе обновления прежние данные сохраняются с явным сообщением об их состоянии.

В сохранённом отчёте отдельно указаны соответствия, файлы без соответствия и ошибки. Пробный запуск обозначается как план без созданных копий; обычный показывает, была ли создана каждая копия. Ошибки видны сразу, подробные списки раскрываются по необходимости. Отчёт относится к последнему запуску: последующие изменения библиотеки и файлов требуют нового сопоставления. Проверка сохранности преобразованного документа находится на странице конвертации рядом с его результатом.

В «Связать файлы» предварительный просмотр рассчитывает имена без копирования. Тестовый запуск также оставляет исходники и выходной каталог без изменений. Ручные соответствия из настроек Web применяются и при просмотре, и при запуске. После обычного запуска отдельно проверяйте копии: совпадение может быть найдено, но файл не скопирован. Такие строки показывают «Копия не создана», а результат содержит ошибки вместо сообщения об успешном копировании. [Контракт отчёта и ручных соответствий](web-details.md#сопоставление-файлов).

```powershell
uv run textalchemy match -s ./literature -b bibliography.txt -o ./renamed --dry-run
uv run textalchemy match -s ./literature -b bibliography.txt -o ./renamed -t 0.30 --json
uv run textalchemy stats -s ./literature -o ./renamed -b bibliography.txt --json
uv run textalchemy gost -i bibliography.txt -o bibliography-gost.txt
uv run textalchemy export -i bibliography.txt -o bibliography.json -f json
uv run textalchemy bibtex -s ./literature -o bibliography.bib
```

`match` копирует совпавшие документы в выходной каталог с вычисленными именами; исходный каталог сохраняется. `--dry-run` здесь проверяет наличие записей и число файлов, а не рассчитывает полный предварительный список совпадений. Статистика CLI считает файлы каталогов, поэтому используйте отдельный каталог результатов без посторонних файлов. Оформление ГОСТ и извлечённые метаданные стоит проверить перед публикацией.

Указывайте `-s`, `-b`, `-o` явно: значения по умолчанию могут обращаться к `literature_files`/`renamed` и автоматически найденной библиографии. `match --json` записывает `matching_report.json` в текущий каталог; в терминале остаются служебные строки. В `matched` каждая запись содержит `original` (исходное имя), `new` (строковый путь фактически созданной копии), `score` и `signals`. Путь сохраняет относительный или абсолютный вид аргумента `-o`. В `unmatched` перечислены имена файлов без совпадения.

При ошибке копирования совпадение остаётся в `matched`, но `new` равно `null`, а причина выводится в журнал. Успех сопоставления не подтверждает создание всех копий: проверяйте `new`. В Python результат `match.files` содержит поле `copied_path`: путь успешной копии либо `None`, если файл не копировался. Исходные документы сохраняются.

`uv run textalchemy init -o config.json` создаёт шаблон структуры `Config` для Python API (`Config.from_file`). Это не файл настроек CLI и не конвейер для `run`. Глобальный `-c`/`--config` не поддерживается ни одной командой CLI: при его передаче запуск завершается с кодом 1 и пояснением до выполнения команды. Содержимое файла не читается; существующий, отсутствующий и пустой путь отклоняются одинаково. Явные параметры команды не отменяют этот отказ, поэтому приоритета настроек файла над ними нет. Уберите `--config` и используйте явные аргументы либо [конвейер YAML/TOML/JSON](#автоматизация). Настройки Web хранятся отдельно.

## Документы из шаблонов

Для заполнения документа из Python доступен интерфейс `textalchemy.templating`: модель OpenDoc и данные → новая заполненная модель. Он работает без Web и обработчиков файлов; [пример и правила подключения изображений и библиографии](../development/templating.md). Прежние функции `textalchemy.generate` сохраняют чтение шаблонов и экспорт DOCX/HTML/PDF.

На странице «Создать по шаблону» сначала выберите основу. Режим **«Заполнить документ»** показывает данные и скачивание DOCX/HTML/PDF. Заголовок и автор идут перед основным текстом; основной текст и аннотация допускают несколько строк. Схема задаёт обязательность, типы и значения по умолчанию; ошибки показываются у полей. Предпросмотр автоматически создаёт файл выбранного формата через 1,2 секунды после паузы во вводе и показывает его страницы. Одновременно выполняется один запрос; устаревший ответ не заменяет новые данные. «Исходный шаблон» переключает просмотр на основу, «Вернуться к предпросмотру» возвращает результат; «Скачать просмотренный файл» выдаёт именно этот снимок. Изменение данных помечает просмотр устаревшим и скрывает ссылку до обновления. Файл хранится один час. Если просмотр страниц недоступен, созданный файл всё равно можно скачать. Если просмотр недоступен, заполнение и скачивание остаются доступны; на узком экране просмотр находится после формы.

Для правки основы выберите **«Изменить шаблон»**, затем нужное действие из описанных ниже. Одновременно раскрыта одна панель настроек. Переключение режимов сохраняет введённые данные. Сохранение правки создаёт отдельную копию и возвращает к заполнению её полей; исходный черновик остаётся привязанным к исходному шаблону. Это редактор поддержанных конструкций, а не свободная правка страницы как в Word.

Текстовые списки заполняются **по строкам**: нажмите «Добавить строку», введите значение, при необходимости переместите его кнопками ↑/↓ или удалите. Одна строка списка может содержать многострочный текст. Порядок, повторы и пустые строки сохраняются в черновике, именованном наборе и данных для генерации; удаление всех строк задаёт пустой список. Для вставки готового массива есть режим **JSON**. Списки с числами, объектами, другими нетекстовыми значениями или более чем 200 элементами открываются в JSON без преобразования типов. Незавершённый JSON сохраняется в черновике; вернуться к строкам можно после исправления. Переключение режимов не заменяет пустое незаполненное поле значением по умолчанию.

Переключатель заполнения и изменения шаблона находится перед рабочей областью. Управление наборами и удаление временного черновика находятся в раскрываемой панели **«Сохранённые данные и черновик»** после полей. Текущий статус автосохранения виден под формой данных в режиме заполнения. Обычный текст использует общий шрифт интерфейса; JSON и формулы — моноширинный. [Компоновка и прикладные сервисы](web-details.md#представление-генератора-и-прикладные-сервисы).

Черновик автоматически сохраняется в хранилище текущей вкладки отдельно для каждого шаблона. После перезагрузки сохраняется выбор шаблона, но форма начинает с его исходных значений, формата DOCX и имени output.docx. Прежние поля и загруженные изображения, включая логотип, автоматически не применяются. Кнопка «Восстановить предыдущий черновик» явно возвращает их вместе с форматом и именем файла. При переключении шаблонов внутри текущей страницы уже введённые данные сохраняются. Изображения записываются в черновик после завершения чтения файла. Незавершённый JSON и пустые значения тоже сохраняются, а проверка схемы выполняется при генерации. Под полями изображения появляется пояснение о восстановленном содержимом: сам выбор файла браузер повторно не заполняет. Другая вкладка ведёт собственный черновик и не перезаписывает текущий.

Это временное хранение в браузере, не архив: после закрытия вкладки восстановление не гарантируется. Большие изображения могут исчерпать квоту. Если черновик не удалось записать, статус сообщает об этом, ввод остаётся на экране; перед уходом сохраните нужные данные отдельно. Если при явном восстановлении обнаружены повреждение черновика или изменение схемы, он не применяется и защищается от перезаписи до удаления. Ввод в новой форме заменяет предыдущий черновик этого шаблона. «Удалить черновик этого шаблона» после подтверждения удаляет только его копию в текущей вкладке и возвращает поля к исходным значениям.

Для повторного использования заполните имя в разделе именованных наборов и сохраните новый набор. Он хранится на сервере без срока истечения и доступен в других вкладках этого приложения. Список показывает наборы выбранного шаблона. Выберите набор и загрузите его: после подтверждения восстановятся поля, изображения, формат и имя выходного файла. Затем можно создать документ или изменить данные и обновить загруженный набор. Последующие правки формы не записываются в именованный набор автоматически.

Если другая вкладка уже обновила набор, запись будет отклонена, а ваш ввод останется на экране. Сохраните его под новым именем либо загрузите актуальную версию. Совпадение имён внутри одного шаблона не приводит к перезаписи. При изменении схемы несовместимый набор остаётся в хранилище, но не загружается. Можно сохранить незавершённые данные, включая некорректный JSON; перед генерацией действует обычная проверка полей. Размер одного набора вместе с изображениями ограничен 5 МБ. Наборы общие для экземпляра приложения; удаление временного черновика их не затрагивает.

Предпросмотр можно открыть до заполнения обязательных полей. В этом случае он подписан «Черновой просмотр»: пустые текстовые места обозначены «Не заполнено», незаданные списки считаются пустыми, флажки — выключенными, а рядом перечислены недостающие поля. Кнопка «Скачать черновик» выдаёт этот же файл с пометкой в имени. Ошибки типов и некорректный JSON по-прежнему требуют исправления; «Создать документ» сохраняет полную проверку схемы.

### Шаблон из обычного DOCX

1. В «Создать по шаблону» раскройте **«Создать шаблон из своего DOCX»**, выберите документ и загрузите отдельную копию. Подойдут служебная записка, титульный лист, отчёт или другой DOCX с обычным текстом; заранее писать переменные не нужно.
2. В редакторе откройте **«Сделать значение полем шаблона» → «Показать текст образца»**. Выберите абзац, ячейку таблицы или колонтитул. В поле поиска оставьте точный заменяемый текст — например, ФИО или марку автомобиля. Предложения дат и ФИО служат только подсказками.
3. Нажмите **«Найти вхождения»**. В контексте отмечены совпадения; выберите только те, которые должны изменяться вместе. Одинаковые ФИО руководителя и исполнителя автоматически не связываются.
4. Назовите поле понятным именем и сохраните копию. В форме появится это поле с прежним значением. Для следующего поля повторите действие с новой копией.
5. Введите новые данные, посмотрите заполненный результат и скачайте DOCX. Исходный документ и предыдущие копии остаются доступны; копии и их схемы сохраняются после перезапуска приложения.

При простых текстовых подстановках DOCX сохраняет исходный пакет: заменяются только выбранные вхождения, остальные XML-части и вложенные ресурсы не переписываются. Переносы строк в значениях становятся разрывами строк Word. При создании условий, циклов и богатых объектов используется модельный экспорт с описанными ограничениями формата. Склонение ФИО, замена уже существующего изображения и вложенные текстовые области не выполняются автоматически. Пределы импорта: DOCX без макросов, до 100 МБ распакованного содержимого и до 2000 текстовых абзацев для выбора вхождений.

### Вставка объектов и сочетание действий

В редакторе панель **«Изображение, формула, источники или ссылка»** позволяет выбрать обычный абзац основного документа и сохранить копию со вставкой. Изображение, формула, список источников и ссылка заменяют содержимое выбранного абзаца. Метка сохраняет текст абзаца и добавляет цель для ссылки; в другом месте выберите ссылку с тем же именем, например `sec:conclusion`.

После вставки изображения форма предлагает файл; для формулы — LaTeX или MathML. Поддержанный MathML экспортируется в редактируемую формулу Word, LaTeX может стать текстовой альтернативой. Источники можно ввести отдельными текстовыми строками либо объектами библиографии в JSON. Отсутствующая цель ссылки даёт ошибку генерации.

В одной копии можно последовательно сочетать поля, независимые условия, повторяемые абзацы, строки таблиц и вставки. Уже обёрнутый другой конструкцией абзац не предлагается для вложенного оборачивания. Else, вложенные циклы, объединённые ячейки и произвольная правка страницы как в Word в этот редактор не входят.

### Правка переменной в Web

Для переименования поля существующего DOCX-шаблона раскройте «Изменить переменную шаблона», нажмите «Показать переменные», выберите поле по имени и контексту. Введите новое уникальное имя латинскими буквами, цифрами и подчёркиванием (не начинайте с цифры), затем сохраните копию шаблона. Во всех простых вхождениях переменная будет переименована, её тип и обязательность сохранятся в обновлённой схеме. Копия появится в списке шаблонов и останется доступна после перезапуска приложения. Заполните её поля и создайте документ; данные исходного шаблона и его именованные наборы автоматически не переносятся.

Исходный шаблон остаётся прежним. В копии переменная, разбитая между фрагментами Word, собирается в один фрагмент с оформлением её начала; соседний текст сохраняет своё оформление. Этот сценарий поддерживает простые переменные в абзацах, таблицах и колонтитулах. Независимые простые условия, циклы и вставки могут оставаться в шаблоне; управляющие поля настраиваются отдельными действиями. Сложные выражения и вложенные текстовые области не поддерживаются.

### Условный абзац в Web

Раскройте «Настроить условный абзац» и нажмите «Показать абзацы». Выберите абзац основного текста и задайте имя поля-флажка, например `show_section`. Новое поле появится в форме данных выключенным; можно использовать уже существующее boolean-поле. По умолчанию абзац показывается при включённом флажке. Для обратного правила отметьте «Показывать, когда флажок выключен». Сохраните копию с условием, заполните её данные и создайте документ. Проверьте результат с обоими значениями флажка.

Копия сохраняется на сервере вместе со схемой. После повторного выбора копии можно снова загрузить абзацы: редактор покажет имя поля и направление условия. Сохранение новой правки создаёт ещё одну копию и заменяет условие выбранного абзаца, не вкладывая его в прежнее. Старое поле схемы при смене имени остаётся, чтобы не затронуть другие вхождения. При изменении шаблона или схемы после загрузки абзацев сохранение отклоняется; загрузите список заново. Поддержан один абзац основного текста без else и вложенности. Редактор условия не изменяет циклы, условия в таблицах/колонтитулах и сложные управляющие выражения.

### Повторяемый абзац в Web

Раскройте «Повторять абзац по списку» и загрузите абзацы. Выберите абзац основного текста с простой переменной, затем переменную для очередного значения и имя поля-списка (например, `items`). Сохраните копию с циклом. В данных копии появится список: добавьте строки «Первый» и «Второй», чтобы получить две копии абзаца в этом порядке. Пустой список убирает абзац. Повторяющиеся значения сохраняются. Все вхождения выбранной переменной внутри этого абзаца получают очередное значение, остальные переменные продолжают использовать общие данные.

Копия DOCX и её схема остаются на сервере после перезапуска. После повторного выбора копии загрузите абзацы, чтобы увидеть источник списка и при необходимости изменить его. Это создаст новую копию без вложения второго цикла. Старые поля схемы сохраняются, поскольку могут использоваться в других частях документа; заполните обязательные поля даже при пустом списке. Поддержан один основной абзац без разрыва секции; таблицы, условия, сложные выражения и вложенные циклы этим редактором не правятся. Имена нового списка должны быть допустимыми идентификаторами и не совпадать с полями другого типа. Изменение исходника или схемы после загрузки списка блокирует сохранение до обновления.

### Повторяемая строка таблицы в Web

В генераторе откройте **«Повторять строку таблицы» → «Показать строки таблиц»**. Выберите строку, переменную для очередного значения и имя поля-списка; сохраните копию. В данных копии добавьте значения по строкам, например «Первый», «Второй», «Первый» (эквивалент в JSON: `["Первый", "Второй", "Первый"]`). Выбранная строка таблицы повторится в этом порядке вместе с остальными ячейками. Пустой список убирает строку; заголовок и итоговая строка остаются. Повторная настройка меняет источник списка без вложенного цикла.

Поддержаны строки простых таблиц основного текста без объединённых ячеек и вложенных таблиц. Редактор заменяет одну выбранную переменную значениями списка; это не сопоставление отдельных полей объекта столбцам. Независимые условия, циклы абзацев и строк таблиц могут находиться в одном шаблоне; вложенные конструкции этим редактором не создаются. Исходник сохраняется; прежние поля схемы остаются для других вхождений переменных.

Свой DOCX загружается через «Создать шаблон из своего DOCX». Готовый шаблон может сопровождаться JSON-схемой в дополнительных настройках. Если в выбранном шаблоне нет подходящих строк, редактор сообщает об этом. Заполненный результат можно проверить до скачивания.

### Пример собственного шаблона

Создайте `template.docx` в Word с такими абзацами (каждая управляющая строка — отдельный абзац):

```jinja2
{{ title }}
{% if show_body %}
{{ body }}
{% endif %}
{% for item in items %}
{{ item.name }}: {{ item.value }}
{% endfor %}
```

Данные [template-data.json](../examples/template-data.json) и схема [template-schema.json](../examples/template-schema.json) готовы для этого примера:

```powershell
uv run textalchemy template-check template.docx --schema docs/examples/template-schema.json --data docs/examples/template-data.json --json
uv run textalchemy generate template.docx result.docx --schema docs/examples/template-schema.json --data docs/examples/template-data.json --json
uv run textalchemy generate template.docx result.html --data docs/examples/template-data.json --json
uv run textalchemy generate template.docx result.pdf --data docs/examples/template-data.json --json
```

Результат содержит заголовок, описание и две строки измерений. Можно передать JSON/YAML/TOML; повторяемый `-p key=value` переопределяет отдельные данные. По умолчанию неизвестные переменные вызывают ошибку; `--no-strict` ослабляет это правило, но не исправляет неверный шаблон.

Список встроенных шаблонов: `uv run textalchemy generate --list`. Поставляются `abstract`, `article`, `laboratory`, `report`; для `laboratory` есть [схема](../../src/textalchemy/generate/templates/laboratory.schema.json). Проверяйте поля выбранного DOCX командой `template-check` перед заполнением.

### Таблицы, изображения, формулы и ссылки

Циклы могут повторять строки таблицы: управляющая конструкция должна занимать отдельную строку таблицы. Типизированное изображение или формула подставляется в отдельный placeholder `{{ logo }}` / `{{ equation }}`. В схеме укажите `image`/`formula`; значение изображения содержит `source`, `alt_text` и при необходимости `width_pt`/`height_pt`, формулы — `value`, `format` (`latex`, `mathml`, `omml`) и `fallback_text`. В Web используйте предназначенные для этого поля загрузки/ввода.

| Конструкция | Результат |
|---|---|
| `{{ bibliography() }}` | Нумерованный список из данных `bibliography` или `references` |
| `{{ toc() }}` | Оглавление по заголовкам модели; указатели основаны на секциях, не на окончательной пагинации Word |
| `{{ id('fig:plot') }}` и `{{ ref('fig:plot') }}` | Регистрация метки и ссылка; также поддержаны `tbl:` и `sec:` |

Шаблонный язык ограничен подстановками и поддержанными конструкциями; произвольный Python не выполняется. Неподдержанная формула может перейти в текстовую альтернативу с диагностикой. Полного визуального редактора конструкций шаблона в Web пока нет.

## Автоматизация

В Web-конструкторе у файлового параметра есть **«Выбрать файл с компьютера»**. После загрузки файл доступен один час; при истечении срока выберите его заново. Поле пути остаётся для опытных пользователей. Файловые результаты создаются в отдельной рабочей папке запуска: в параметрах `output_path`, `output_dir`, `output` задаётся имя, а не место перезаписи на компьютере. После успешного запуска ссылки **«Скачать…»** выдают созданные файлы; каталоги выдаются ZIP. Текстовый итог тоже доступен файлом. Результаты хранятся один час, входные файлы не меняются. В CLI пути по-прежнему имеют обычный смысл.

На странице «Автоматизировать» (`/pipeline`) соберите шаги и связи. Начальный пример содержит открытие файла, извлечение текста и LaTeX: сначала выберите файл, фиктивного пути по умолчанию нет. Каталог действий свёрнут; «Добавить действие» открывает его и переводит к поиску. Действия группируются по назначению, поиск работает по русскому названию, описанию и техническому имени. Обязательные параметры видны сразу, дополнительные раскрываются отдельно. В Web текстовый режим принимает YAML или JSON; CLI также читает TOML. Начальные данные и результаты шагов образуют общий контекст.

«Проверить связи» проверяет описание сценария без выполнения операций: доступность файлов и качество результата при этом не подтверждаются. Правка шага снимает прежнее сообщение об успешной проверке. «Запустить» выполняет сценарий; на время проверки, запуска, загрузки файла и переноса между режимами редактирование заблокировано. Если загрузка файла отказала, текущий путь шага не меняется, выбранный файл сохраняется и появляется «Повторить загрузку».

Вход шага выбирается среди начальных данных и результатов предыдущих шагов. Новые шаги получают неповторяющиеся имена результатов; если типы соседних операций точно совпадают, связь предлагается автоматически. После удаления, переименования или перестановки источника недоступная связь остаётся видимой с пояснением — выберите подходящий источник. Проверка связей не гарантирует совместимость всех значений и успешное выполнение операции.

Возврат из текстового режима через кнопку «Конструктор» переносит правки; при ошибке разбора текст остаётся на экране. Результат последнего запуска виден в обоих режимах: статус, выполненные шаги, ошибка или итоговое значение. Полный JSON находится в раскрываемом отчёте. Путь к созданному файлу относится к компьютеру, где запущен сервер; это не ссылка на скачивание в браузере.

При отказе преобразования в YAML конструктор переносит текущие правки в JSON и сообщает об этом. Недоступное действие после импорта текста сохраняет своё имя и показывается явно; проверка связей сообщает об ошибке. После редактирования готовый результат остаётся доступным с пометкой «результат предыдущего запуска». Ссылки скачивания расположены перед подробностями выполнения и относятся к этому сохранённому запуску.

Готовый [пример конвейера](../examples/text-to-docx.yaml) читает [текст](../examples/input.txt) и создаёт `.textalchemy/user-guide/result.docx`:

```powershell
uv run textalchemy run docs/examples/text-to-docx.yaml --json
uv run textalchemy run --list
```

В примере `output` шага даёт имя результату, `input` следующего шага ссылается на это имя. `params: {x: $y}` передаёт значение `y` из контекста; `params: {x: "{title}"}` подставляет текстовое значение. Для буквальных фигурных скобок в параметрах конвейера используйте `{{` и `}}`. Пути относительны каталогу запуска, а не файлу YAML.

Полный проверенный перечень зарегистрированных операций и их входов/выходов — [справочник операций](../reference/operations.md). Отличайте `render.json` (JSON библиографии) от сохранения JSON-модели через `convert-file`. Модельные операции экспорта PPTX/TXT возвращают отчёт; `render.docx_model` возвращает путь. Формат `run --json` сохраняет эти различия.

Для `render.bibtex`, `render.gost`, `render.markdown`, `render.json` свяжите шаг с библиографией через `input: bib`: реестр передаст список в аргумент `items`. Значение `bib` может быть результатом `bibliography.parse`/`bibliography.smart_parse` либо списком записей в начальном контексте. Прежняя запись `params: {items: $bib}` без поля `input` также поддерживается.

[Готовый пример библиографии → JSON](../examples/bibliography-to-json.yaml):

```powershell
uv run textalchemy run docs/examples/bibliography-to-json.yaml --json
```

В этом примере результат находится в поле `final` отчёта конвейера как строка JSON. Чтобы получить список записей программно, разберите сначала отчёт, затем `final`. Для другого оформления замените `render.json` на `render.bibtex`, `render.gost` или `render.markdown`; связь `input: bib` остаётся той же.

## Справочник команд

Префикс для каждой команды: `uv run textalchemy`. Перед командой допустим `--debug`; `--version` показывает версию. Детальные параметры: `uv run textalchemy <команда> --help`.

| Команда | Назначение | Примечание |
|---|---|---|
| `convert-file input output` | Универсальный доступный маршрут | Основной способ конвертации одного файла |
| `plan source target` | План и прогноз потерь | Без преобразования документа |
| `inspect input` | Структура, `--compare`, JSON-отчёт | `--strict` завершает команду ошибкой при замечаниях |
| `convert -i input -o output` | Специализированный PDF → DOCX | `fanout` по умолчанию; также pdf2docx/pymupdf/libreoffice |
| `pptx2html -i slides.pptx -o viewer` | Отдельный HTML-просмотрщик презентации | Каталог с HTML/assets; покрытие отличается от общего model → HTML |
| `extract input [output]` | DOCX → text/latex/pandoc | Для других источников — `extract.text` в pipeline |
| `recognize input` | OCR и PDF-сценарии | `--output` выбирает выходной файл |
| `generate template output` | Документ из данных | DOCX-шаблон → DOCX/HTML/PDF; также `--list` |
| `template-check template` | Проверка шаблона/схемы/данных | Без генерации |
| `match` | Библиография → совпавшие файлы | Явные каталоги и порог |
| `stats` | Статистика каталогов библиотеки | Не оценка точности совпадений |
| `gost` | Форматированный список литературы | Нужны `-i` и `-o` |
| `export` | Библиография → JSON/Markdown/ГОСТ | Не экспорт произвольного документа |
| `bibtex` | Сбор .bib по PDF в каталоге | Проверьте извлечённые поля |
| `init` | Пример конфигурации | `-o config.json` |
| `run` | Выполнение YAML/TOML/JSON | `--list` перечисляет операции |
| `completion bash` | Скрипт дополнения команд | Также zsh/fish; PowerShell-варианта нет |
| `web` | Локальный сервер | По умолчанию 127.0.0.1:8000 |

Большинство команд имеют `--json`, но контракт зависит от команды; `export`, `init`, `web`, `completion` используют другие способы выдачи. Проверяйте код завершения вместе с результатом; CLI без команды показывает справку и возвращает 1.

## Python API

Для собственных приложений, которым нужна только структура документа, подключайте самостоятельный пакет `opendoc`. Его руководство находится в `C:/project/opendoc/docs/guide/index.md`; библиотека создаёт и сохраняет модели, валидирует ресурсы и сравнивает структуру. TextAlchemy добавляет обработку файлов и пользовательские сценарии. [Подключение, JSON-совместимость и обновление зависимости](../development/document-library.md). Старые импорты `textalchemy.core.*` сохраняются для существующего кода приложения.

Для программной конвертации используйте те же маршрут и отчёт, что в CLI:

```python
from pathlib import Path
from textalchemy.convert.executor import ConversionExecutor, ConversionRequest
from textalchemy.core.types import DocFormat

report = ConversionExecutor().execute(ConversionRequest(
    Path("input.html"), Path("result.docx"), DocFormat.HTML, DocFormat.DOCX,
))
print(report.to_dict())
```

Для изменения модели:

```python
from textalchemy.core.document_codec import load_document, save_document
from textalchemy.core.document_model import Paragraph, TextRun

document = load_document("model.json")
paragraph = next(block for block in document.sections[0].blocks if isinstance(block, Paragraph))
paragraph.content = [TextRun("Исправленный текст")]
save_document(document, "edited.json")
```

Этот пример целиком заменяет содержимое первого абзаца, включая прежнее строчное оформление и вложенные элементы. Для сохранения формул/ссылок изменяйте только нужный `TextRun`. `DocumentModel` содержит секции, абзацы, таблицы, изображения/формулы, ресурсы и сведения об их происхождении; `Text` предназначен для плоского текста. [Контракты разработки](../../AGENTS.md).

## Хранение и решение проблем

Web хранит библиотеку в SQLite и задачи/артефакты в пользовательском каталоге данных TextAlchemy, определённом `platformdirs`. История конвертаций и результаты имеют TTL один час; чистка выполняется при обращениях/обслуживании хранилища. Это не бессрочный архив. Сохранённые ожидающие/выполняющиеся конвертации могут возвращаться в очередь после перезапуска; восстановление зависит от наличия исходника и срока хранения.

| Ситуация | Действие |
|---|---|
| Нужного направления нет | Посмотрите причины в каталоге; установите соответствующие extras/внешние компоненты, перезапустите сервер |
| В HTML отсутствует картинка | Обычный CLI/Web не читает относительный внешний файл. Встройте изображение в HTML; Python-импортёр допускает явный ограниченный `resource_root` |
| Бюджет отклонил результат | Найдите конкретные сообщения/объекты. Исправьте исходник или осознанно измените лимит и повторите |
| Нельзя измерить сохранность | Проверьте покрытие инспектора для обоих форматов; не трактуйте неизвестное значение как успешную проверку |
| OCR недоступен | Проверьте backend и языки; для PDF с текстовым слоем попробуйте `fast` |
| Файл из истории недоступен | Срок истёк или артефакт удалён; загрузите исходник снова |
| Ошибка квоты/размера | Уменьшите документ/пакет; HTML-импорт ограничен 10 МиБ, также действуют квоты загрузки и распаковки |
| Отличается вид документа | Проверьте шрифты и сообщения о потерях, затем нужные страницы и объекты в целевой программе |
| Порт занят | Запустите Web с другим `--port` |

Сохраняйте исходник, результат и отчёт вместе. В обращении об ошибке укажите команду/действие, версию, формат, ожидаемое поведение и минимальный пример. Полная точность всех форматов, OCR и доступность по WCAG не заявляются проведёнными ограниченными проверками.
