# Аудит документации и переход к вехам

Исторический отчёт от 2026-09-13. Описанные ниже дефекты M0.1–M0.3 впоследствии исправлены; они не являются текущими ограничениями. Актуальные действия — в [руководстве](../guide/index.md), статусы — в [TODO](../../TODO.md), последующие изменения — в [истории](changes.md).

Дата: 2026-09-13. Объект — текущее рабочее дерево, включая незакоммиченные изменения. Проверены корневые README/TODO/AGENTS/CODING_STANDARDS, все Markdown-справочники docs и описания корпуса tests/corpus. Сопоставлялись парсер CLI, обработчики команд, реестр операций, маршруты Web, конфигурация зависимостей/CI, код импортёров/генератора и существующие свидетельства приёмки.

Аудит проверяет структуру документации и соответствие описанных действий реализации. Он не повторяет всю визуальную приёмку в Office, не запускает заново весь тестовый набор и не подтверждает автоматически каждую закрытую отметку старого TODO.

## Результат

Теперь пользователь начинает с [руководства](../guide/index.md), разработчик — с AGENTS/стандартов, планирование ведётся только в [TODO по вехам](../../TODO.md). README служит точкой входа. [Каталог документации](../README.md) разделяет использование, технические детали, план и свидетельства. Старый backlog стал указателем ID.

В карте миграции сохранены **273 из 273** отметок старого плана: 228 исторически закрытых, 45 открытых. Они не превращаются в процент готовности. [Снимок первоначального TODO](todo-2026-09-13.md) не изменён; [короткий TODO](todo-before-milestones-2026-09-13.md) сохранён отдельно и связан с M4.1. Крупные открытые родители разделены на выполненный базовый объём и остаток: например, PPTX/HTML — M2 и M5, TXT/EPUB/DjVu — M1 и M5.5.

## Найденные несоответствия

| Находка | Почему мешала | Действие/статус |
|---|---|---|
| README совмещал установку, API-контракты и неполный «полный список» операций | Пользователю трудно найти рабочий сценарий; HTML/EPUB и модельные экспорты отражены не полностью | Созданы руководство и справочник всех 27 зарегистрированных операций |
| Быстрый старт вызывал CLI без `uv run`; набор OCR/Web/dev назывался полным | Команды могли обращаться к другому окружению; отсутствовали форматные зависимости | Примеры используют uv и различают базовую, форматную и полную установки |
| README фиксировал «665 тестов», старые планы — другие числа | Число тестов выглядело показателем текущей готовности | В README оставлены команды; исторические числа только в датированных свидетельствах |
| Несколько P0/P1, короткая очередь и backlog жили параллельно | Повторы генератора, workspace, OCR-редактора, пакетов и архитектуры могли снова запускаться как новая работа | Один план M0–M8, старые ID и каждая архивная отметка имеют адрес назначения |
| Закрытые «визуально точные диаграммы», provenance/surrogate шире фактической приёмки | Структура XML/собственный golden могли восприниматься как доказанная совместимость | Старый статус сохранён только как история; текущие границы ссылаются на конкретную приёмку; остаток M5/M6 |
| PPTX-справочник говорил об открытой Office-приёмке статистики рядом с закрытой приёмкой презентаций | Было неясно, какой объём принят | Явно разделены полная статистика диаграмм и ограниченные два документа; устаревшее «следующий этап HTML» исправлено |
| В AGENTS PDF-exporter назван reportlab, регистрация операций приписана runner | Следующая работа могла опираться на неверную архитектуру | Исправлено на PyMuPDF Story и `pipeline.register_builtin_operations`, описан HTML-импорт |
| Пользовательский путь не объяснял тождественную конвертацию, OCR-DOCX, оглавление и значение lossless | Можно было считать копирование round-trip, текст OCR — восстановленной вёрсткой, номера секций — страницами | Ограничения и правильные проверки добавлены в руководство |
| Локальные абсолютные ссылки предыдущего аудита | Не работали в другой копии репозитория | Переведены в относительные ссылки на те же файлы; исторические номера строк остались в описании |
| `match --json` проверялся только на пустом каталоге | Непустое успешное совпадение ломает запись JSON | Дефект воспроизведён, оставлен открытым в M0.1; в руководстве есть обход через pipeline |
| Глобальный `--config` принимается, но не читается обработчиками | Пользователь может ожидать применения настроек, которые игнорируются | Подтверждено чтением кода; ограничение описано, исправление контракта — M0.2 |
| Четыре библиографические операции зарегистрированы с входом `input`, но принимают `items` | Описанная универсальная связь шагов падает с TypeError | Проверены все четыре: `input: bib` не работает, `params: {items: $bib}` работает. Обход описан в руководстве и справочнике, исправление — M0.3 |

## Что проверено исполнением

- 28 команд из блоков PowerShell руководства успешно разбираются актуальным CLI-парсером. Это проверка синтаксиса, не выполнение всех команд с условными именами файлов.
- Конвейер из `docs/examples/text-to-docx.yaml` реально создаёт DOCX; наличие исходного текста проверено повторным чтением.
- DOCX-шаблон с буквальным содержимым примера, приложенные JSON-данные и схема прошли `template-check`. Генерация DOCX, HTML и PDF успешна; заголовок, описание и обе строки измерений проверены чтением каждого результата.
- HTML → JSON-модель, изменение первого абзаца и сохранение JSON выполнены; новая строка сохранена. Строгий `--max-loss-issues 0` отклонил HTML с известными потерями, выходной DOCX не создан.
- Реестр выдал 27 операций; справочник сформирован из их реальных входов/выходов и сигнатур. Встроенный laboratory-шаблон отдельно прошёл инспекцию со своей схемой.
- Реальный минимальный пример сопоставления: одна запись библиографии, один TXT, порог 0. Получено `Matched: 1`, затем код 1 и `Object of type WindowsPath is not JSON serializable`. Копирование произошло до ошибки отчёта. Исходники/результат примера ограничены временным каталогом проверки.
- Проверено соответствие объявленного входа сигнатурам всех 27 операций. Для четырёх исключений воспроизведена ошибка связанного шага и успешный обход через `params.items`; протокол — `.textalchemy/docs-audit/operation-input-results.json`.
- Проверены 174 относительные ссылки/якоря в документации (кроме ссылок внутри неизменяемых снимков); ошибок нет. Каждая из 273 старых отметок встречается в карте ровно один раз. SHA-256 старого снимка: `c4fd10a562283efba21cd34fcd71b80e0619a64178a839c04b62d1f9050ad196`.

Три дефекта CLI/конвейера не исправлялись в документационном изменении; они получили конечные критерии в M0.1/M0.2/M0.3. Следующий порядок — M0.1 → M0.3 → M0.2 → прежний пользовательский результат M4.1.

Локальный протокол проверки примеров: `.textalchemy/docs-audit/examples-results.json`, результаты — `.textalchemy/docs-audit/smoke/` и `.textalchemy/user-guide/`; они игнорируются Git. В репозитории остаются входные примеры, руководство и карта миграции. Чтение текста PDF не является визуальной проверкой в Word/PowerPoint; новые офисные свидетельства не заявляются.

## Судьба существующих документов

| Группа | Решение |
|---|---|
| README | Краткий запуск и ссылки, без второго перечня планов |
| TODO и backlog | Единый план по вехам и указатель прежних ID |
| Старый TODO и его аудит | Сохранён исторический смысл; статусы не переобъявлены текущими |
| todo-history | Хронология выполненной работы, со ссылкой на единый план |
| HTML/EPUB/TXT/PPTX/MathML и Web | Сохранены технические контракты; руководство даёт сценарии и отсылает к подробностям |
| PPTX acceptance | Сохранены корпус, границы, версии, хэши и локальные свидетельства; обновлена только устаревшая ссылка на следующий этап |
| AGENTS/CODING_STANDARDS | Инструкции разработки; исправлены обнаруженные фактические неточности AGENTS, правила работы не переписывались |
| README корпуса и Office provenance | Сохранены происхождение и условия воспроизведения; не подменяют пользовательское руководство |

Исторические снимки сохраняют исходные относительные пути и номера строк; их ссылки следует читать в контексте старого корня репозитория. Новая карта миграции даёт актуальную навигацию. Внешние ссылки справочников в этом локальном аудите не перепроверялись.
