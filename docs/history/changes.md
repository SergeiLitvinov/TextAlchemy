## 2026-09-29 — новая форма и автоматический предпросмотр

После перезагрузки генератор сохраняет выбор шаблона, но открывает его исходные поля, DOCX и стандартное имя результата. Прежний текст и загруженные изображения, включая логотип, не применяются автоматически. Для возврата есть явное действие «Восстановить предыдущий черновик». Именованные наборы по-прежнему загружаются явно. Переключение шаблонов внутри текущей страницы сохраняет только текущий ввод; неприменённый снимок прошлого сеанса не должен внезапно восстанавливаться при возврате. Удаление черновика сбрасывает и временную копию в памяти.

Предпросмотр запускается автоматически через 1,2 секунды после паузы. На вкладку приходится не более одного выполняющегося запроса; изменения во время генерации объединяются в следующий запрос, устаревший ответ отбрасывается. Неполные поля дают черновой результат, ошибки JSON требуют исправления. Просмотр исходного шаблона приостанавливает автоматические запросы; кнопка возврата или повторной попытки остаётся вспомогательной. Модули генератора загружаются с версией ресурсов, чтобы после обновления приложения не оставалась старая логика восстановления.

Проверки включают чистую форму после перезагрузки, явное восстановление текста/изображения/списков, независимость вкладок, смену схемы, удаление черновика, автоматическое создание настоящего DOCX и задержанный ответ сервера, который не подменяет последний ввод. Общий прогон Web/архитектуры — 268 проверок; отдельно 174 проверки нового пути и архитектуры после исправления кэширования. Последние изменения восстановления проверены повторно выбранными браузерными сценариями. Руководство и M4 обновлены без открытия новой вехи.

## 2026-09-28 — завершение M4: образец, выборка и файловые сценарии

M4.4–M4.6 закрыты в описанных в TODO границах. Добавлен путь обычный DOCX → предложения изменяемых значений → явный выбор связанных вхождений → поле с понятным названием → заполненный DOCX. Одинаковые строки разных ролей не объединяются автоматически. Исходный образец остаётся отдельной копией. Для простых текстовых замен сохраняются нетронутые части пакета; проверены ФИО, разбитое на фрагменты с разным оформлением, постоянная таблица, колонтитул, разрывы строк и устаревший выбор. Готовый шаблон можно импортировать с необязательной схемой.

Редактор добавляет изображение, формулу, список источников и перекрёстную ссылку в выбранный основной абзац. Независимые простые условия, циклы абзацев и строк таблиц теперь совместимы в одной копии. Совместная проверка создаёт DOCX с обеими ветвями условия, повторами, изображением, нативной MathML-формулой, библиографией и ссылкой. Вложенные конструкции и свободная вёрстка не заявляются; сложные объекты идут через модельный экспорт с его ограничениями.

В истории доступны отмена выбранных активных файлов и ZIP выбранных готовых результатов. Проверены состав архива/manifest, неверная выборка, сохранность остальных задач и гонка завершения с отменой. Готовый результат не теряется при смене состояния. Предпросмотр генератора показывает заполненный документ и выдаёт именно этот файл; изменение формы делает просмотр устаревшим. На странице подготовки PDF фрагмент выбирается на изображении мышью или клавиатурой. В конструкторе сценариев можно загрузить входной файл и скачать созданные файлы; результаты размещаются в рабочей папке и выдаются по ID с ограниченным сроком хранения.

По замечанию пользователя предпросмотр разрешён и с незаполненными обязательными полями. Он явно помечен как черновик, показывает недостающие поля и видимые подстановки вместо текста; пустые коллекции и выключенные флажки не подменяются выдуманными данными. Скачать такой результат можно как «Черновик». Ошибки типов остаются ошибками; обычная генерация сохраняет исходную схему проверки.

Проверка: Ruff без замечаний; полный прогон **1903 passed** на Windows/Python 3.14; после смягчения предпросмотра повторно прошли **148** связанных Web/API/браузерных проверок и **165** архитектурных проверок. Новые браузерные проверки охватывают четыре законченных пути при 375/1280 px: образец → поле → предпросмотр → DOCX; TXT → конвейер → DOCX; выборочный ZIP/отмена; выбор PDF-фрагмента и сохранение классификации. Содержимое скачанных документов проверено. Общий прогон включает прежние проверки всех экранов, мобильной компоновки и выбранных ошибок; axe не является полной сертификацией WCAG. Навигаторы перегенерированы, строгая проверка документации пройдена. При завершении pytest Windows по-прежнему сообщает отказ очистки временного указателя `pytest-current`; тесты и код завершения успешны. Приёмка пользовательских документов остаётся отдельной M8.

## 2026-09-28 — заполнение списков без ручного JSON

В генераторе текстовые списки представлены отдельными строками с добавлением, удалением и перемещением вверх/вниз. Многострочный текст, порядок и повторы сохраняются. Переключение на JSON, восстановление черновика и загрузка именованного набора синхронизируют видимые строки. Сложные типы, незавершённый JSON и списки длиннее 200 элементов остаются в текстовом режиме без преобразования данных. Обновлены подсказки и руководство; формы для списков объектов пока не реализованы.

Прошли 18 браузерных сценариев генератора и 174 проверки архитектуры Web, наборов и повторов шаблона. Проверки на 375/1280 px доходят до скачивания и чтения DOCX, включают сохранность данных, отсутствие горизонтального переполнения и серьёзных/критических нарушений axe в проверенном состоянии. Обнаружены и исправлены отсутствующие доступные названия кнопок задач и языка на узком экране. Это не полная проверка WCAG. Pytest завершает проверки успешно, но при очистке временного указателя `pytest-current` Windows сообщает `WinError 5`; на результаты сценариев это не влияет.

## 2026-09-28 — связи сценария и подготовка PDF как часть конвертации

По просьбе пользователя создание шаблонов из документов-образцов перенесено на поздний этап; текущий приоритет — M4.6. Убрано название «Редактор PDF» и отдельный пункт меню: существующая возможность готовит структуру создаваемого DOCX, не редактирует исходный PDF. После выбора PDF на странице конвертации действие открывает подготовку с уже выбранным файлом. Для других форматов и пакетного режима действие скрыто; старая ссылка `/pdf-order` сохраняется для черновиков.

Конструктор предлагает только уже доступные источники, назначает уникальные имена новым результатам и сохраняет нарушенные связи с пояснением. Валидатор больше не принимает ссылку шага на собственный ещё не созданный результат. Вывод запуска показывает фактический `result.ok`, ход выполнения и итоговое значение, а JSON скрыт в подробностях. Это устраняет ложное сообщение об успехе при ошибке операции; результат виден и в текстовом режиме. Возврат в конструктор переносит изменения текста. Браузерные проверки покрывают успешный/неуспешный запуск, смену режимов, связи и передачу PDF на 375/1280 px. Прошли 286 проверок Web/архитектуры/сценариев и отдельный прогон 10 проверок конструктора, навигации и подготовки PDF.

## 2026-09-28 — пользовательские режимы редактора

Генератор начинает с выбора шаблона и данных. Заполнение и правка основы разделены; наборы и удаление черновика находятся в раскрываемой панели, статус автосохранения остаётся видимым. Редактор раскрывает одно действие за раз, сохранение копии возвращает к заполнению без ожидания предпросмотра. Основной текст и аннотация стали многострочными; заголовок и автор идут первыми. На узком экране исходный шаблон показывается после формы, при недоступном просмотре есть пояснение.

PDF-редактор вынесен в основное меню: свойства текста и границы таблицы появляются по выбранному объекту, исходная страница остаётся рядом; для скачивания по умолчанию выбран DOCX. Каталог конструктора сохраняет все операции, группирует их по назначению и ищет по русским и техническим названиям. Добавление действия ведёт к выбору, а не создаёт произвольную операцию. Текстовый режим сохраняет исходные ID. Версия статических ресурсов учитывает обновление файлов при запуске Web, чтобы браузер не продолжал показывать прежнее оформление.

Прошёл полный набор из 83 браузерных проверок и отдельный прогон 280 проверок Web/архитектуры/новых переходов; Ruff и строгая проверка документации прошли. Проверены переходы клавиатурой, сохранность многострочного ввода при переключении и перезагрузке, возврат из редактора, поиск и перенос сценария между режимами на 375/1280 px. Проверки доступности не являются полной приёмкой WCAG. Направление M4.4 уточнено пользователем: превращать существующий документ-образец в шаблон с конкретными заменяемыми значениями, а не требовать подготовленную техническую схему. Для предметной приёмки нужен первый образец.

## 2026-09-28 — строка таблицы и аудит живого Web

Добавлен редактор повторяемой строки простой таблицы: одна переменная получает значения списка, остальные ячейки повторяются вместе с ней. Проверены пустой список, порядок и повторы, жирное начертание разбитой на runs переменной, заголовок/итоговая строка, сохранность исходника, повторная настройка и отказ при устаревшей ревизии. Объединённые ячейки и совместное редактирование разных управляющих конструкций не приняты. Обновлены руководство и API-контракт.

Прошли 302 проверки Web/API/архитектуры и 15 выбранных сценариев генератора в Chromium, включая 375/1280 px. Первый прогон мобильной строки не дождался списка за 5 секунд; диагностика теперь отдельно проверяет HTTP-ответ. Синхронный предпросмотр в async-обработчиках мог задерживать другие запросы: оба обработчика перенесены в рабочий поток. После исправления прошли 4 проверки строки и отзывчивости HTTP-сервера при искусственно задержанном предпросмотре. Это не измерение производительности всего приложения.

На обычном Web отдельно просмотрены генератор, распознавание, вход в PDF-редактор, каталог конвертации и конструктор. Новые редакторы присутствуют, каталог конвертации и 27 операций доступны. Обнаружены разрывы: нет загрузки своего шаблона; предпросмотр не заполнен данными; редакторы нельзя свободно сочетать; наборы данных показаны до выбора шаблона; ссылка PDF скрывает дополнительные возможности за названием про порядок; конструктор использует технические имена. Исправлена общая надпись об очистке всех файлов через час: постоянные наборы и шаблоны выделены отдельно. Остальные пробелы включены в существующие M4.4/M4.6 без новой параллельной очереди. Следующий приоритет — собственный шаблон в Web. Обработка пользовательского корпуса и все состояния остальных экранов этим обзором не проверены.

## 2026-09-28 — M4.4: повторяемый абзац по списку

Генератор позволяет выбрать простой основной абзац, переменную для очередного значения и поле-список. Сохраняются отдельная DOCX-копия и схема с array-полем. Пустой список убирает абзац, остальные списки сохраняют порядок и повторы. Повторная правка меняет источник списка без вложения нового цикла. Проверка отпечатка DOCX/схемы отклоняет устаревшую правку; неподходящие поля и управляющие конструкции отклоняются до публикации. Прежние поля схемы сохранены для остальных вхождений.

Прошли 200 выбранных проверок генератора, API, архитектуры и Chromium. Новый API-сценарий проверяет пустой/одиночный/повторяющийся список, оформление, соседние абзацы, повторную правку и сохранность исходника. Chromium 375/1280 px проверяет копию → перезагрузку → пустой и непустой DOCX → восстановление настройки. M4.4 остаётся открытым; следующий отдельный сценарий — строка таблицы. Циклы таблиц и вложенные конструкции этим срезом не приняты.

## 2026-09-27 — M4.2: переход от предупреждения к PDF-блоку

Неизвестные адреса остаются без кнопки; отчёт относится к версии модели и скрывается после локальных изменений.

Настоящий двухстраничный PDF с векторным прямоугольником воспроизводит предупреждение о замене рисунка текстовой подписью в DOCX. API проверяет правильную страницу/ID, устойчивость после перестановки, отсутствие мутации черновика, устаревшую версию и неверные адреса. Chromium при 375/1280 px проверяет переход с клавиатуры, рамку, восстановление ссылки и обновление отчёта после правки. Всего прошли девять выбранных браузерных сценариев, включая прежнюю HTML-навигацию, классификацию и таблицы. Ограниченный объём M4.2 закрыт; следующий срез — черновик генератора M4.3.

## 2026-09-27 — M4.2: классификация текстовых PDF-блоков
