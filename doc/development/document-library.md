# Библиотеки и границы приложения

TextAlchemy использует официальные OpenDoc **0.1.0** и OpenDoc Formats **0.3.0** как неизменяемые зависимости. Wheel, URL выпуска, commit и SHA-256 закреплены в `vendor/`, `provenance.json`, `uv.lock` и [контракте потребителя](../../contracts/libraries.json). Установка не требует соседних checkout и не пересобирает библиотеки.

## Граница ответственности

| Владелец | Реализация | TextAlchemy обращается через |
|---|---|---|
| OpenDoc | Структуры, свойства, единицы, цвета, ресурсы, формулы, JSON, валидация, инвентаризация и сравнение | Публичные модели и API; [документация](https://SergeiLitvinov.github.io/opendoc/) |
| OpenDoc Formats | Чтение/запись форматов, LaTeX, файловая инспекция, изображения страниц PDF, снимки/транзакционные правки DOCX, офисный PDF | Реестр форматов и публичный native API; [документация](https://SergeiLitvinov.github.io/opendoc-formats/) |
| TextAlchemy | Маршруты и стадии, задания и отмена, OCR, шаблоны, библиография, политики/отчёты, CLI/Web, публикация результата | Прикладные сервисы, операции и команды |

**93 совместимых пути импорта** остаются фасадами установленного пакета: не копируют обработчики и возвращают те же библиотечные определения. Список заморожен в контракте. **Прямых обходов движков и нативных мостов в приложении нет.** Проверка запрещает статические/динамические импорты движков, приватный native API, XML/OOXML-реализацию и вторую модель документа.

В шаблонизаторе приложение отвечает за маркеры, schema, условия, повторения, выбор областей и ревизии. Библиотека получает универсальные правки документа и выполняет их транзакционно. Web-кеш изображений принадлежит приложению; извлечение/отрисовка страниц — адаптеру. JSON с прежним `textalchemy.document` читается прикладным миграционным слоем; новые документы используют `opendoc.document` версии 2. Версия схемы данных не равна версии пакета.

## Проверить установленную границу

```powershell
uv run python -m tools.check_library_contracts
uv run pytest tests/test_library_contracts.py tests/test_document_library_integration.py tests/test_format_library_integration.py
```

Проверка сравнивает wheel и установленные файлы с provenance, проверяет публичные API и исходники приложения. Подмена wheel с прежней версией или импорт из соседнего checkout отклоняются. CI отдельно устанавливает два wheel без TextAlchemy и тяжёлых движков. Тесты реализации/покрытие библиотек принадлежат их проектам; здесь проверяются контракт потребителя и прикладные сценарии.

## Обновить библиотеку

1. Передайте владельцу воспроизводимый случай: версии, сценарий, разрешённый пример, ожидаемые данные, диагностику, лимиты, отмену и критерии совместимости.
2. Библиотека согласует контракт и публикует выпуск в своей сессии. В приложении не создаётся временный парсер или копия модели.
3. Подключите официальный wheel инструментом `tools.update_document_core` либо `tools.update_format_adapters` с точной версией, URL, release ref и SHA-256. Параметры доступны через `--help`.
4. Проверьте lockfile, provenance, установленные файлы и интеграционные тесты. Обновите руководство и встроенную справку.

Контракты и очереди развития остаются у владельцев: [OpenDoc](library-requests/opendoc.md), [OpenDoc Formats](library-requests/opendoc-formats.md). `TODO.md` приложения содержит только интеграцию опубликованных API и пользовательскую приёмку.

## Самостоятельная библиотека адаптеров форматов

Другому приложению достаточно установить OpenDoc Formats с нужными extras и OpenDoc. CLI/Web, база, пользовательские каталоги и политики TextAlchemy не нужны. При поставке исходников приложения оба wheel включены в sdist; при распространении app wheel предоставляйте wheel зависимостей рядом, пока они не опубликованы в реестре. [Комплект OpenDoc](vendor-opendoc.md), [комплект адаптеров](vendor-opendoc-formats.md).
