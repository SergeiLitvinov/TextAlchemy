# Библиотеки и границы приложения

TextAlchemy использует официальные OpenDoc Model **0.7.2** и OpenDoc Formats **0.19.1** как неизменяемые зависимости. Wheel, URL выпуска, commit и SHA-256 закреплены в `vendor/`, `provenance.json`, `uv.lock` и [контракте потребителя](../../contracts/libraries.json). Установка не требует соседних checkout и не пересобирает библиотеки.

## Граница ответственности

| Владелец | Реализация | TextAlchemy обращается через |
|---|---|---|
| OpenDoc Model | Структуры, свойства, единицы, цвета, ресурсы, формулы, JSON, валидация, инвентаризация и сравнение | Публичные модели и API; [документация](https://SergeiLitvinov.github.io/opendoc-model/) |
| OpenDoc Formats | Чтение/запись форматов, LaTeX, файловая инспекция, изображения страниц PDF, снимки/транзакционные правки DOCX, офисный PDF | Реестр форматов и публичный native API; [документация](https://SergeiLitvinov.github.io/opendoc-formats/) |
| TextAlchemy | Маршруты и стадии, задания и отмена, OCR, шаблоны, библиография, политики/отчёты, CLI/Web, публикация результата | Прикладные сервисы, операции и команды |

**93 совместимых пути импорта** остаются фасадами установленного пакета: не копируют обработчики и возвращают те же библиотечные определения. Список заморожен в контракте. **Прямых обходов движков и нативных мостов в приложении нет.** Проверка запрещает статические/динамические импорты движков, приватный native API, XML/OOXML-реализацию и вторую модель документа.

В шаблонизаторе приложение отвечает за маркеры, schema, условия, повторения, выбор областей и ревизии. Библиотека получает универсальные правки документа и выполняет их транзакционно. Web-кеш изображений принадлежит приложению; извлечение/отрисовка страниц — адаптеру. JSON с прежним `textalchemy.document` читается прикладным миграционным слоем; новые документы используют `opendoc.document` версии 2. Версия схемы данных не равна версии пакета.

## Проверить установленную границу

```powershell
uv run python -m tools.check_library_contracts
uv run pytest tests/test_library_contracts.py tests/test_document_library_integration.py tests/test_format_library_integration.py
```

Проверка сравнивает wheel и установленные файлы с provenance, проверяет публичные API и исходники приложения. Подмена wheel с прежней версией или импорт из соседнего checkout отклоняются. CI отдельно устанавливает два wheel без TextAlchemy и тяжёлых движков. Тесты реализации/покрытие библиотек принадлежат их проектам; здесь проверяются контракт потребителя и прикладные сценарии.

## Обновить библиотеку

### Переименование OpenDoc Model

Библиотека модели называется [OpenDoc Model](https://github.com/SergeiLitvinov/opendoc-model): дистрибутив `opendoc-model`, пространство импортов `opendoc_model`. Её официальный выпуск 0.7.2 подключён вместе с OpenDoc Formats 0.19.1, который требует ровно эту модель. Другой выпуск Model не подставляется вопреки точной зависимости адаптеров. Прежнего пакета `opendoc` в зависимостях и поставке приложения нет. Проверка границ отклоняет его статические и динамические импорты, чтобы не смешивать типы.

Инструменты подключения, provenance, lockfile, CI и фасады согласованы с новым именем. Формат JSON остаётся `opendoc.document` версии 2; поддерживаются прежняя версия 1 и прикладной идентификатор `textalchemy.document`. Переименование Python-пакета не переименовывает схему сохранённых документов.

1. Передайте владельцу воспроизводимый случай: версии, сценарий, разрешённый пример, ожидаемые данные, диагностику, лимиты, отмену и критерии совместимости.
2. Библиотека согласует контракт и публикует выпуск в своей сессии. В приложении не создаётся временный парсер или копия модели.
3. Подключите официальный wheel инструментом `tools.update_document_core` либо `tools.update_format_adapters` с точной версией, URL, release ref и SHA-256. Параметры доступны через `--help`.
4. Проверьте lockfile, provenance, установленные файлы и интеграционные тесты. Обновите руководство и встроенную справку.

Контракты и очереди развития остаются у владельцев: [OpenDoc Model](library-requests/opendoc.md), [OpenDoc Formats](library-requests/opendoc-formats.md). `TODO.md` приложения содержит только интеграцию опубликованных API и пользовательскую приёмку.

## Самостоятельная библиотека адаптеров форматов

Другому приложению достаточно установить OpenDoc Formats с нужными extras; совместимый OpenDoc Model устанавливается как его зависимость. CLI/Web, база, пользовательские каталоги и политики TextAlchemy не нужны. При поставке исходников приложения оба wheel включены в sdist; при распространении app wheel предоставляйте wheel зависимостей рядом, пока они не опубликованы в реестре. [Комплект OpenDoc](vendor-opendoc.md), [комплект адаптеров](vendor-opendoc-formats.md).

## Процессы при запуске Web

Web выполняет задания вне своего event loop. При старте ASGI lifespan приложение выбирает стандартный `multiprocessing`-контекст `spawn`, если контекст ещё не выбран или был `fork`; уже выбранные `spawn`/`forkserver` сохраняются. Импорт пакета сам по себе не меняет контекст.

Это политика запуска приложения: нативные процессы опубликованного адаптера получают отдельное окружение и не наследуют потоки сервера и открытые соединения, в том числе каналы браузерного драйвера при E2E. Чтение, запись и внутреннее выполнение конвертера остаются в неизменённом OpenDoc Formats. Нативные параметры и приватные объекты движков в приложении не подменяются.

При встраивании Web учитывайте выбор контекста на старте lifespan; собственные точки входа должны соблюдать стандартную защиту `if __name__ == "__main__"` для запуска дочерних процессов. CLI-сценарий без Web эту настройку не применяет. Пакетная PDF-конвертация проверяется существующим реальным browser E2E с опубликованными wheel, без замены конвертера тестовым обработчиком.
