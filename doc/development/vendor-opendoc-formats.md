# Зависимость OpenDoc Formats

Неизменённый wheel [официального выпуска v0.17.0](https://github.com/SergeiLitvinov/opendoc-formats/releases/tag/v0.17.0).
Обработчики, экспортёры, LaTeX, OOXML/шрифты, PDF-растры, офисный предпросмотр, нативные правки DOCX и ресурсы CSS/JS/Lua принадлежат библиотеке.
В приложении только совместимые импорты и управление маршрутами. Соседний checkout не нужен.
Содержимое закреплено хешами provenance.json и lockfile; установленный код и CSS/JS/Lua проверяются
`uv run python -m tools.check_library_contracts`. Обновление — через `tools.update_format_adapters`
с опубликованным SHA-256, URL выпуска и commit. Пересборка библиотек в сессии приложения запрещена.
Не редактируйте установленную библиотеку вручную.

В v0.15.2 доступны отдельные профили `pdf-rich` (PyMuPDF), `pdf-layout` (pdfplumber), `pdf-docx` (pdf2docx). TextAlchemy пока использует совместимый полный `pdf`, сохраняя существующие маршруты. Профиль `epub` читает контейнер средствами библиотеки и Beautiful Soup, без EbookLib и lxml; необязательный `epub-ebooklib` приложение не подключает. OpenDoc Model остаётся v0.3.0.

Выпуски 0.9.x добавили ограниченную обработку PDF-аннотаций/полей и регистрацию потерь HTML с инертным снимком исходника. В 0.10.0 доступны EPUB-таблицы, вложенные таблицы, объединения ячеек и MathML. Приложение проверяет эти возможности через опубликованные API. Сохранение всей семантики HTML, сложных PDF-объектов и заголовков DOCX этим обновлением не объявляется принятым.

В библиотеке 0.14.0 опубликован ограниченный EPUB-экспорт; TextAlchemy пока предоставляет EPUB как входной формат. Наличие writer в зависимости не означает, что он подключён к CLI/Web. Приёмка новых маршрутов выполняется отдельно. Исторические нативные проверки Word/PowerPoint на 0.10.0 не считаются проверками 0.14.0.

В 0.15.1 текстовый DjVu-адаптер задаёт декодирование независимо от локали процесса и отклоняет пустой слой. TextAlchemy снял требование UTF-8 окружения после приёмки на Windows cp1251; требуется только внешний `djvutxt`. [Свидетельства](../guide/verification.md#djvu-0151-в-windows-cp1251). LaTeX reader из 0.15.0 ещё не включён в маршруты приложения.

В 0.15.2 подключены исправления процентных ширин DOCX и сохранение текста/оболочки smartTag. Непрозрачность smartTag сообщается как LOSS; строгий бюджет 0 отклоняет импорт. Собственная нативная Word-приёмка и пользовательские Web/Word-циклы описаны в [руководстве](../guide/verification.md#кандидат-docx-0152-word-ширины-и-smarttag).
