# TextAlchemy — оставшиеся работы

Актуализировано 2026-10-09. Это единственный активный план приложения: только
незавершённые результаты. Возможности, выполненные проверки и ограничения находятся
в [руководстве](../guide/index.md) и [матрице приёмки](../guide/verification.md).
Стабильные ID сохраняются; номера не задают порядок выполнения.

Подключены неизменённые официальные OpenDoc Model 0.7.2 / OpenDoc Formats 0.17.0.
[Контракты и TODO библиотек](document-library.md) принадлежат их отдельным проектам.
Здесь планируются интерфейс, сценарии, политики и приёмка опубликованных API.
Библиотечные обработчики и новые структуры в приложении не реализуются.

| Веха | Оставшийся результат | Условие начала |
|---|---|---|
| [M6](#m6) | Структурированная связь заменённых объектов | Опубликованный API provenance |
| [M5](#m5) | Приёмка выбранных сложных объектов на собственных примерах | Готовый API или доступный экранный диктор |
| [M8](#m8) | Приёмка пользовательского корпуса в целевых программах | Корпус уже доступен; выбранный маршрут прошёл M5 |
| [M9](#m9) | Подтверждённые условия поставки дополнительных компонентов | Первичные источники разрешений |

<a id="m6"></a>
## M6. Свидетельства качества

- [ ] **M6.3 (Q3):** после публикации [структурированной карты provenance/fallback](library-requests/opendoc-formats.md) интегрировать связь исходного объекта, его замены и объекта результата в отчёт TextAlchemy; принять объяснение и повтор выбранного маршрута. Связь поступает из публичного API, не восстанавливается из текста сообщения. Растр не объявляется редактируемым вектором.

<a id="m5"></a>
## M5. Сложные форматы: собственные примеры

- [ ] **M5.1 DOCX (D1):** на опубликованных API принять выбранные comments/SmartArt/OLE/защиту: два цикла на собственном примере, явная область сохранения и диагностика упрощений, строгий отказ с сохранением прежнего результата. Непрозрачное сохранение не считается семантическим редактированием. [Граница и передача запросов](library-requests/opendoc-formats.md).
- [ ] **M5.2 PDF (D2/D3):** принять порядок сложных блоков/наложений, выбранное нативное восстановление интерактивности и слои/маски; после опубликованных исправлений повторить [маленькую страницу](library-requests/pdf-interactions-export.md). Проверить содержимое/геометрию результата, два цикла, точность расположенных диагностик и отказ без замены прежнего файла. [Владелец реализации](library-requests/opendoc-formats.md).
- [ ] **M5.4 HTML (H1):** принять выбранный маршрут в реальном экранном дикторе: язык, имя таблицы, связи заголовков ячеек и переходы по внутренним ссылкам. Зафиксировать программу/версию и исходный/выходной файлы; DOM/ARIA и автоматический аудит не заменяют эту проверку. При новых дефектах CSS/paged media/семантики экспортёра передать воспроизводимый запрос владельцу Formats и принять опубликованный результат. [Контракт и проверенная область](library-requests/html-accessibility.md).

**Выход M5:** объявлены объект и маршрут; собственный fixture проверяет заявленные
свойства и диагностику через публичные API. Реализацию исправляет библиотека.
Приёмка пользовательских исходников и их оформления выполняется отдельно в M8.

<a id="m8"></a>
## M8. Пользовательский корпус

- [ ] **M8.2:** принять просмотр расширенного PDF-корпуса в Chromium PDF viewer: реальные исходник и результат, все выбранные страницы и мелкие подписи. Геометрические/пиксельные измерения сами по себе не закрывают просмотр в целевой программе.
- [ ] **M8.3:** после опубликованных исправлений и проверки выбранного маршрута в M5 повторить оставшиеся пользовательские DOCX/PDF/PPTX случаи. Для DOCX сверить текст, страницы, таблицы и заявленные сложные свойства; для сложного PPTX — исходное оформление всех 35 слайдов в PowerPoint, а не только стабильность уже упрощённого второго цикла. Сохранить два цикла с выбранной нативной правкой, диагностику, хеши и отдельные структурные/визуальные наблюдения; обновить матрицу и ограничения в руководстве. Просмотр PDF viewer учитывается в M8.2 и не принимается повторно здесь.

**Корпус доступен:** `C:/project/Учебные материалы` разрешён только для чтения.
Рабочие копии/результаты остаются в отдельном локальном каталоге TextAlchemy.
Приватные тексты, имена файлов, схемы и изображения не публикуются. Неизмеренное
остаётся неизвестным; успешное открытие не доказывает сохранность оформления.

## M9. Лицензии дополнительных компонентов

- [ ] **M9.1:** подтвердить условия распространения выбранных OCR-весов `craft_mlt_25k.pth` и `cyrillic_g2.pth`: первичный источник разрешения и текст условий именно для поставляемых файлов, актуальный реестр/проверка профиля и проверенный OCR-сценарий. - [ ] **M9.2:** после закрытия [OF16 у владельца Formats](https://sergeilitvinov.github.io/opendoc-formats/development/todo/) принять подтверждённую поставку lxml для `docx`/`pptx`/`pdf`: точные версии, первичные источники разрешений, реестр потребителя, проверки соответствующих профилей и интеграции. До этого комплекты этих зависимостей не выпускаются. XSL не удаляется из установленного пакета, библиотека здесь не пересобирается. [Основания аудита](licenses.md).

## Как поддерживать план

- Выбирать ближайший доступный срез с конечным сценарием и проверяемой приёмкой.
- Библиотечный пробел передавать отдельным контрактом владельцу; интеграция ждёт опубликованного выпуска. Машиночитаемый контракт потребителя не разрешает обход движков.
- Принимать M5 на собственных примерах, M8 на пользовательском корпусе; не дублировать одну проверку в двух вехах.
- После приёмки переносить результат в руководство/матрицу и удалять завершённый пункт. В частично выполненном пункте оставлять только остаток.
- Активен один план: проверка документации запрещает закрытые отметки и повторяющиеся ID. Прежние планы остаются в истории Git.
