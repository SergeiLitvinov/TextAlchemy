# TextAlchemy — оставшиеся работы

Актуализировано 2026-10-04. Это единственный активный план приложения: только незавершённые результаты. Доступные возможности и ограничения описаны в [руководстве](../guide/index.md) и [матрице проверок](../guide/verification.md). Стабильные ID сохраняются для ссылок; порядок номеров не задаёт порядок выполнения.

OpenDoc v0.1.0 и OpenDoc Formats v0.3.0 подключаются как отдельные зависимости. Здесь только работа TextAlchemy: интерфейс, сценарии, политики, отчёты и приёмка готовых API. Контракты и TODO библиотек ведутся в их собственных проектах: [OpenDoc](library-requests/opendoc.md), [OpenDoc Formats](library-requests/opendoc-formats.md). Прежние OF-01–OF-05 переданы владельцу адаптеров; здесь нет копии его плана. Изменение библиотек выполняет их сессия; приложение подключает проверенный выпуск. Прямые обходы движков запрещены. [Контракт границ](document-library.md).

<a id="m7"></a>
## M7. Архитектура приложения

- [ ] **M7.2 (A2):** подключить независимую проверку записанного PDF из OpenDoc Formats к стадии verify до публикации; адаптировать выполнение маршрута по подтверждённому дефекту. Приёмка: каждая стадия выполняет работу и выдаёт проверяемый результат; ошибка проверки PDF сохраняет прежний файл.

**Граница:** оставшаяся M7.2 отвечает за внутреннее выполнение конвертации. Прикладные сценарии описаны в руководстве. OpenDoc Formats развивается как общий набор обработчиков; стадиями маршрутов, задачами и публикацией результата владеет TextAlchemy. Отдельного проекта для каждого модуля план не требует.

<a id="m6"></a>
## M6. Свидетельства качества

- [ ] **M6.1 (Q1):** калибровать прогноз на выбранном корпусе, связывать визуальные измерения и реальные проверки редактирования с отчётом. Указывать происхождение и область проверки; отсутствие измерений оставлять `null`. Приёмка: пользователь отличает прогноз от измеренного результата и проверки в целевой программе.
- [ ] **M6.2 (Q2):** добавить числовые бюджеты ещё не покрытых свойств оформления и объектов на выбранном маршруте. Каждый бюджет требует воспроизводимого случая потери. Приёмка: строгий лимит отклоняет публикацию результата и сохраняет прежний файл.
- [ ] **M6.3 (Q3):** показывать диагностику и связь исходного объекта с fallback, предоставленные готовым API адаптеров. Проверить отчёт и повторный пользовательский маршрут; растр не объявлять редактируемым объектом. Недостающие данные/их сохранение — запрос OF-04.
- [ ] **M6.4 (Q4):** объяснять ограничения цвета и применять пользовательский бюджет потерь на данных готовой библиотеки. Приёмка: предупреждение понятно, строгая политика сохраняет прежний файл. Передача ICC/output intent/CMYK/blend — запрос OF-05.

**Граница:** M6.1 измеряет и объясняет, M6.2 ограничивает потери, M6.3 показывает замену объекта, M6.4 применяет политику цвета. Реализация чтения, записи и сохранения свойств принадлежит библиотекам.

<a id="m5"></a>
## M5. Сложные форматы

- [ ] **M5.1 DOCX (D1):** принять пользовательский маршрут на опубликованной библиотеке: открытие, предупреждения, правка и два цикла в Word. Неподдержанные comments/SmartArt/OLE/защита — OF-03; непрозрачное сохранение не называется редактированием.
- [ ] **M5.2 PDF (D2/D3):** интегрировать и принять чтение/порядок блоков и объяснимый fallback готовых API. Недостающие annotations/forms/layers, маски, формулы или векторы — воспроизводимый OF-03; парсер в приложении не создаётся.
- [ ] **M5.3 PPTX (P1/P2):** проверить выбранные диаграммы, геометрию и объекты через пользовательский маршрут и правку в Office; показывать ограничения готовой библиотеки. Недостающие темы/master/layout, анимации, медиа и объекты — OF-03.
- [ ] **M5.4 HTML (H1):** принять готовый экспорт в браузере и вспомогательных технологиях, улучшить отображение диагностик. Недостающие CSS/paged media/семантика экспортёра — OF-03.
- [ ] **M5.5 DjVu (F1):** интегрировать возможности опубликованного адаптера и показывать ограничения текстового извлечения. Страницы и координаты требуют OF-03 до интеграции.
- [ ] **M5.6 XLSX/ODS (F2):** исследовать конкретные примеры и принять документированное решение о табличном представлении, отсрочке либо отказе. Это исследование, а не обещание поддержки Excel.

**Граница реализации:** обработчики форматов принадлежат OpenDoc Formats. TextAlchemy интегрирует выбранную возможность и проверяет пользовательский маршрут; новых парсеров/экспортёров в приложении не создаётся.

**Выход каждого среза:** объявлены объект, маршрут и корпус; сохраняются нужные данные и поведение, потери видны пользователю. «Поддержать полный формат» не является критерием завершения. Новые общие структуры согласуются с владельцем OpenDoc, а не реализуются второй моделью в приложении.

## M8. Приёмка на документах пользователя

- [ ] **M8.1:** согласовать корпус: происхождение, форматы, особенности, ожидаемый результат и правила обезличивания. Выбрать маршруты и критерии приёмки.
- [ ] **M8.2:** выполнить маршруты, сохранить отчёты и доступные измерения времени/памяти; проверить реальные изменения и повторное открытие в нужных Word/PowerPoint/LibreOffice/браузере/PDF viewer. Неизмеренное оставить неизвестным.
- [ ] **M8.3:** превратить разрешённые дефекты в воспроизводимые fixtures, исправить и повторить приёмку; опубликовать матрицу проверенных сценариев и принятые ограничения в руководстве.

**Начало:** получены документы и правила использования. Ожидание корпуса не останавливает проверку текущих сценариев и остальные вехи.

## M9. Лицензии дополнительных компонентов

- [ ] **M9.1:** установить лицензию точных выпусков `aistudio-sdk 0.3.8` и `cuda-toolkit 13.0.2` либо выбрать документированную совместимую замену в OCR-окружении. Приёмка: есть первичный источник разрешения и текст условий для поставляемого файла; реестр и проверка профиля обновлены, функциональность выбранного OCR-сценария проверена. До этого комплект зависимостей `ocr` не выпускается. Модель документа и адаптеры форматов не изменяются. [Основания аудита](licenses.md).

## Как поддерживать план

- Активен один ближайший срез; новая работа имеет конкретный сценарий и конечную приёмку.
- Перед изменением определить владельца. Библиотечный пробел получает отдельный контракт; интеграция ожидает опубликованный выпуск. Расширять `contracts/libraries.json` для обхода этого правила нельзя.
- После приёмки обновить руководство и матрицу проверок, затем удалить выполненный пункт отсюда. Если выполнена часть пункта, оставить только остаток.
- Проверка документации запрещает закрытые отметки, повторяющиеся ID и задачи вне своей вехи.
- Завершённые пункты удаляются; доступный функционал и ограничения описываются в руководстве. Прежние планы остаются только в истории Git.
