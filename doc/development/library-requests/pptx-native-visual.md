# PPTX: нативное визуальное свидетельство сложного маршрута

Владелец импорта/экспорта — OpenDoc Formats. Проверено 2026-10-08 на официальном 0.10.0, OpenDoc Model 0.3.0, TextAlchemy 0.2.0rc2 и Microsoft PowerPoint 16.0 build 17932. Библиотеки не изменяются в приложении.

## Вызывающий сценарий и свидетельство

`pptx-complex-01`: 35 слайдов с таблицами, группами, изображениями и элементами шаблона. Два реальных Web-цикла PPTX → модель → PPTX; между ними отдельная правка в PowerPoint. Исходник разрешён только для локального чтения: имя, текст, схемы и снимки не публикуются. Полный отчёт и хеши находятся в игнорируемой приёмке; доступен отдельной библиотечной сессии локально при разрешении пользователя. Это пользовательское свидетельство, не опубликованный минимальный fixture.

Через PowerPoint Slide.Export созданы PNG 1280×960 всех слайдов исходника, первого результата, его отредактированной копии и второго результата. Все четыре входа остались неизменными. Сравнение проверяет программу/версию, SHA-256 каждого PNG, порядок, число и размеры всех слайдов.

Первый цикл: изменены 34 из 35 PNG, максимальный MAE 0.108903 на шкале 0–1. Просмотр всех слайдов подтверждает изменение фона/элементов шаблона, пропажу участков линий и изменение оформления текста/таблиц. Зарегистрированы `pptx.package`, `pptx.group`, `pptx.shape` и `styles`; нулевой бюджет уже отклоняет результат. Соответствие каждой видимой потери конкретному объекту отчёта не доказано и не извлекается из строки сообщения.

Второй цикл: все 35 PNG совпадают побайтно по RGB с отредактированной копией первого результата. Это стабильность уже упрощённого входа; она не восстанавливает исходное оформление, группы или редактируемость всех объектов. Координатные float-различия в COM-инвентаре могут существовать при совпадении рендера.

## Собственные минимальные воспроизведения

`tests/corpus/pptx_acceptance.py::write_visual_presentation` создаёт шесть однослайдовых случаев
через независимый python-pptx; пользовательский текст, картинки и пакеты не используются.
`tests/test_pptx_visual_acceptance.py` выполняет реальные PPTX → модель → PPTX циклы через
executor приложения и отдельный opt-in рендер PowerPoint. Свидетельство 2026-10-08:

| Случай | Независимое наблюдение | Диагностика 0.10.0 |
|---|---|---|
| `master-background` | Исходный слайд наследует сплошной фон мастера `184860`; после экспорта заливка мастера отсутствует. Первый PNG отличается, MAE 0.748007; второй совпадает с первым результатом | Общий `pptx.package` LOSS; отдельная причина потери фона мастера отсутствует |
| `nested-group` | Две вложенные группы с прямоугольником, овалом и линией остаются двумя группами в обоих результатах; PNG обоих циклов совпадают с исходным | Два `pptx.group` LOSS с сообщением о flattening в каждом цикле, хотя это изменение в данном случае не наблюдается |
| `freeform-axis-lines` | PowerPoint отображает горизонтальный и вертикальный свободные контуры; их bounding extents имеют соответственно нулевую высоту/ширину. После первого цикла обе фигуры отсутствуют, MAE 0.005771; второй результат стабилен | Два расположенных `pptx.shape` LOSS: `Shape with nonpositive extent is skipped` |
| `freeform-line` | Контрольный свободный контур с ненулевыми шириной/высотой сохраняется; оба PNG совпадают | Нет `pptx.shape`; общий LOSS пакета остаётся |
| `table-theme` | Таблица 2×2 с унаследованным стилем: белый текст первой строки становится чёрным; первый PNG отличается, MAE 0.002124; второй стабилен | Экспорт даёт общий `styles` LOSS без точной связи с цветом первой строки |
| `table-style` | Контрольные прямые заливка, Arial 20 pt bold, белый цвет и отступы ячеек сохраняются; оба PNG совпадают | `styles` LOSS остаётся, хотя изменения этих измеренных свойств не наблюдаются |

Это конечные воспроизведения, а не подтверждение всех фонов или групп. Пиксельное совпадение
не доказывает всю редактируемость. Для первого случая требуется сохранение объявленного фона
либо точная расположенная причина его потери; для второго — диагностика фактической потери
или явно обозначенной непроверенной области, без утверждения flattening сохранённой иерархии.
Нулевой бюджет отклоняет экспорт обоих текущих случаев по зарегистрированным LOSS и сохраняет
прежний файл; он не исправляет точность библиотечной диагностики. Все проверенные PPTX остаются
неизменными после read-only рендера в PowerPoint 16.0 build 17932.

Нулевой bounding extent не означает пустой путь: конечные точки прямого свободного контура
могут различаться по другой оси, а толщина линии даёт видимый штрих. Контракт этого среза:
сохранить выбранные горизонтальный/вертикальный контуры и унаследованный цвет заголовка таблицы
либо дать конкретный расположенный LOSS. Растеризация не объявляется сохранением редактируемого
контура. Положительные контрольные примеры не подменяют дефектный вход и не отменяют общих
предупреждений по непроверенным свойствам.

## Область приёмки исправления

Для согласованного конечного среза объявляются поддержанные свойства группы/линии, шаблона/layout и оформления таблицы/текста. Они либо сохраняются по модели и нативному рендеру, либо дают расположенный LOSS с конкретной причиной и ссылкой на объект; неполное сохранение не называется полной поддержкой PPTX. Текущий общий строгий отказ сохраняется. Непрозрачный исходный пакет и совпадение второго упрощённого цикла не заменяют этот контракт.

Приёмка нового опубликованного выпуска: разрешённый локальный пользовательский случай и собственный минимальный fixture без его текста; два цикла с правкой; нативный рендер всех слайдов, отдельная структурная/визуальная проверка, исходные/выходные хеши и отказ с сохранением прежнего результата. Пределы времени/памяти и отмена остаются частью публичного адаптера; новый нативный обработчик в TextAlchemy не создаётся. Реализация и библиотечный TODO ведутся у владельца.

## Повтор осевых линий на опубликованном 0.15.5

Собственный `freeform-axis-lines` сохраняет оба FREEFORM-контура, координаты и размеры в двух публичных циклах. Нативные PNG 1280×960 через PowerPoint Slide.Export совпадают с исходником по всем RGB-пикселям в обоих циклах; исходники неизменны. Принят этот конечный случай, прежняя потеря nonpositive extent закрыта. Оформление пользовательского PPTX из 35 слайдов, фон и наследуемый стиль таблицы этим не приняты. Проверка: `tests/test_pptx_visual_acceptance.py::test_native_visual_two_cycles_on_own_minimal_cases[freeform-axis-lines]`.
