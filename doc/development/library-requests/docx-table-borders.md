# DOCX: прямые границы таблицы

Владелец реализации — OpenDoc Formats. Проверено 2026-10-10 на официальных
Formats 0.19.1 / Model 0.7.2; Word 16.0 build 16.0.17932.
SHA-256 Formats `10923fd95441d0d88d618fd898bcfd00aa838a72528e5f13fe4c9086b01b7695`.
Все переданные примеры собственные, без частных документов, макросов и ссылок.

## Пример и наблюдение

DOCX содержит собственный заголовок и таблицу 3×2 с шестью короткими подписями.
Стиль таблицы — `Normal Table`. В `w:tblPr/w:tblBorders` явно заданы
top/left/bottom/right/insideH/insideV: `val=single`, `sz=8`, `color=000000`.
Создание собственного OOXML допускается только в QA; runtime приложения его
не разбирает и не исправляет.

| Свойство в реальном Word | Исходник | Цикл 1 | Цикл 2 |
|---|---|---|---|
| Открытие | Да | Да | Да |
| Страниц | 1 | 1 | 1 |
| Верхняя граница, `Borders.Item(-1).LineStyle` | 1, single | 0, none | 0, none |
| Внутренняя горизонтальная граница, `Borders.Item(-5).LineStyle` | 1, single | 0, none | 0, none |

Оба DOCX → JSON → DOCX цикла имеют `success=true,lossless=true`. Единственное
замечание — `font-substitution` уровня WARNING без location; оно не описывает
утрату границ. Бюджет 0 заменяет прежний файл. Исходный SHA-256 не меняется.
Контроль с теми же подписями и стилем `Table Grid` сохраняет обе границы в двух
циклах; явно заданный цвет заголовка также сохранён. Общая неспособность
обрабатывать цвета или все стили этим примером не утверждается.

Собственные свидетельства: `.textalchemy/qa/docx-styles0191/`,
`own-direct.docx`, `direct-{0,1}.json/docx`, `direct-evidence.json`,
`word-direct-evidence.json`, `strict-evidence.json` и рендеры Word.
Контроль — `own.docx`, `cycle-{0,1}.docx`, `word-evidence.json`.

## Требуемое поведение

Сохранить прямые внешние/внутренние границы с их областью действия либо дать
расположенную table-border LOSS, либо отказать атомарно. Замечание о шрифте
не покрывает утрату границ. Сохраняются источник, ограничения ресурсов, отмена
и прежний файл при строгом отказе. Сначала проверить существующие публичные
структуры границ Model; отдельный запрос Model нужен лишь при доказанном пробеле
представления. Приложение не переносит обработчик OOXML в свой runtime.

После официального исправления повторить оба цикла относительно исходных
LineStyle/рендера Word, нативную правку отдельной копии и сохранение/открытие.
Частный корпус выявил и другие изменения оформления; они не переносятся в этот
собственный пример и не объявляются исправленными по совпавшим счётчикам.
Его визуальная приёмка остаётся в M8.3.
