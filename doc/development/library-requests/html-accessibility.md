# Контракт приёмки HTML-семантики для OpenDoc Formats

Владелец реализации — OpenDoc Formats; TextAlchemy принимает опубликованный выпуск. Этот документ содержит воспроизводимое свидетельство к запросу OF-03, а не копию плана библиотеки. Код обработчиков и модель документа здесь не изменяются.

## Зафиксированный случай

Проверено 2026-10-07: TextAlchemy 0.2.0rc2, OpenDoc Model 0.3.0, официальный OpenDoc Formats 0.6.0, Chromium 151.0.7922.34. SHA-256 wheel адаптеров: `699a2c555d12033380a712634fad8b39ee6c81f189c14f3b8946690eab7af532`; commit `e701be63309125d4d77186d840dfcce3617a4d8f`. [Происхождение пакета](../vendor-opendoc-formats.md).

Исходник — `tests/corpus/html-accessibility.html`: короткий английский отчёт, два уровня заголовков, нумерованный список с `start=3`, таблица с caption, заголовками строк/столбцов и двумя внутренними ссылками. Документ написан для проверки, не содержит пользовательских данных или внешних ресурсов. Исходник не изменяется. Маршрут: HTML → модель JSON → HTML, затем повтор того же цикла на полученном HTML. Конвертация выполняется через настоящий HTTP API TextAlchemy, который вызывает готовые обработчики библиотеки.

|---|---|---|
| Язык HTML | `en` | `ru` |
| Заголовки документа | h1 и h2 с соответствующими ролями | Сохраняются |

## Воспроизведение и ответственность

`tests/test_web_html_accessibility.py::test_web_html_roundtrip_preserves_language_caption_and_header_roles` выполняет оба цикла на ширинах 375/1280, сохраняет в каталоге теста отчёты, версии, ARIA-снимки и PNG. Зелёный результат этого теста подтверждает воспроизведение известного дефекта; он не означает прохождение семантической приёмки. Соседние проверки покрывают пользовательское пояснение и управление инспектором HTML с клавиатуры.

Независимый библиотечный случай строится тем же исходником через публичные `read_html_model`, сериализацию/десериализацию OpenDoc Model и `write_html_model`. Предлагаемый контракт: сохранить язык, caption и семантические связи заголовков таблиц либо зарегистрировать явные диагностированные потери с местом исходного элемента. Приложение не исправляет HTML после экспорта и не извлекает эти сведения вторым парсером.

Если для caption/заголовков ячеек нужны новые общие структуры, владелец адаптеров согласует контракт с владельцем OpenDoc Model. Нельзя заменять семантику жирным текстом или считать обычную ячейку заголовком по её расположению. Совместимость старых моделей должна сохраняться; отсутствие сведений остаётся неизвестным, а не выдуманным.

## Предлагаемая приёмка опубликованного API

На разрешённом fixture проходят два цикла с `lang=en`, именем таблицы Measurements, двумя `columnheader`, одним `rowheader` и работоспособными якорными ссылками. Неподдержанное свойство даёт диагностику с местом и объяснением; JSON сохраняет её, строгий нулевой бюджет отклоняет результат до публикации и сохраняет прежний файл. Нельзя заявить сохранение доступности только по совпадению текста или числа ячеек.

Для фиксированного и адаптивного HTML должны быть явно объявлены разные гарантии компоновки; текущая фиксированная страница не принимается как адаптивная веб-страница. Приложение подключит готовый режим после публикации API. Проверка библиотечного случая должна учитывать лимиты ресурсов и отмену до публикации; прежние исходник/результат не изменяются при отказе. Реальная проверка экранным диктором проводится отдельно на выбранной программе и версии.

## Повтор на 0.10.0

2026-10-08: официальный wheel 0.10.0 сохраняет диагностический ledger и инертный оригинал для обнаруженных ограничений (например, неподдержанного CSS/script). В данном семантическом случае язык, caption/имя таблицы и роли ячеек результата всё ещё теряются без LOSS; нулевой бюджет не отклоняет результат. Остаток контракта — диагностирование и сохранность этих свойств, затем приёмка экранным диктором. Подробности в [матрице](../../guide/verification.md#приёмка-opendoc-formats-0100).

Повторное чтение HTML, созданного экспортёром, в 0.10.0 регистрирует ограничения его CSS (media/page, flex, размеры и другие свойства). В проверенном втором цикле эти сообщения сохраняются через JSON и нулевой бюджет отклоняет результат; разрешающий запуск позволяет осмотреть потери. Это отдельная область диагностики, а не подтверждение обнаружения потерь языка/caption/ролей первого цикла.
