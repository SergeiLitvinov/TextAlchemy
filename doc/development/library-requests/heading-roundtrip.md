# DOCX: сохранение формальной роли заголовка

Владелец исправления — OpenDoc Formats. TextAlchemy не читает Word XML и не определяет заголовки самостоятельно.

## Воспроизводимость

Проверено 2026-10-08 на официальных OpenDoc Model 0.3.0 и OpenDoc Formats 0.8.2. Wheel адаптеров: SHA-256 `79f34d533833a790bdf98547a96e37a2f78cf46d8cfaf4a92e24bc436e6bce2e`, commit `6a7f38c8154e8fa97044f276748761c52f3f6cf7`. Тот же дефект наблюдался в 0.6.0.

Собственная модель из `tests/convert/test_heading_budget.py::heading_model` содержит два абзаца: `Unique heading` с `set_heading(paragraph, Heading(2))` и `Body`. После JSON → DOCX → публичная инспекция DOCX роль заголовка становится `null`; сравнение модели регистрирует одну изменённую роль.

В варианте с именованным стилем `Heading 2` нативный файл действительно содержит `w:pStyle=Heading2` и `w:outlineLvl=1`. Это проверено ZIP/XML только в тесте. Роль отсутствует именно в повторно прочитанной модели; утверждать, что заголовок отсутствует в Word, нельзя. Базовый экспорт не сообщает о потере. Без именованного стиля также зарегистрирована потеря роли в модели; приёмка в Word не выполнялась.

## Ожидаемый публичный контракт

| Сценарий | Ожидаемое поведение |
|---|---|
| Формальный `Heading(2)` без именованного стиля | Экспорт и повторный импорт сохраняют роль и уровень либо дают конкретную диагностику потери |
| Нативный Heading2 с outlineLvl 1 | Импорт восстанавливает формальную роль уровня 2 через модель |
| Обычный абзац | Не превращается в заголовок по размеру/жирности текста |
| JSON между циклами | Сохраняет роль, диагностику и происхождение |
| Отказ/отмена | Не заменяет предыдущий результат, соблюдает публичные ограничения |

Приёмка: два цикла через опубликованные API, исходная модель неизменна; роль измеряется публичным сравнением без эвристического сопоставления. Открытие и правка в Word остаются отдельной пользовательской проверкой. На прежнем выпуске строгий бюджет приложения корректно блокировал этот непроверенный переход, даже если нативный Word-стиль присутствует.

Контракт подготовлен локально для отдельной сессии библиотеки; реализация и её TODO сюда не перенесены.

## Реальная проверка Word на 0.10.0

2026-10-08: `tests/test_word_acceptance.py` выполняет два Web-цикла на собственном составном DOCX и реальные правки в Word 16.0, build 16.0.17932. Абзац, ячейка, встроенное изображение и жирное выделение сохраняют проверенное поведение. В первом результате заголовок имеет уровень структуры 2; после Word-правки, сохранения и второго цикла он имеет уровень 10 (основной текст). Тест сохраняет отрицательную проверку заголовка отдельно от положительной правки текста/ячейки. Этот факт не распространяется на все DOCX: в пользовательском пилоте один заголовок уровня 3 сохраняется. Исправление роли требует приёмки обоих случаев, не изменения приложения или эвристики по размеру текста.

## Принятый конечный случай 0.16.0

Официальные Formats 0.16.0 и Model 0.6.0 подключены без изменений. Два JSON/DOCX-цикла с Heading(2), с именованным стилем и без него, имеют `changed_headings=0`, подтверждённую проверку и принятый нулевой допуск. Обычный абзац остаётся обычным. Исходная модель неизменна. В собственном составном документе реальные Word-правки и второй Web-цикл теперь также сохраняют уровень 2. Два выбранных пользовательских DOCX сохраняют уровни, текст и измеренные число страниц/таблиц в двух циклах с правками Word; оригиналы неизменны. Полная визуальная приёмка этим не объявляется.

Воспроизводимые положительные проверки — `tests/convert/test_heading_budget.py`, нативный сценарий — `tests/test_word_acceptance.py`. Прежние отрицательные наблюдения выше относятся к указанным старым выпускам; этот контракт закрыт в объявленной области. Другие сложные DOCX-объекты остаются отдельными запросами.
