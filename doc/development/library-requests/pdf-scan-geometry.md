# PDF: геометрия полностраничного скана

Владелец — OpenDoc Formats. Проверено 2026-10-08 на неизменённом официальном 0.10.0, OpenDoc Model 0.3.0 и TextAlchemy 0.2.0rc2. Приложение не исправляет PDF writer и не подменяет модель парсером.

## Воспроизводимый случай

`tests/test_pdf_scan_acceptance.py::scan_pdf` независимо создаёт две страницы 595×842 pt. Каждая содержит собственный PNG с красной рамкой и синей линией на всю страницу; текста, пользовательских материалов и сторонних ресурсов нет. Реальный CLI executor дважды выполняет PDF → модель → PDF. Размер и число страниц сохраняются, но координаты изображения отличаются от исходных, пиксели рендера меняются; LOSS отсутствует. Успех теста подтверждает известный дефект, а не сохранность геометрии.

Пользовательский `scan-pdf-01` независимо подтверждает симптом: две страницы около A4, изображения исходно на всю страницу, после первого экспорта начинают размещаться в (72,72) pt и уменьшаются. Второй цикл сохраняет уже уменьшенную геометрию, но оригинал не восстанавливает. Исходные имена, схемы и снимки остаются только в локальном игнорируемом каталоге. `tools.acceptance.scans` измеряет все страницы, размеры, image boxes и RGB-различие; это QA, не обработчик приложения.

## Ожидаемый публичный контракт

Выбранный PDF-растр сохраняет объявленные страницу, координаты, масштаб и область обрезки при повторном экспорте. Если экспортёр переводит его в потоковую компоновку или не может сохранить геометрию, требуется расположенный LOSS с причиной; нулевой бюджет должен отклонять публикацию. Проверяются два цикла, неизменность оригинала, image boxes и рендер всех страниц. Нативный просмотр и пригодность мелких подписей остаются отдельной приёмкой. OCR здесь не требуется: пустой текстовый слой не означает пустое изображение.

Библиотечное исправление и его TODO реализуются в отдельном проекте и поступают опубликованным выпуском; TextAlchemy выполняет повторную интеграционную приёмку.

## Повтор собственного случая на 0.15.5

Два цикла через опубликованные API сохраняют image boxes, размеры и число страниц, точные RGB-пиксели обеих страниц при независимом рендере. Нулевой бюджет принимает экспорт; оригинал неизменён. Проверка `tests/test_pdf_scan_acceptance.py::test_full_page_scan_two_cycles_preserve_geometry_and_pixels` принята. Пользовательский `scan-pdf-01` также принят по геометрии и точным RGB-пикселям всех страниц в двух реальных Web-циклах 0.15.5; оригинал неизменён. Просмотр в целевой программе не перепроверен; прежнее отрицательное свидетельство относится к 0.10.0.

## Отказ произвольного поворота из DOCX на 0.15.5

Собственный `tests/corpus/scientific_report.py::build_scientific_report` содержит обрезанное изображение с поворотом 3° (`rot=180000`). Публичные `read_docx_model` → `write_pdf_model` дают ERROR `pdf-raster-unsupported`, `Only quarter-turn raster rotations are supported`, адрес `sections[0].blocks[17].content[0]`; PDF smoke не доходит до рендера. Отказ воспроизведён и на коротком временном пути Windows. Это ограничение опубликованного writer, а не принятая сохранность корпуса.

Передано владельцу Formats: проверить поддержку произвольного поворота/обрезки и совместимость прежнего маршрута; сохранить геометрию или доказать адресный безопасный отказ без замены прежнего результата. Не отключать ERROR и не вводить нативный обход в приложении. Пользовательские материалы не нужны: fixture полностью собственный. Проверка `tests/quality/test_document_corpus.py::test_scientific_report_pdf_pages_pass_visual_smoke_bounds` остаётся незакрытой до официального исправления.

Повтор на официальном Formats 0.16.1 / Model 0.6.0 даёт ту же ERROR и тот же адрес.
Основной полный прогон приложения: 2088 passed, 26 skipped, один PDF smoke failed;
отдельный повтор публичного writer сохранил полный отчёт и подтвердил неизменность
источника. Исправление ожидается опубликованным выпуском, тест не отключён.

## Приёмка 0.17.0

2026-10-09: официальный Formats 0.17.0 / Model 0.7.2 подключён без изменений. Прежний PDF smoke научного отчёта проходит с исходными критериями; просмотрены все три страницы собственного результата, включая повёрнутое/обрезанное изображение и альбомное приложение. Это проверка smoke, а не доказательство полной точности исходного DOCX.

`tests/test_web_pdf_vectors.py::test_browser_exports_rotated_raster_in_two_cycles` выполняет два настоящих Web-экспорта собственного растра 3° с промежуточным PDF → модель через executor. На ширинах 375/1280 доступно скачивание; независимо измерены угол 3° (допуск 0.00001°), центр (40,50) pt (допуск 0.001 pt) и точное равенство всех RGB-пикселей двух результатов. Источник неизменён. Повреждённый PNG проверяется отдельно: расположенный реальный `pdf-raster-unsupported`, отказ без предложения результата, доступное объяснение. Исторический отказ 0.15.5–0.16.1 выше устранён для этих конечных случаев. Сложные эффекты/обрезка и пользовательский PDF viewer остаются отдельной приёмкой.
