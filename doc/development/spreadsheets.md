# Решение по XLSX/ODS

Принято 2026-10-07 для TextAlchemy 0.2.0rc2, OpenDoc Model 0.3.0 и OpenDoc Formats 0.6.0: **отложить прямую конвертацию расчётных книг**. В текущем каталоге нет публичного маршрута XLSX/ODS. Таблица документа сама по себе не означает поддержку книги с формулами, листами и пересчётом. Новые обработчики в приложение не добавляются.

## Исследованные примеры

Синтетический XLSX создан встроенным инструментом таблиц; пользовательские документы не использовались. Два листа `Summary` и `Data`: значения `Data!B3:B5` равны 1, 2, 3; формула `Summary!B3` — `=SUM('Data'!B3:B5)`. После пересчёта результат 6; изменение `Data!B3` на 10 даёт 15; восстановление 1 возвращает 6. Проверены значения, формула, XML экспортированной книги и изображения обоих листов. Это проверка исследовательского инструмента, а не конвертации TextAlchemy или совместимости с Excel/Calc.

| Пример | Наблюдение / источник | Последствие для документного представления |
|---|---|---|
| Формула между двумя листами XLSX | В XML итоговой ячейки есть и формула, и сохранённое значение 6 | Одного числа недостаточно для последующих расчётов; повторный импорт таблицы не восстановит зависимости |
| Текстовый идентификатор `00123` | Значение и XML сохраняют строку `00123`; исследовательский PNG показывает `123` | Изображение и данные нужно проверять отдельно; исследовательский рендер не принят как эталон |
| ODS: числовая ячейка с формулой | Спецификация разделяет `table:formula`, `office:value-type` и `office:value` | Наличие значения не подтверждает актуальный пересчёт; язык формул задаётся отдельно |
| Несколько листов и печатное представление | XLSX-пример содержит два листа; выбор листов и страниц не задан единственной таблицей | Пользователь должен явно выбрать область и порядок вывода; настройка печати в Excel/Calc здесь не проверена |

Для XLSX [Microsoft описывает отдельно формулу и кэш последнего вычисления](https://learn.microsoft.com/en-us/office/open-xml/spreadsheet/working-with-formulas). Для ODS исследованы определения ячеек [ODF 1.3, часть 3](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part3-schema.html) и языка формул [часть 4](https://docs.oasis-open.org/office/OpenDocument/v1.3/OpenDocument-v1.3-part4-formula.pdf). ODS-файл в LibreOffice не открывался; внешние связи, диаграммы, макросы, сводные таблицы и печать не принимались. Исследование не подтверждает поддержку полного формата.

## Пользовательский сценарий сейчас

Загрузка `.xlsx`/`.ods` объясняет отсутствие поддержки и предлагает экспортировать нужные листы в PDF в Excel или LibreOffice. PDF переносит представление страниц; формулы и связи остаются в исходной книге. Отказ не создаёт задание конвертации. Проверяются одиночный и пакетный запросы, включая попытку указать другой исходный формат; в браузере проверяются мобильная ширина и смешанный пакет.

## Условия пересмотра

Пересмотр нужен при появлении конкретной пользовательской книги и опубликованного публичного API OpenDoc Formats. Сначала выбирается один результат: статическая проекция выбранных листов или сохранение вычислительного поведения. Для статической проекции необходимо согласовать листы/диапазоны, типы и отображение значений, состояние кэша формул, правила печати и явные диагностики потерь. Для расчётной книги дополнительно нужны контракт зависимостей и реальный пересчёт в целевой программе. Запросы на модель и адаптер создаются в проектах библиотек; приложение отвечает за выбор, предупреждения и приёмку. Отдельного незавершённого TODO о «поддержке Excel вообще» здесь нет.
