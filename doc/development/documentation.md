# Система документации

Редактируемое руководство хранится в `doc/guide/`; API и навигаторы формируются из кода. MkDocs собирает локальный сайт с поиском и темами. Готовый архив `src/textalchemy/web/assets/documentation.zip` входит в пакет и доступен из приложения по `/help/` без MkDocs, checkout и интернета.

## Источники истины

| Источник | Что описывает |
|---|---|
| `doc/guide/` | Доступные действия, ограничения, таблицы возможностей и примеры |
| `doc/guide/verification.md` | Область и даты проверок, смысл метрик |
| `doc/development/roadmap.md` | Только незавершённые задачи приложения по вехам; корневой `TODO.md` ведёт сюда |
| `contracts/libraries.json` | Неизменяемые выпуски и границы потребителя библиотек |
| `contracts/dependencies.json` + `uv.lock` | Проверенные метаданные лицензий и полный состав зависимостей |
| `doc/reference/` | Генерируемые содержание, CLI, операции, код, Web-маршруты, зависимости |
| `doc/development/` | Разработка, релизы, лицензии и интеграция библиотек |
| `doc/examples/` | Данные исполняемых примеров |

Закрытый пункт удаляется из TODO, а возможность описывается в соответствующей главе. Старые планы, карты миграции и журналы реализации не включаются в справку; прежние версии доступны в Git. Библиотечные задачи ведутся в проектах библиотек, приложение хранит ссылки и контракт интеграции.

## Обновление и проверка

```powershell
uv sync --extra docs --extra dev --extra html --extra docx --extra pdf
uv run python -m tools.docs generate
uv run python -m tools.docs check
uv run python -m tools.docs serve
```

Порт самостоятельной справки — [8001](http://127.0.0.1:8001/). Добавляйте `docs` к наборам текущего окружения: `uv sync` удаляет невыбранные extras. Для документированных примеров PDF нужна соответствующая зависимость и её лицензия.

| Команда | Результат |
|---|---|
| `generate` | Перегенерирует справочники, строго собирает сайт и обновляет архив приложения |
| `build` | Проверяет дрейф справочников и совпадение новой сборки с архивом |
| `check` | Дополнительно проверяет структуру документации, активный план, команды и содержимое результатов примеров |
| `serve` | Предпросмотр с обновлением; не переписывает поставляемый архив |

CLI читается из парсера, операции — из реестра и сигнатур, код — из AST, маршруты — из декораторов, содержание — из заголовков глав. Реестр зависимостей перечисляет все версии lockfile и профили использования; обновление lockfile без соответствующих метаданных блокирует сборку. Генерация не обращается к интернету.

Проверки отклоняют забытые страницы/битые ссылки/якоря, устаревшие справочники и архив, старые TODO, закрытые/повторяющиеся задачи, неподдержанные команды и примеры с потерей ожидаемых данных. Примеры проверяют библиографический и текстовый конвейеры, DOCX/HTML/PDF-генерацию из Jinja-шаблона. Внешние ссылки не запрашиваются при сборке.

## Состав сайта

Оформление принадлежит TextAlchemy: [шаблон](../theme/main.html), [CSS](../assets/documentation.css), [JS](../assets/documentation.js). Нет CDN и внешних шрифтов. Локальный поиск использует Lunr и языковые модули; лицензии и уведомления поставляются вместе с архивом. Версия в шапке берётся из `pyproject.toml`.

ZIP имеет фиксированные порядок записей и время, нормализованные окончания строк; сравнение не зависит от сжатия. Только документированные файлы и связанные снимки исходников входят в сайт. Базы, загрузки и результаты пользователя не попадают в архив. Ссылки вне репозитория и отсутствующие локальные файлы отклоняются. Python/JS/HTML/CSS показываются как экранированный текст с номерами строк.

После изменения кода, Web-файлов, импортов тестов, зависимостей, заголовков или темы выполните `generate`, затем `check` и сохраните архив вместе с исходниками. При изменении сборщика перезапустите `serve`. Проверки ссылок и тестовых импортов не доказывают корректность всех функций; заявленные границы требуют содержательного обновления главы и приёмки сценария.

Воспроизводимые кеши удаляет `uv run python -m tools.clean --apply`; старые известные артефакты разработки — тот же инструмент с `--development-artifacts`. Каталог данных целиком не очищается. [Релизные проверки](releases.md).

## Публикация через CI

Все поддерживаемые документы, лицензии и тема находятся в `doc/`; в корне остаются только README и TODO. CI отклоняет дополнительный корневой Markdown и возвращение старых планов. На каждом изменении проверяются ссылки, справочники, архив и исполняемые примеры. После успешных проверок основной ветки сайт автоматически публикуется на [GitHub Pages](https://SergeiLitvinov.github.io/TextAlchemy/). Предварительный выпуск публикует тот же проверенный сайт.

Сайт на Pages и встроенная справка строятся из одинаковых источников. Workflow [CI](../../.github/workflows/ci.yml) сохраняет проверенный сайт; [Pages](../../.github/workflows/pages.yml) публикует только этот артефакт. [Release](../../.github/workflows/release.yml) повторяет проверки перед созданием тега и загрузкой комплекта поставки.
