# Версии и выпуск приложения

Текущая версия — **0.2.0rc1**. Суффикс `rc` означает предварительный выпуск после перехода на независимые библиотеки. Библиотеки сохраняют собственные номера OpenDoc 0.1.0 / OpenDoc Formats 0.3.0. Релиз приложения не пересобирает и не переименовывает их.

## Что входит в 0.2.0rc1

| Область | Доступный результат |
|---|---|
| Независимые библиотеки | Неизменённые официальные wheel; публичные API вместо нативных мостов; контроль хешей и запрет прямых движков |
| Пользовательские сценарии | Конвертация одного файла/пакета, OCR/PDF-подготовка, DOCX-шаблоны, библиография, конвейеры |
| Качество | Прогноз, диагностируемые потери, сравнение и пользовательские бюджеты; неизвестные измерения не считаются успехом |
| Справка | Главы по задачам, таблицы возможностей, локальный поиск, CLI/API и навигатор кода, доступ из программы |
| Лицензии | LICENSE/NOTICE и тексты лицензий встроенного поиска; реестр всех версий зависимостей; явные ограничения optional-профилей |
| Поставка | Wheel приложения и sdist, исходники документации и проверок в sdist, отдельные официальные wheel библиотек, SHA-256 manifest |

Сценарии и их ограничения описаны в [руководстве](../guide/index.md). Кандидат не обещает поддержку всего Office/PDF, полноценный PDF-редактор, XLSX/ODS или точность OCR на любом корпусе. PDF-vector дефекты и расширение адаптеров ведутся владельцем библиотеки, а не исправляются копией обработчика в приложении. Проверка текущих объектов в Office на пользовательских документах остаётся задачей приёмки.

## Правило версионирования

Единственный источник номера — `[project].version` в `pyproject.toml`. CLI, Web, метаданные пакета и шапка справки получают этот номер; версия JSON-схемы документа независима. Формат — `major.minor.patch`, кандидаты `rcN`. До 1.0 несовместимые изменения публичного API поднимают minor, совместимые исправления — patch. Стабильный `0.2.0` выпускается после проверки кандидата; `rc1` не переиспользуется для иной опубликованной сборки.

Тег — `v<version>`. `tools.release --tag` проверяет соответствие, но не создаёт тег и не публикует пакет. Новая версия требует обновления README, этой страницы и встроенной справки. Библиотечный выпуск фиксируется точной версией, wheel SHA-256 и provenance.

## Подготовка и проверки

Используйте lockfile и нужные extras. CI устанавливает среду разработчика с форматами и Chromium. OCR проверяется с подставными движками; реальные модели устанавливаются отдельно для приёмки распознавания. Набор `ocr` имеет [неподтверждённые лицензии](licenses.md). У `docx`, `pptx`, `pdf`, `epub` не подтверждено разрешение на два XSL-ресурса lxml 6.1.1. Комплекты этих зависимостей не одобрены для бинарной поставки; релиз ниже содержит только приложение и две библиотеки, без движков.

```powershell
uv sync --frozen --extra dev --extra docs --extra web --extra pdf --extra docx --extra pptx --extra html --extra epub
uv run ruff check
uv run python -m tools.check_library_contracts
uv run python -m tools.dependencies
uv run pytest tests/ --cov=textalchemy
uv run python -m tools.docs generate
uv run python -m tools.docs check
uv build --out-dir dist
uv run python -m tools.release --dist dist --tag v0.2.0rc1
```

Backend сборки закреплён на `setuptools==81.0.0`. `uv build` строит wheel из sdist; исходная поставка содержит документацию, воспроизводимые тесты, lockfile и vendor-wheel, а кеши и пользовательские данные исключены. Проверка релиза отклоняет неверную версию/тег, неполную документацию, отсутствующие лицензии, изменённые библиотечные wheel, копии библиотек в wheel приложения, пути обхода/дубликаты/ссылки в архивах и следы кешей/баз/старых TODO.

`release-manifest.json` содержит SHA-256 четырёх артефактов. CI сохраняет комплект после lint, интеграционных тестов и сборки. Выбор `--profile ocr`, `docx`, `pptx`, `pdf` или `epub` отклоняется до подтверждения неустановленных разрешений. Базовый профиль релиза не содержит lxml или OCR-компонентов. Эта проверка не заменяет условия распространения известных AGPL/LGPL/NVIDIA-компонентов.

## Автоматический выпуск

Откройте [Actions → Release](https://github.com/SergeiLitvinov/TextAlchemy/actions/workflows/release.yml), выберите `main` и запустите workflow с параметром `version`:

| Значение | Результат |
|---|---|
| `current` | Опубликовать текущий номер, если он ещё не опубликован |
| `patch` / `minor` / `major` | Поднять выбранную часть номера и обнулить следующие |
| Явный номер, например `0.2.0rc2` или `0.2.0` | Следующий кандидат или стабильный выпуск; понижение номера отклоняется |

При выпуске текущего номера workflow ждёт успешный CI на точном commit основной ветки и получает его проверенные архивы и сайт. Повторно сверяет архивы с исходниками, лицензиями, библиотечными хешами и тегом. CI уже выполнил полный набор тестов на Python 3.11–3.13 с покрытием не ниже 80%, включая браузерные сценарии.

При смене номера workflow обновляет версию приложения в pyproject, его записи lockfile, README и этой странице; библиотечные версии сохраняются. Пересобирает справку, выполняет lint, проверку контрактов, зависимостей, руководства и примеров, полный набор тестов на Python 3.13 с Chromium и сборку архивов. Проверенные изменения и тег записываются в Git атомарно; в GitHub Release загружаются четыре архива и manifest. Номер с a, b или rc отмечается как prerelease. Сайт публикуется на Pages из проверенного артефакта.

Запуск по заранее созданному тегу `v<version>` тоже поддерживается, но исходники уже должны содержать его номер. Опубликованные версии и их файлы не заменяются. Неудавшуюся загрузку черновика можно повторить; существующий тег обязан указывать на проверенный commit. Конкурирующее изменение `main` прервёт атомарную запись и требует нового запуска. Пакетный реестр PyPI здесь не используется: [комплекты находятся в GitHub Releases](https://github.com/SergeiLitvinov/TextAlchemy/releases).

## Проверка установки

В чистом окружении установите сначала два vendor-wheel, затем wheel приложения с выбранными extras. Пока библиотеки не опубликованы в пакетном реестре, все три wheel передаются вместе; локальные пути `tool.uv.sources` предназначены для source checkout и не разрешаются автоматически установщиком wheel.

Проверьте `textalchemy --version`, импорт без тяжёлых движков, список операций, TXT-сценарий и `/help/` без исходного checkout/MkDocs. Для Web дополнительно откройте реальную конвертацию и справку. Стабильный выпуск требует этих проверок и принятых ограничений. [Матрица качества](../guide/verification.md), [оставшийся план](roadmap.md).

Перед публикацией сохраните исходники и артефакты, убедитесь, что хеши manifest относятся к публикуемой сборке. После публикации не заменяйте файлы тем же номером; исправление получает новую версию.
