# Форматы и сохранность

TextAlchemy выбирает маршрут и объясняет результат. Чтение, запись, LaTeX и нативная работа с файлами выполняются установленными OpenDoc Formats; структуры и сравнение предоставляет OpenDoc. Эта глава описывает пользовательские возможности, а не второй контракт библиотек. [Границы интеграции](../development/document-library.md).

## Доступность

| Формат / сценарий | Возможности | Что проверить |
|---|---|---|
| TXT | Чтение текста, модель, экспорт UTF-8 | Исходную кодировку и CRLF нельзя считать сохранёнными |
| DOCX | Структура, текст и оформление поддержанных объектов; генерация и правки шаблонов | Сложные Office-объекты, унаследованное оформление, редактирование результата в Word |
| PDF | Текстовый слой; с `pdf` — геометрия, страницы/изображения, специализированный PDF → DOCX; экспорт PDF | Порядок чтения, шрифты, сканы, векторы; PDF-результат не означает редактируемость |
| PPTX | Слайды, поддержанные фигуры/таблицы/диаграммы; нативный экспорт и отдельный HTML-просмотрщик | Тема/master/layout, оформление диаграмм и выбранные объекты в PowerPoint |
| HTML/HTM | Самодостаточный статический HTML, ограниченный CSS, модель и экспорт | Внешние ресурсы и скрипты не загружаются; сложный CSS и paged media не гарантируются |
| EPUB | Текстовая структура и встроенные ресурсы через адаптер | Точные страницы/типографика не гарантируются; в v0.6.0 extra `epub` не требует EbookLib или lxml |
| DjVu | Извлечение доступного текста через внешний компонент | Скан без текста требует OCR; наличие адаптера не означает поддержку всех координат/объектов |
| JSON-модель | Обмен структурой OpenDoc, изменение поддержанных свойств и повторный экспорт | Схема модели не обещает полного покрытия исходного формата |
| LaTeX / библиографические входы | Извлечение и рендеринг через операции/CLI | Проверить доступную команду и внешние программы; не каждый формат участвует в универсальном маршруте |

Каталог `/api/convert/catalog` и экран конвертации показывают достижимые направления и причины недоступности в текущем окружении. В CLI используйте `plan` и `--help`; дополнение устанавливается для соответствующего сценария. [Установка](index.md#установка-и-запуск), [полный реестр зависимостей](../reference/dependencies.md).

## Обмен моделью с OpenDoc

Новые JSON-файлы записываются как `opendoc.document` версии 2 и открываются напрямую OpenDoc. Приложение читает прежний `textalchemy.document` версий 1/2 через слой совместимости. Неизвестные схемы и невалидные ссылки на ресурсы отклоняются; исходник при чтении не переписывается.

Для проверки чтения/записи используйте промежуточную модель:

```powershell
uv run textalchemy convert-file input.docx model.json --json
uv run textalchemy convert-file model.json result.docx --json
uv run textalchemy inspect result.docx --compare input.docx --json
```

Прямое преобразование формата в тот же формат может просто копировать файл. Оно не проверяет импорт/экспорт. [Python API и конвейеры](automation.md), [отчёты и бюджеты](conversion.md#отчёт-и-проверка-качества).

<a id="html"></a>
## HTML

| Возможность | Граница |
|---|---|
| Текст, заголовки, вложенные списки, таблицы | Поддержанное статическое подмножество; нестандартная семантика диагностируется |
| Inline/internal CSS | Ограниченные свойства; не полный движок браузерной вёрстки |
| HTTP-ссылки, якоря/закладки | Проверяйте цель и навигацию после экспорта |
| PNG data URI, SVG, MathML | Поддержанный ресурс/формула сохраняется либо получает явный fallback |
| Внешние изображения, CSS и JS | Обычные CLI/Web не загружают сеть и относительные файлы; Python-адаптер допускает явно ограниченный `resource_root` |
| Предпросмотр и инспектор | Предупреждение связывается с текстовым фрагментом/объектом; это не HTML/CSS-редактор |

При загрузке обычного HTML встройте необходимые ресурсы. Ограничение импорта — 10 МиБ, дополнительно действуют квоты распаковки и загрузки. Отсутствующие ресурсы и CSS-потери видны в отчёте. Строгий бюджет может остановить публикацию.

### Переход от предупреждения к фрагменту

На экране конвертации кнопка возле предупреждения открывает инспектор. Привязанная диагностика выбирает соответствующий фрагмент; общая относится ко всему документу. Связь хранится в JSON и истории задания. [Проверенные HTML-сценарии](verification.md#проверка-в-office).

<a id="txt"></a>
## DjVu

Каталог конвертации предлагает перенос существующего текстового слоя через публичный API OpenDoc Formats, когда `djvutxt` доступен в PATH. Результат по умолчанию — TXT; другие доступные направления показываются по установленным компонентам. Режим «Максимально похожий вид» не предлагается: страницы, координаты, изображения и оформление не восстанавливаются. Скан без текста требует отдельного распознавания; этот маршрут OCR не запускает.

При отсутствии `djvutxt` каталог сообщает причину, а API отклоняет запуск до создания задания. В официальном адаптере 0.15.1 декодирование не зависит от системной локали; Windows cp1251 принят без `PYTHONUTF8=1`. Приложение не подменяет декодирование внутри библиотеки. [Приёмка](verification.md#djvu-0151-в-windows-cp1251).

Если в результате нет значимого текста, конвертация отклоняется: пустой TXT не заменяет прежний результат. При ошибке адаптера прежний файл также сохраняется. Успешный маршрут добавляет предупреждение «Текстовый слой DjVu»; отсутствие сообщений о потерях не подтверждает сохранность исходных страниц. В отчёте область импорта — `text_layer_only`, проверка геометрии остаётся неизвестной, OCR отмечен как невыполнявшийся. Число потерянных графических объектов здесь не измерено. Структурная проверка исходного DjVu на экране не предлагается.

Реальный двухстраничный Unicode-пример проверен DjVuLibre 3.5.29 на Windows в UTF-8 окружении: два запуска через браузер на ширинах 375/1280 px, скачивание UTF-8 TXT, порядок текста, неизменность исходника и видимое предупреждение. Проверен и файл без текстового слоя. Это собственный синтетический корпус; произвольные пользовательские книги, сохранность страниц и OCR не приняты. [Матрица проверок](verification.md#djvu-интеграция-и-область-проверки), [границы форматов](../development/roadmap.md#m5).

## TXT

TXT сохраняет плоский текст, пустые абзацы, пробелы и табуляцию в текстовом маршруте. Экспорт — UTF-8. Входная cp1251 может быть декодирована адаптером, однако сохранение первоначального кодирования и CRLF не обещается. При преобразовании богатого документа оформление, таблицы, картинки и формулы могут быть сведены к тексту с диагностикой; контролируйте фактический результат.

<a id="epub"></a>
## EPUB

Импорт получает доступную структуру книги, текст и встроенные ресурсы. Перенос EPUB в DOCX/PDF не гарантирует прежнюю пагинацию или CSS. Неподдержанные свойства должны быть объяснены диагностикой адаптера. В OpenDoc Formats 0.6.0 используется нативный адаптер; extra `epub` не требует EbookLib или lxml. [Проверенный сценарий](verification.md#epub-без-прежних-backend).

<a id="pptx"></a>
## PPTX

| Поддержанное подмножество | Проверка пользователя |
|---|---|
| Текстовые блоки, положение, размер, поддержанные фигуры | Нет новых рамок/теней, обрезки и неожиданного изменения цвета |
| Таблицы, текст ячеек и поддержанное оформление | Унаследованная тема может быть упрощена; проверьте границы, заливку и шрифт |
| Категориальные/XY/пузырьковые и комбинированные диаграммы адаптера | Согласованы кэш, встроенная книга, оси, порядок рядов и значения |
| Подписи, тренды, погрешности, настройки точек | Нативный PPTX и HTML имеют разное покрытие; сохранённое свойство не означает проверенную визуальную семантику |
| Изображения, ресурсы, заметки | Неподдержанный вектор/объект может получить fallback; проверьте связь и редактируемость |

Изменения модели и экспорт используют публичные API библиотеки. Поля диаграмм, диапазоны параметров, свойства серий/точек и реализация OMML документированы владельцем [OpenDoc Formats](https://SergeiLitvinov.github.io/opendoc-formats/); приложение не поддерживает вторую спецификацию этих полей.

### Граница HTML-предпросмотра и приёмка

Отдельный `pptx2html` создаёт просмотрщик с ресурсами; универсальный модель → HTML имеет другое покрытие. Например, HTML-представление некоторых трендов может быть недоступно даже при нативном сохранении в PPTX. Предпросмотр не заменяет открытия результата в PowerPoint. Ограниченная датированная проверка двух презентаций описана в [матрице](verification.md#проверка-в-office); она не подтверждает все объекты Office.

### Проверка обратного пути

Используйте PPTX → JSON → PPTX, измените нужный объект в модели и проверьте сохранение/правку в целевой программе. Прямой PPTX → PPTX может оказаться тождественным маршрутом. При изменении данных диаграммы проверяйте одновременно кэш и встроенную книгу.

<a id="mathml"></a>
## Формулы MathML

Поддержанная формула может оставаться MathML в HTML либо стать нативной Office-формулой через адаптер. Неподдержанная конструкция может превратиться в текст или изображение с LOSS. Изображение формулы не объявляется редактируемой формулой. Проверьте дроби, индексы, символы и возможность правки именно в целевой программе; наличие `math` в HTML само по себе не доказывает точное отображение.

## PDF и сложные объекты

Скану нужен OCR; текстовый PDF может иметь неверный порядок чтения или геометрию. Подготовка PDF в приложении позволяет выбрать страницы, порядок и классификацию блоков, но не редактирует произвольный PDF как есть. [Распознавание и подготовка](recognition.md).

В адаптере 0.3.0 подтверждён отдельный пробел экспорта PDF с векторными объектами; статус и воспроизводимый пример ведутся в [плане библиотеки](../development/library-requests/opendoc-formats.md). Аннотации, формы, слои, маски, SmartArt/OLE, анимации и сложное наследование оформления не считаются полностью поддержанными по факту наличия маршрута. Проверяйте отчёт, нужные страницы и редактирование; пробел адаптера не обходится новым парсером в приложении.

Библиотека отвечает за сохранение данных формата, приложение — за понятный маршрут, диагностику, пользовательскую политику потерь и атомарную публикацию. [Матрица свидетельств](verification.md), [оставшиеся задачи приложения](../development/roadmap.md).

## Расчётные книги XLSX/ODS

Прямое чтение и экспорт XLSX/ODS пока не поддерживаются. Для переноса страниц экспортируйте нужные листы в PDF из Excel или LibreOffice и загрузите PDF. Формулы, связи между листами и пересчёт останутся в исходной книге. Доступные допуски конвертации PDF не проверяют расчёты книги. Загрузка XLSX/ODS объясняет ограничение до запуска обработки; также проверяется смешанный пакет файлов. [Исследование и принятое решение](../development/spreadsheets.md).
