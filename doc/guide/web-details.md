# Web: контракты API и хранения

Действия пользователя описаны в [руководстве](index.md); здесь собраны технические контракты Web. [Указатель маршрутов и обработчиков](../reference/web-routes.md) формируется из кода. План дальнейшей работы ведётся только в [TODO](../development/roadmap.md).

## Библиография

`GET /api/bibliography` возвращает записи с идентификатором `id`, исходным `index`, массивом авторов и годом в виде строки; неизвестный год — пустая строка. `POST /api/bibliography` добавляет запись, `PUT /api/bibliography/{id}` меняет выбранную, `DELETE /api/bibliography/{id}` удаляет выбранную. Авторы формы разделяются точкой с запятой; пробелы и пустые элементы отбрасываются. Изменение и удаление не пересохраняют остальные записи. При обновлении сохраняются поля выбранной записи, которых нет в форме, например URL и исходный текст.

Неизвестная запись при обновлении возвращает прежний `404` с `detail: "Item not found"`. Повторное удаление уже отсутствующей записи успешно и возвращает `success: true`. Если запись исчезла между чтением и обновлением, она не создаётся заново.

`POST /api/bibliography/import` принимает загруженный файл и использует существующий разбор текстовой библиографии. Разобранные записи добавляются одной транзакцией с идентификаторами базы данных; ошибка сохранения откатывает весь новый набор, прежняя библиотека остаётся целой. Временная загрузка удаляется и при ошибке разбора. Ответ успешного импорта — `success: true, count: N`. Новые форматы импорта этим изменением не добавлены.

`POST /api/bibliography/smart-parse` принимает текст формы и возвращает предварительно разобранные записи (`index`, `authors`, `title`, `year`) без сохранения в библиотеку. `GET /api/operations` получает каталог параметров из отдельного сервиса операций. Подготовка формы, CRUD и импорт делегируются прикладному сервису библиографии; HTTP-слой отвечает за форму, загрузку и перевод ошибки отсутствующей записи.

## Каталог конвертации

Переключатель простого и экспертного режима действует на форму новой конвертации. Режим не сохраняется между открытиями страницы. Простой режим выбирает `balanced`, при отсутствии этого приоритета — первый поддержанный. Возврат к простому очищает допуски и возвращает индивидуальные настройки пакета к общим. Для пакета без общего формата обязательны видимые индивидуальные настройки. Ограничения маршрута и итоговые замечания показываются в обоих режимах; техническое описание маршрута — в экспертном. API и повтор сохранённых задач используют явно заданные параметры независимо от режима формы.

На странице «Преобразовать» карта направлений доступна до загрузки документа.
Она строится по `/api/convert/capabilities` с учётом установленных зависимостей,
показывает форматы назначения и доступные приоритеты для каждого источника.
Для недоступных режимов каталог возвращает `unavailable_modes`: отсутствие
поддержки движком (`unsupported_mode`), недостающие компоненты выбранного
теоретического маршрута (`missing_dependencies` с `requirements`), отсутствие
подключённого обработчика (`backend_unavailable`) или необходимость промежуточных
файлов, не поддержанных веб-слоем (`web_route_unsupported`). Это диагностика
маршрута планировщика, а не минимальный набор установки среди всех альтернатив.
Сначала проверяется доступный маршрут, поэтому рабочий fallback не скрывается.

Недоступные результаты находятся в `unavailable_targets`, полностью недоступные
источники — в `unavailable_sources`. Интерфейс показывает их причины в карте,
но не добавляет их в выбор файлов и результатов. Подсказка приоритета также
показывает причины отключённых режимов, для пакета — по исходным форматам.

Каталог передаёт рекомендуемый формат результата: например, TXT → DOCX,
EPUB → HTML, PPTX → HTML. Интерфейс выбирает его, если направление доступно.
Сохранение в тот же формат не предлагается: такой маршрут тождественный.

При выборе результата показываются пояснения возможностей и ограничений
экспорта PPTX/TXT и импорта EPUB. Для PPTX → модель объяснён обратный путь:
изменённую модель можно загрузить для экспорта в PPTX. Встроенного редактора
текста, таблиц и диаграмм презентации пока нет. Сохранение настроек диаграмм
движком не означает возможности редактировать эти настройки в браузере.

Прогноз перед одиночной конвертацией явно обозначен как оценка маршрута,
а не измерение конкретного результата. Для пакета не показывается прогноз
первого файла как общий: каждый файл получает свой маршрут и итоговый отчёт.
Рекомендации всех исходных форматов объединяются без повторов.

Проверки включают каталог при недоступных зависимостях, рекомендуемые форматы,
реальный браузер, переключение пояснений и пакетный прогноз на мобильной
ширине, клавиатуру и сообщение при ошибке загрузки каталога.

## Предпросмотр и структурная инспекция конвертации

Одиночный запуск `/api/convert` выполняет `ConversionSubmissionService`. Загрузка, определение формата, проверка направления и допусков, сохранение и постановка в очередь вызываются без HTTP. `ConversionSettings` и `check_conversion_route` общие для одиночного и пакетного сценария; `BatchSettings` остаётся совместимым именем тех же настроек. Прежние поля `source_format`, `target_format`, `fmt`, ограничения и успешный ответ с ID/адресами задачи сохраняются.

Частичный отказ нового сохранения удаляет только новую задачу и её исходник; ранее сохранённые результаты остаются целыми. При отказе очереди одиночный API сохраняет прежний 503, но исходник и состояние `queued` остаются для восстановления при запуске приложения. Пояснение ожидания записывается, если хранилище доступно; оно не перезаписывает завершившуюся задачу. Временная загрузка освобождается при успехе и отказах. HTTP-адаптер переводит ошибки настроек в 400, недостаточный прогноз — в 422, сохраняя ошибки ограничения загрузки.

`ConversionPreviewService` предоставляет метаданные, PNG исходника/результата и карту различий без HTTP-клиента. Маршруты `/api/convert/preview/{task_id}/meta`, `/api/convert/preview/{task_id}` и `/diff` являются синхронными адаптерами: FastAPI выполняет рендер в рабочем потоке. Существующие параметры сторон, страниц и DPI сохраняются; DPI ограничен 200. Неизвестная или истёкшая задача даёт 404, незавершённая или изменившаяся задача — 409. Метаданные отдельно описывают недоступную сторону и ошибку её движка.

Кэш страниц относится к снимку сохранённых метаданных, включая срок хранения. Состояние повторно проверяется после обработки: поздний ответ старого результата отклоняется, удаляется только его каталог кэша. Рендер, завершившийся после удаления задачи, не оставляет восстановленный каталог задачи. PNG выдаётся с `Cache-Control: private, no-cache, max-age=0`; повторные запросы используют серверный кэш после проверки состояния. Клиент запрашивает страницы и различия с `cache: no-cache`, чтобы повторно проверить и страницы, сохранённые прежней версией с часовым сроком. Нулевое число страниц после временного отказа LibreOffice не сохраняется в кэше. Его отдельный профиль и временный каталог освобождаются при тайм-ауте. Клиент отбрасывает ответы ранее выбранной задачи и освобождает адреса Blob при смене страницы и сбросе просмотра.

`ConversionInspectionService` принимает поток загрузки, проверяет структуру в рабочем потоке и возвращает прежний `success`/`inspection` с именем файла без локального пути. Общий жизненный цикл загрузки освобождает временный каталог при успехе или отказе. При отмене запроса сервис дожидается завершения чтения работником, затем удаляет исходник. Ошибки HTTP-загрузки сохраняют свои коды; отказ структурной проверки возвращает 400. Эти сценарии не меняют формат конвертированного файла и не заменяют офисную приёмку.

## Архив результатов пакета

После завершения всех заданий пакета готовые результаты можно скачать одним
ZIP из панели прогресса или истории. `GET /api/convert/jobs/{job_id}/archive`
возвращает результаты в отдельных нумерованных папках и `manifest.json`
со статусами всех файлов. Одинаковые имена не перезаписываются. Ошибочные,
прерванные и истёкшие результаты не включаются; готовый результат, чей файл
уже недоступен, отмечается как `unavailable`. HTML-просмотрщик остаётся своим
вложенным ZIP без повторной распаковки.

Пока пакет выполняется или отменяется, выдача возвращает 409. При отсутствии
готовых файлов также возвращается 409, при истечении срока пакета — 404.
Суммарный размер включённых результатов ограничен 512 МБ (превышение — 413).
Архив собирается во временном файле с переносом на диск после 8 МБ и удаляется
после выдачи или ошибки; отдельной долговременной копии ZIP не создаётся.
Если файл исчезает во время сборки, предлагается обновить пакет и повторить
скачивание. Список результатов отражает состояние на момент запроса.

Панель пакета фильтрует файлы по состоянию и имени (без учёта регистра).
«В очереди и в работе» включает отменяющиеся задания; «Требуют внимания» —
ошибки, прерывания, отменённые и истёкшие результаты, а также неизвестные статусы.
Счётчик показывает размер выборки и всего пакета. При обновлении статусов фильтр
сохраняется, при открытии другого пакета сбрасывается. Кнопка «Открыть пакет»
в истории позволяет фильтровать завершённые задания без повторного запуска.
Фильтры меняют только список: ZIP содержит все готовые результаты пакета.
Ответы и таймеры ранее открытого пакета не заменяют текущий список.

## Индивидуальные настройки файлов

`BatchSubmissionService` проверяет настройки и все исходники, сохраняет задачи и описание пакета, затем передаёт задания обработчику. До сохранения описания пакета очередь не вызывается. Отказ загрузки очищает временные файлы; отказ записи нового пакета удаляет его частичные записи, не затрагивая прежнюю историю. Форма сохраняет выбранные файлы и настройки для повторной отправки. Нельзя считать пакет сохранённым до успешного ответа API.

`BatchRetryService` повторяет сохранённые исходники, `BatchHistoryService` формирует публичную историю. Прямые вызовы сервисов проверяются без HTTP-клиента. Отказ очереди оставляет долговременные задания в `queued`; исходники и ограничения сохранены. Пояснение ожидания показывается в списке и истории, если его удалось записать. Восстановление при старте сохраняет прежние ограничения TTL и наличия исходника.

Для каждого файла пакета можно выбрать собственный формат и приоритет в блоке
«Формат и приоритет каждого файла». Общие настройки меняют нетронутые строки;
кнопка применения ко всем сбрасывает индивидуальные правки. При недоступном
общем направлении выбирается доступный вариант строки. Если общего формата
нет совсем, индивидуальные настройки автоматически раскрываются для проверки.
Бюджеты сохранности остаются общими для всех файлов.

API принимает поле формы `file_options`: JSON-массив объектов `target_format`
и `mode` в порядке загрузки файлов. Длина должна совпадать с числом файлов,
неизвестные поля отклоняются. Пропущенные свойства наследуются из общих
настроек; отсутствие массива сохраняет прежний контракт API. Весь пакет
проверяется до постановки в очередь. Имена файлов могут совпадать: соответствие
настроек определяется позицией. Выбранные формат и приоритет сохраняются в
каждой задаче и восстанавливаются при перезапуске, отображаются в деталях истории.

Границы офисной приёмки PPTX описаны в [датированном отчёте](verification.md#проверка-в-office).

## Повтор неудачных файлов

Кнопка «Повторить неудачные» в истории запускает только задания со статусами
`error`, `interrupted`, `cancelled`. API: POST к маршруту перезапуска пакета
с полем формы `failed_only=true`. Готовые и выполняющиеся задания не меняются.
Отсутствующие исходники и недоступные маршруты пропускаются; интерфейс сообщает,
если повторно запустить ничего не удалось. Обычный полный перезапуск сохраняет
прежнее поведение. Оба режима используют индивидуальный приоритет файла;
исправлена его ошибочная замена общим приоритетом при повторном запуске.

Для повтора части неудачных файлов раскройте пакет истории, отметьте файлы и нажмите
«Повторить выбранные (N)». Выбор доступен только для `error`, `interrupted`, `cancelled`;
обновление истории его сбрасывает. API: `POST /api/convert/jobs/{job_id}/rerun`,
поле формы `task_ids` — JSON-массив уникальных идентификаторов этого пакета.
При наличии выбора режим `failed_only` включается независимо от переданного значения.
Пустой список, пустое поле, неверный JSON, повторяющиеся или чужие ID возвращают 400
до изменения задач; отсутствие поля сохраняет прежние режимы полного/неудачного повтора.

Ответ содержит `queued` (поставленные в очередь ID), `launched` (переданные обработчику ID)
и `skipped` (объекты `task_id`, `name`, `reason`). Статусы и наличие исходника проверяются
заново; изменение метаданных до очистки результата приводит к пропуску. Сравнение состояния,
очистка и постановка в очередь выполняются под одной блокировкой хранилища. Невыбранные
файлы не изменяются. При временном отказе очереди задача остаётся `queued`, интерфейс
поясняет ожидание её перезапуска. Индивидуальные формат/приоритет и бюджеты сохраняются.

Новое состояние записывается атомарно до удаления старого результата: отказ записи сохраняет его байты и прежние метаданные. Для пакета такой файл возвращается в `skipped` с причиной; другие допустимые файлы продолжают повтор. Отказ последующей очистки не останавливает уже сохранённый повтор: старый файл перестаёт публиковаться, а замена результата или TTL завершит очистку. Повтор отдельной конвертации использует ту же проверку неизменившегося состояния и обработку отказа очереди.

## Отмена оставшихся файлов

«Отменить оставшиеся файлы» в панели пакета и истории вызывает
`POST /api/convert/jobs/{job_id}/cancel`. Для ожидающих и выполняющихся задач
используется штатная кооперативная отмена; ответ перечисляет `requested`
(идентификатор и новое состояние) и `skipped` (пропущенные идентификаторы).
Готовые, терминальные и уже отменяющиеся задачи пропускаются. Завершение
или исчезновение задания между проверками не прерывает обработку пакета.
Для выполняющегося обработчика запрос отмены не означает немедленную остановку:
панель продолжает опрос до терминального состояния. Готовые результаты можно
скачать отдельно, а ZIP — после завершения остальных задач.
## Импорт HTML

В каталоге доступен HTML/HTM → модель, DOCX и другие достижимые направления. Для самодостаточного HTML сохраняются статический текст, списки, таблицы, встроенные изображения и формулы. Внешние файлы и скрипты не загружаются; потери CSS/ресурсов входят в общий отчёт и бюджет. Кнопка у предупреждения открывает соответствующий фрагмент в инспекторе; общие предупреждения открывают область «Весь документ». Привязки сохраняются в JSON и истории задачи. Инспектор показывает текст и сведения об изображениях; правка и выделение на изображении страницы остаются за пределами первого среза U1. [Границы и приёмка HTML](formats.md#html).

## Исправление распознанного текста

На `/recognize` и `/extract` выбор или перетаскивание файла только сохраняет его в открытой вкладке. Запрос отправляется основной кнопкой после выбора настроек. На время обработки блокируются загрузка, параметры и повторный запуск. При ошибке сохраняются файл, настройки и прежний результат. Новый результат получает имя своего исходника; изменение формы не переименовывает прежний текст. `/extract` проверяет `success` в JSON-ответе и распознаёт JSON-ошибку LaTeX даже при HTTP 200, не показывая её как документ. TXT/TeX скачивается из отображённого снимка, без нового серверного запуска.

Редактор OCR скрыт до получения текста или восстановления сохранённого черновика. Смена выбранного файла не меняет черновик; перед запуском сохраняется прежняя проверка несохранённых правок. Язык доступен в основной форме; рукописный режим/GPU, порядок абзацев и восстановление версии раскрываются отдельно. Изображение отправляется со сценарием `scan`, независимо от ранее выбранного режима PDF. Возможности движков и контракт API не расширены.

Сценарий распознавания выполняет `RecognitionService`: принимает асинхронный поток файла, использует переданный движок и сохраняет черновик в переданном хранилище. `ExtractionService` извлекает текст либо возвращает содержимое LaTeX. Оба сервиса вызываются без HTTP-клиента; временные исходники и частичные результаты удаляются после успеха, ошибки чтения, превышения квоты или отказа обработки/хранения. PDF с текстовым слоем в сценарии `fast` работает без OCR-движка. Неудачное распознавание не создаёт черновика. Перенос сценариев не добавляет поддержку новых OCR-объектов или сохранение геометрии.

При скачивании LaTeX имя файла передаётся в `filename*` с UTF-8: кириллица не вызывает ошибку HTTP-заголовка. Содержимое читается до освобождения временного каталога.

На странице распознавания доступны сохранение правок, загрузка сохранённой версии и экспорт TXT/DOCX/PDF/JSON. Порядок действий и ограничения описаны в [руководстве](recognition.md#распознавание-и-извлечение).

`POST /api/recognize` при успехе возвращает `draft_id`, `revision`, `text` и `model`. `GET /api/recognize/drafts/{draft_id}` восстанавливает снимок; `PUT` по тому же адресу принимает обязательные `text` и `revision`. Пустая строка допустима, пропущенное поле — ошибка. Лимит — 1 000 000 символов, переводы строк нормализуются. Текст хранится в абзацах DocumentModel, без исходной геометрии и изображений.

`GET /api/recognize/drafts/{draft_id}/export?revision=N&format=txt` выдаёт сохранённый снимок; другие форматы — `docx`, `pdf`, `model`. Ответ содержит `X-Document-Revision`. Устаревшая версия при записи или экспорте даёт 409, истёкший/неизвестный документ — 404, недопустимые данные — 422, ошибка хранилища — 503. Интерфейс сохраняет локальный ввод при отказе записи и не запускает скачивание старого текста. Срок хранения наследуется от хранилища задач (по умолчанию 3600 секунд с записи); черновики лежат отдельно от истории конвертаций. Защита конкурентных записей рассчитана на штатный однопроцессный Web-сервер.

## Порядок областей PDF

Экран `/pdf-order` доступен по ссылке из распознавания. Инструкции и границы приёмки — в [руководстве](recognition.md#распознавание-и-извлечение). `POST /api/pdf-order` принимает PDF; `GET /api/pdf-order/{id}` возвращает страницы, подписи, координаты рамок, стабильные ID и `revision`. `PUT` принимает `revision` и `order` — массив массивов ID, по одному на страницу. Нельзя пропустить, повторить блок или перенести его на другую страницу. При сохранении только порядка меняются последовательности исходных словарей блоков; классификация и границы таблиц задаются отдельными полями ниже.

`GET /api/pdf-order/{id}/pages/{page}` возвращает PNG исходной страницы (нумерация с нуля). `GET /api/pdf-order/{id}/export?revision=N&format=model` выдаёт JSON; `format=docx` — DOCX. Старая версия даёт 409, отсутствующий/истёкший черновик — 404, неверная перестановка — 422, ошибка хранилища — 503. Черновики и исходники сохраняются отдельно от задач конвертации; TTL наследуется от хранилища (3600 секунд по умолчанию). Конкурентные записи защищены в штатном однопроцессном Web-сервере. Вёрстка DOCX и сложные объекты зависят от существующего экспортёра; сохранность полного импортированного представления проверяется JSON-моделью.

В том же `PUT /api/pdf-order/{id}` необязательное поле `classifications` передаёт словарь `ID блока → paragraph|heading1|heading2|heading3`. Оно содержит только ручные изменения. Порядок и классификация проверяются и записываются одной ревизией; прежний запрос без этого поля сохраняет типы. В сводке блок имеет `classifiable` и `classification` (`auto` до ручного выбора). Допустим только абзац из текстовых фрагментов: его стиль и признаки заголовка обновляются без пересоздания содержимого, координат и ресурсов. Ошибочный тип/ID отклоняет весь запрос с 422. В DOCX используются Normal и Heading 1–3; прямое оформление фрагментов сохраняется.

Для обрезки таблиц тот же `PUT` принимает `table_ranges`: словарь `ID таблицы → [первая строка, последняя строка, первый столбец, последний столбец]`. Все четыре значения — строгие целые числа, границы включительные, нумерация с 1 по полной исходной таблице. Допустим непустой диапазон прямоугольной сетки с координатами без объединённых ячеек; неверный диапазон/ID/тип даёт 422 без частичной записи других изменений. В сводке `table` содержит размеры, исходные тексты/координаты ячеек и выбранный `range`; для неподдержанного блока это `null`.

Первое изменение сохраняет исходный блок в служебных данных черновика. Последующие диапазоны всегда относятся к нему, а полный диапазон восстанавливает исходный блок целиком. JSON-экспорт включает выбранную таблицу; служебная копия вне модели не экспортируется. Обрезка обновляет строки/ячейки, рамку и PDF-метаданные таблицы, сохраняя остальные данные. Это не повторное распознавание и не изменение самостоятельных векторных линий страницы.

`GET /api/pdf-order/{id}/diagnostics?revision=N` выполняет пробный DOCX-экспорт сохранённого снимка, возвращая `revision`, `success` и `issues`; результат не кешируется браузером. Сохранённый черновик и его TTL не изменяются. Для разрешимого адреса `sections[N].blocks[M]` (включая вложенный путь) сообщение получает `target: {page, block_id, label}`, где `page` начинается с нуля. Адреса ресурсов, колонтитулов, неизвестные индексы и общие сообщения получают `target: null`. Старый номер версии даёт 409. Переход сохраняет `block` в адресе редактора; ID устойчив к перестановкам. Это навигация по исходному PDF, не адрес страницы перевёрстанного DOCX. После загрузки черновика отчёт можно получить заново кнопкой проверки.

## Правка переменной шаблона

`GET /api/generate/templates/{name}/variables` возвращает простые переменные, текстовый контекст и отпечаток DOCX вместе со схемой (`revision`). `POST` на тот же адрес принимает `old`, `new`, `revision` и возвращает имя отдельной копии. Несовпадение отпечатка, занятое/неверное имя и неподдержанные конструкции дают 422; отсутствие шаблона — 404, отказ сохранения — 503. Копия DOCX и `template.schema.json` публикуются вместе переименованием временного каталога внутри `edited-templates` каталога данных Web. Эти копии доступны в списке, схеме, предпросмотре и генерации Web, без срока истечения; встроенный каталог и CLI не изменяются. XML-части без замен переносятся как есть. Простые переменные разбираются в текстовых узлах абзацев; выбранная переменная переносится целиком в первый фрагмент для совместимости с генератором.

## Условный абзац шаблона

`GET /api/generate/templates/{name}/conditions` возвращает абзацы основного текста с адресом `id`, текстом, полем условия `field`, направлением `negate` и общим отпечатком `revision`. `POST` на тот же адрес принимает `block`, `field`, `negate`, `revision` и сохраняет отдельную копию. Отпечаток охватывает DOCX и схему; неверный адрес, устаревший отпечаток, конфликт типа поля и неподдержанная конструкция дают 422. Новое поле получает тип boolean и default false. Условие записывается отдельными абзацами `{% if field %}` / `{% endif %}` либо `{% if not field %}`. Повторная правка заменяет открывающую строку. Целевой абзац и прочие XML-части переносятся без изменения. Хранение и публикация пары DOCX/схема используют тот же механизм, что переименование переменной.

## Цикл одного абзаца шаблона

`GET /api/generate/templates/{name}/loops` возвращает `blocks` (адрес `id`, текст, доступные `variables`, текущий источник `field`) и отпечаток DOCX/схемы `revision`. `POST` принимает `block`, `variable`, `field`, `revision`. Копия содержит отдельные строки `{% for __ta_item in items %}` и `{% endfor %}`; выбранная простая переменная заменяется на `__ta_item` только в выбранном абзаце. Новое поле списка получает тип array и default `[]`. При повторной правке меняется открывающая строка цикла. Занятое служебное имя, несовместимый тип поля, неверный адрес/переменная, устаревший отпечаток и неподдержанные управляющие конструкции дают 422. Формат хранения и публикации пары файлов общий с редакторами переменной и условия. Редактор не обещает поддержку произвольных существующих циклов; принимается только описанная конструкция одного абзаца.

## Цикл строки таблицы шаблона

`GET /api/generate/templates/{name}/table-loops` возвращает доступные строки и `revision`; `POST` принимает `block` в виде `индекс_таблицы:индекс_строки`, `variable`, `field`, `revision`. Ответ содержит имя отдельной DOCX-копии с обновлённой схемой. Поддерживаются прямые таблицы основного текста и строки без объединений, вложенных таблиц и сложных выражений. Независимые условия и циклы абзацев сохраняются. Вложенные конструкции отклоняются. Повторная правка меняет источник списка, не создавая вложенный цикл. Пустой список удаляет выбранную строку; соседние строки сохраняются. Устаревшая ревизия и неподходящие поля возвращают 422 до публикации копии; ошибка хранения — 503. Исходник не изменяется.

## Допуск изменения выделения

`POST /api/convert` и `POST /api/convert/batch` принимают необязательное целое `max_changed_emphasis >= 0`. Метаданные задач и пакетов сохраняют его при перезапуске и повторе. В `report.metrics.emphasis_quality_gate` находятся `verified`, `accepted`, `changed_characters`, `max_changed_emphasis`, `basis` и `reason`. Это число непробельных символов с изменёнными bold/italic в модели, а не число сообщений о потерях или оценка всего оформления. Изменение обоих свойств одного символа считается один раз; добавленное выделение тоже учитывается. Несопоставимый текст или недоступное представление дают `null`, `reason: unavailable` и отказ выдачи. При отказе скачивание возвращает 409; результат не публикуется. [Границы проверки](conversion.md#отчёт-и-проверка-качества).

## Допуск изменения формул

`POST /api/convert` и `/api/convert/batch` принимают необязательный целый неотрицательный `max_changed_formulas`. Отсутствие параметра отключает проверку; `0` требует совпадения всех формул исходника. Лимит хранится в задаче и пакете, восстанавливается при перезапуске и повторе выбранных файлов. При отказе проверки задача получает `error`, готовый артефакт не публикуется, скачивание возвращает 409. В `report.metrics.formula_quality_gate` находятся `basis`, `source_formulas`, `changed_formulas`, `max_changed_formulas`, `verified`, `accepted` и `reason`; недостоверное измерение оставляет `changed_formulas: null`. Контракт измерения описан в [руководстве](conversion.md#отчёт-и-проверка-качества).

## Генерация документов и шаблоны

`POST /api/generate/import` принимает DOCX в `file` и необязательную JSON-схему в `schema`. Обычный образец сохраняется без изменения исходных байтов; готовые переменные обнаруживаются автоматически. `GET /api/generate/templates/{name}/source?query=...` возвращает абзацы, предложения, точные вхождения и отпечаток. `POST` принимает `query`, пользовательский `label`, явный список `selected: [{id,start,end}]` и `expected` отпечаток. Публикуется новая копия с полем и default исходного значения; устаревший выбор отклоняется. Вхождения и техническое имя поля не выбираются по предположениям о ролях людей.

`POST /api/generate/templates/{name}/rich` принимает `block`, `kind` (`image`, `formula`, `bibliography`, `id`, `ref`), `field` и `expected`. Независимые простые конструкции проверяются совместно перед публикацией; вложенность редакторами не создаётся. Формула Web принимает строку LaTeX или MathML с корневым `<math>`; типизированные значения по-прежнему доступны через API.

`POST /api/generate` с `preview=true` возвращает ID созданного снимка, число страниц, `download`, `draft` и список `missing_fields`. Только для предпросмотра незаполненные поля получают видимые подстановки либо пустые коллекции/false. Проверка типов переданных значений сохраняется. При неполных обязательных данных имя файла начинается с «Черновик»; обычная генерация использует исходную схему. `GET /api/generate/results/{id}` выдаёт тот же файл, `/pages/{page}` — PNG страницы с нумерацией от 1. Снимок хранится в TaskStore один час; отсутствие средств рендеринга не удаляет готовый файл. После изменения формы прежняя ссылка скрывается до нового просмотра. Клиент автоматически запускает предпросмотр после 1200 мс без ввода; запросы последовательны, ответы прошлой версии формы отбрасываются. При переключении на исходный шаблон автоматические запросы приостановлены.

`POST /api/pipeline/files` принимает `file`, возвращает имя и непрозрачную ссылку `@upload:ID`. Запуск разрешает её только для живого входа конвейера. Выходные файловые параметры направляются в отдельную рабочую папку; ответ `/api/pipeline/run` дополнен `downloads`. `GET /api/pipeline/results/{id}` выдаёт только сохранённый результат конвейера. Произвольные пути и устаревшие ID через этот маршрут не читаются. Входы и результаты имеют TTL TaskStore, квота рабочей папки — 100 МБ.

Для выбранных файлов `POST /api/convert/jobs/{id}/cancel` принимает необязательный JSON-массив `task_ids` в форме; `GET .../archive` — такой же параметр запроса. Повторы, чужие ID и пустой явный выбор отклоняются до действий. Отмена пропускает уже завершённые файлы, не удаляя их результат при смене состояния. Выборочный ZIP требует готовности всех выбранных файлов, включает только их и manifest; невыбранные активные задачи не блокируют скачивание. Без параметра сохраняется прежнее действие над всем пакетом.

## Хранение наборов данных

Постоянные именованные наборы дополняют временное автосохранение. `GET /api/generate/datasets?template=...` выдаёт список выбранного шаблона, `GET /api/generate/datasets/{id}` — снимок и ревизию; ответы не кешируются. `POST /api/generate/datasets` принимает `template`, `name`, `snapshot`; `PUT /api/generate/datasets/{id}` дополнительно требует `revision`. Снимок использует тот же формат, что временный черновик. Сервер проверяет схему, типы исходных значений, формат вывода и лимит 5 МБ; содержательная проверка данных остаётся перед генерацией.

Наборы хранятся в `generator-datasets.sqlite3` каталога данных Web, отдельно от задач и их TTL. Транзакционное обновление проверяет ревизию; устаревшая запись и повтор имени внутри шаблона (без учёта регистра и крайних пробелов) дают 409. Изменение схемы также даёт 409 без удаления снимка. Неизвестный ID — 404, неверные данные — 422, отказ хранилища — 503. Вкладка сохраняет локальный ввод при конфликте; выбор в списке не разрешает обновление до загрузки. Наборы общие для экземпляра приложения, без срока истечения. Во время загрузки изменение формы отменяет применение полученного снимка.

## Временный черновик генератора

Страница `/generate` сохраняет исходные значения формы в `sessionStorage` по ключу `textalchemy.generator-draft.v1.<template>`. Выбранный шаблон хранится отдельно в `textalchemy.generator-selected.v1`. Запись содержит версию формата, снимок схемы, массив значений, формат и имя файла. Boolean сохраняется как boolean, прочие поля — как строки; JSON не разбирается до штатной валидации формы, изображение хранится как data URI после чтения. Браузер не восстанавливает native file input: данные изображения восстанавливаются отдельно с пояснением.

После загрузки страницы прежний снимок не применяется: форма использует defaults и пустые изображения, восстановление доступно только по кнопке. Внутри одной страницы уже посещённые шаблоны сохраняют текущий ввод. При явной попытке восстановления изменение схемы или повреждённый снимок блокируют применение/перезапись; явное удаление текущего черновика возвращает поля к defaults. При отказе хранилища ввод остаётся на экране, отображается ошибка и предупреждение об уходе с несохранёнными изменениями. Шаблоны и вкладки не перезаписывают черновики друг друга. Это восстановление при перезагрузке той же вкладки, без серверной синхронизации и гарантии хранения после её закрытия. Пользовательский порядок работы описан в [руководстве](templates.md#документы-из-шаблонов).

## Сопоставление файлов

В интерфейсе «Показать предложения» выполняет только анализ. При включённом «Только проверить» второе действие называется «Составить отчёт»; при снятом флажке — «Копировать с новыми именами». Исходные файлы сохраняются. Список документов и настройки папок раскрываются отдельно.

`POST /api/preview/rename` рассчитывает предложения без копирования; `POST /api/match/run` выполняет тот же расчёт и при `dry_run=false` создаёт копии. Оба сценария применяют `manual_matches` из сохранённой конфигурации Web: объект вида `{"имя файла без расширения": 1}`. Значение — позиция записи в текущем списке библиографии, начиная с 1, а не ID базы данных. При выборе `bibliography_file` это позиция в разобранном файле. После изменения порядка источников проверяйте соответствия заново. Настройки можно получить через `GET /api/config` и сохранить через `POST /api/config` (поле формы `cfg` с JSON; сохраняйте остальные настройки).

В отчёте запуска каждая запись `matched` содержит `original`, `planned_name`, `match`, `score`, `copied`, `copied_path`, `new`. `new` — имя фактически созданной копии, `copied_path` — её путь; оба равны `null` при dry-run или ошибке копирования. Планируемое имя сохраняется отдельно. Dry-run помечается `dry_run=true` и не создаёт выходной каталог. Ошибка копирования сохраняет найденное совпадение, добавляет запись `errors` с `code=copy_failed` и возвращает `success=false`; браузер всё равно показывает полный отчёт. Исходный файл сохраняется. `GET /api/match/report` читает сохранённый отчёт, включая ошибки и признак тестового запуска.

Сценарии сопоставления, отчётов и статистики реализованы в сервисе с переданными репозиторием, конфигурацией и путём отчёта. Конвейерный конструктор и шесть форматов экспорта библиографии также вызывают сервисы; маршруты адаптируют формы, ошибки и скачивание. OpenDoc не зависит от этих сценариев.

## Представление генератора и прикладные сервисы

Переключатель «Заполнить документ» / «Изменить шаблон» находится перед рабочей областью. В режиме заполнения сначала идут шаблон и поля документа, затем блок восстановления черновика и сохранённых наборов, после него — имя и формат файла. Обычный текст редактируется пропорциональным шрифтом; JSON и формулы используют моноширинный. Ошибки и автоматический предпросмотр сохраняют прежнее поведение.

Навигация разделяет «Документы», «Библиотеку» и «Инструменты». Общая шкала текста использует основной текст 16 px, элементы управления 15–16 px и пояснения 14 px при стандартном размере шрифта браузера. Шрифты локальные системные; масштаб браузера не блокируется. Поля генератора больше не обёрнуты в дополнительные карточки, настройка шаблона остаётся отдельным режимом.

Каталог и схема выполняются в `GeneratorCatalogService`, генерация — в `GeneratorService`, сохранение и проверка наборов — в `GeneratorDatasetService`. Эти сценарии вызываются без HTTP-клиента и получают подменяемые зависимости. Сервис возвращает файл с функцией освобождения временного каталога: HTTP-адаптер вызывает её после передачи файла. Предпросмотр сначала сохраняет отдельную копию результата, затем освобождает каталог генерации. Ошибка записи пути, экспорта или сохранения предпросмотра также освобождает каталог. Неподходящий JSON-тип параметров возвращает понятную ошибку без создания файлов.
